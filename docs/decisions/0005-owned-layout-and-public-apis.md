# ADR 0005：按稳定职责组织目录和公开面

## 选择

已成立owner整体按engine／features／rulesets／agents／recording／adapters归属，目录不再沿game大层或阶段编号排列。共同夜能力、死亡枪、Catalog有限组合和独立verifier各有实际目录；不通过增加private→ports转发壳声称完整迁移。

## 理由

逐角色核心分支和重复数据会隐去真实写权；把已有owner继续拆小则只增加callee／初始化／异常面。物理移动应保原实际算法与模块图，再根据具体finding处理真正owner边界。

## 后果

单一class／enum／WeakMap／默认实例。兼容key如保留只指唯一physical target；公开出口只保原名和顺序，未知外部deep-import退休不承诺无影响。time-wolf-consort组织名不改变稳定协议ID、规则版本或原fixture origin。

Catalog→observation原late binding仍是实际已知依赖，不能凭新目录宣称消失。checker必须覆盖新目录，不通过分类漏检使gate变绿。

实际目录和公共面见[模块归属](../architecture/module-ownership.md)。
