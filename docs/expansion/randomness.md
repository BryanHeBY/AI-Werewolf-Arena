# 按局随机契约（P2 T01）

## 所有权与版本

每次bootstrap创建一个独立根随机源，或者接收调用方注入的源。游戏配置seed为非空字符串；未指定时以crypto.randomUUID生成实际seed。manifest记录实际seed、算法和分流方式，公开播放器契约暂不增加字段。

算法ID：`mulberry32-fnv1a-utf16-v1`；分流方式：`named-path-v1`。

初始状态是FNV-1a对`JSON.stringify([seed, ...path])`的UTF-16码元逐个散列，32位无符号截断；之后使用Mulberry32，每次返回[0,1)。整数运算、序列化和路径必须保持版本稳定；不兼容修改使用新算法ID并在T04回放时拒绝旧版本或明确转换。

`fork(name)`从根seed与完整路径重建子流，父流消费数量不影响子流。相同路径的新fork重新从该路径起点开始；持续策略必须保留该玩家的stream实例，不能每次决策重新fork。并行对局不修改全局Math.random。

当前路径：

| 使用处 | 路径 |
| --- | --- |
| 发牌 | `deal` |
| 第d夜狼队顺序 | `night` → `day:d:wolf-order` |
| P2模拟决策（后续T03） | 按玩家ID持有独立`players` → `id:<id>`流 |

测试控制器可注入`fixedRoles`，仍必须与板子牌堆的数量/身份多重集完全相同。该字段不开放为未校验CLI规则。

## 验证范围

- 独立参考向量冻结算法；中文seed覆盖UTF-16处理。
- 六人、十二人各25个固定seed，真实引擎流程结束；相同seed及确定性动作在交错游戏中得到一致事件与结果，领域时间戳规范化。
- 此处沿用既有特权baseline作为确定性控制器夹具，仅验证随机隔离；它不是T03受限观察模拟玩家。
- T04将录制实际动作及版本/配置，建立兼容检查和完整离线复现；相同seed不保证相同真实模型文本。
