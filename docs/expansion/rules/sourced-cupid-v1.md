# 丘比特：来源情侣胜利策略

## cupid

来源：[网易官方 2017 圣诞扩展公告](https://langrensha.com/news/official/2017/12/21/26904_730873.html)首夜狼队之前连接两人、丘比特始终跟随情侣胜利、人狼恋第三方、殉情禁技能；[Lui-même 原版规则书](https://cdn.1j1ju.com/medias/af/08/f4-the-werewolves-of-millers-hollow-rulebook.pdf)第6–7、12、18页：首夜连接两人，可包括自己，互认不看底牌，人狼情侣必须消灭所有其他玩家，情侣不能互投。核验日期2026-10-09。出版社文件为规则书镜像，其署名和版本与网易正文独立。

首批采用 `netease_2017_cupid_follows_lovers_v1` 默认。确切来源分歧另设 `lui_meme_lovers_only_v1`：人狼恋时独立丘比特仍随好人，必须被情侣消灭；网易丘比特也随情侣独胜，未被选为情侣时可与情侣同存并获胜。策略标识为AWA来源版本名，不声称官方自身采用该编号。不能拿“原版玩法”将两个胜利目标混为一谈。

## 身份、计数与胜利

- 丘比特原身份为好人神职，最多一名；保留自身真实底牌。首批屠城目标，不开放未核验的屠边或狼到半数。情侣保留原身份、原技能、原阵营查验标签、原生狼队互认/刀权，独立胜利归属另行记录；不靠修改真实阵营来授予或撤销刀权。这是AWA既有身份与胜利归属分离的表达方式，不冒称官方明确了内部计数组件。
- 两人原生阵营相同：情侣与网易丘比特胜利归属为该阵营；Lui-même未被选丘比特继续好人归属。情侣死亡不妨碍同阵营团队终局获胜，沿用已死团队成员获胜的普通定义。
- 人狼恋：情侣胜利归属换为唯一关系组；网易丘比特也加入该关系组，Lui-même只有被选入情侣的丘比特加入。关系获胜要求两个情侣都实际存活、所有不属该关系组的人实际死亡。网易独立丘比特可已死或仍活，均随关系组获胜；Lui-même独立丘比特必须死亡且不获胜。
- 先完成全部死亡链，再检查关系独胜；否则检查普通屠城。狼全灭始终只计真实Wolf身份，不把跟随狼胜的Cupid当作额外狼。好人全灭计真实Good身份，但网易策略下跟随Wolf或第三方的原Cupid不再阻挡狼屠城；Lui-même独立Cupid仍计好人。情侣仍按各自原生阵营计数。这是身份/目标分离所需的工程表示，不声称来源规定了内部算法。双狼情侣与网易独立Cupid三人存活时狼方获胜；全体真狼死亡时独立Cupid不会成为幽灵狼延长游戏。普通阵营获胜者来自各玩家显式胜利归属，人狼情侣及网易第三方丘比特不会被原生阵营误计为获胜成员。
- 首批禁止和咒狐、混血儿等其它独立/跟随目标同板，避免未冻结多目标优先。首批支持Cupid、Wolf、WolfKing、WhiteWolfKing、Seer、Witch、Guard、Hunter、Idiot、Villager、Knight、Dreamer、WolfBeauty；有单角色白名单时双方都须允许。后续逐来源增加组合，不一律全开放。

## 请求、关系与死亡

- 首夜在狼行动前一次必选两名不同实际存活玩家，允许包括自己。至少两名合法活人才能请求；null/重复/死人/非整数/撤权/失败不消费，不允许跳过或后夜补选。角色/自身生命/状态/阶段及双方的生命、Role组件、角色、阵营、privateState、Victory组件与归属内容在请求时绑定并在合法提交前复验；三次请求均无合法结果则显式失败，无伪造回退。提交后拒绝整夜重入，不因更换Cupid状态重复选择。
- 提交后只通知两名情侣彼此玩家ID，不通知底牌、阵营或独立丘比特的ID；丘比特知道自己选择的两人，不知道底牌或最终分组。不会给狼队公开情侣身份；wolf身份继续只提供既有合法狼队信息。当前胜利归属若含秘密阵营/分组，不得直接加入玩家DTO泄露对方身份。
- 网易没有在这两份来源中明确情侣禁互投，首批仅Lui-même策略禁止相互放逐投票；网易保留既有AWA投票许可，不宣称已证实允许情侣互投。这是有限来源版的保留边界，而非新“任意投票”规则开关。
- 关系绑定选定玩家ID和原生命。角色更换不删除已付费关系；实际死亡一次触发另一人的 `lovers` 死因；复活或替换生命不继承旧关系。丘比特死亡、变身或技能库存变化不撤销已提交关系。
- 初始或追加死亡一波中，一名自然死亡立即将另一名纳入同波；根死亡仍按自身死因资格行动，殉情方不得枪/其他死亡能力；守、救、梦不能挡殉情。
- 若两名情侣同一波都有独立致死来源，双方追加lovers抑制死因，均不触发死亡技能。该复合死因口径是抑制优先的工程补全，不冒称官方；只对原始波次种子执行，不能把派生殉情再反向添加到自然根死者导致错误禁枪。
- 殉情抑制WolfBeauty死亡时的魅惑牵连（全部来源策略）。Dreamer已提交的当夜梦关系属于付费效果而非死亡时发动技能：其夜间殉情仍使梦者牵连，日间殉情不使旧梦牵连；此跨角色口径是按梦规则夜死条件作的工程补全。梦与情侣闭包在同波任何枪请求之前完成。
- 所有关系死亡在对应最终判胜点之前完成，使用既有DeathResolution追加波次、生命授权和枪流程；不能提前因末狼/末神标记而封盘。
- 遗言沿用已配置来源策略：AWA默认不给纯殉情遗言；同波保有首夜刀/毒/梦或日间放逐独立来源者按原资格遗言。`netease_2017_day_and_first_night_v1` 按其日间及首夜规则包含殉情。此跨角色遗言兼容边界不冒称丘比特来源专门规定。
- God录制保存选择、来源策略、两者原阵营、显式胜利归属和关系死亡；玩家事件仅白名单私有互认或公开死亡事实，公开事件不额外标注情侣/第三方关系。机器ID、事件与Tape均与显示语言无关。

## 人工判例

| 输入                                    | 预期                                                             |
| --------------------------------------- | ---------------------------------------------------------------- |
| 首夜选择A/A、死人、null或目标新生命     | 不提交、不通知、不消费；严格必选失败行为沿既有阶段规范           |
| 选择自己和好人                          | 普通好人情侣；双方互认玩家ID，不看角色                           |
| 选择两个Wolf，独立Cupid                 | 网易Cupid随Wolf获胜；Lui-mêmeCupid随Good；Cupid原身份/刀权不改变 |
| 选择Good+Wolf，其他角色都死，Cupid仍活  | 网易关系独胜三名成员；Lui-même继续游戏                           |
| Good+Wolf情侣仅二人存活                 | 两策略情侣独胜；网易另计已死Cupid，Lui-même不计独立Cupid         |
| 自选Cupid+Wolf仅二人存活                | 两策略关系独胜两名成员                                           |
| 只有Hunter情侣被普通刀死                | 伴侣殉情禁技能；Hunter根死因可枪；先枪链后判胜                   |
| Hunter被殉情、毒+殉情、刀+殉情          | 无枪请求、无发枪，库存按既有死亡到期；保护不救殉情               |
| 两情侣同波独立被刀/毒死                 | 双方lovers抑制优先，禁死亡技能；标为工程补全                     |
| 关系提交后独立Cupid死亡/换身份          | 关系仍在；不会用新Cupid状态复选/补库存                           |
| 情侣旧生命死而后复活                    | 不继承旧关系牵连或新关系胜利                                     |
| 最后Wolf情侣根死亡引发Good情侣殉情/枪链 | 全部结算后普通屠城，按显式成员确定获胜者                         |
