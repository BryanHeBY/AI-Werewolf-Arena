# 警徽、选民与PK的实施契约

本块在原目录main实施，不改变省略参数的AWA默认。新流程采用有限具名AWA策略；独立站2021规则和2026赛事PK描述只能支持各自明确部分，不能称完整网易preset。

- `sheriff.electionPolicy=awa_final_candidates_v1`默认保留退水后候选人之外的活人投票与已有平票策略。`awa_nomination_offstage_pk_v1`第一轮只有未上警的合格活人投票；唯一候选人直接当选；有正票的最高平票者仅进行一次PK发言与重投，重投选民是PK候选人之外的合格活人，再平票/全弃票不授徽。所有回复在落地前重查候选资格、选民资格与当前流程。
- `sheriff.badgePolicy=awa_next_seat_v1`默认保留顺位交接。`awa_holder_choice_v1`死亡持徽者获一个引擎暂时授权的单动作回合，选择合格存活继任者或null撕徽；无动作/非法动作撕徽。请求构造、await、gateway、提交均检查同一持徽实例/死亡生命版本/日次与阶段/目标生命版本；授权在finally撤销。白痴翻牌失去资格时直接撕徽，不能借死亡授权继续行动。
- `voting.exilePolicy=awa_direct_v1`默认保留现有计票和平票策略。`awa_one_pk_v1`正票最高者平票时仅进行一次PK发言，PK候选人不参与第二轮投票，目标仅能在仍合格PK者中选，投票权重维持；第二次平票/全弃票无人放逐。两轮始终依赖相同日次/阶段，过期不重试或记票。

配置通过公共v2参数和严格内部BoardConfig、双语板子/阶段/目标提示、player观察、SDK/ACP统一preflight、事件/回放、录制/Tape闭环。新事件只描述公开候选/轮次；不披露他人角色或秘密免死。验证需覆盖默认兼容、退水选民、首次/二次平票、弃票、候选/选民死亡或撤权、迟到回复、徽章转让/撕毁/复活、双语、SDK/MCP及严格Tape。
