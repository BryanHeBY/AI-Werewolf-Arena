# P3 中英文本契约

## I01 共用目录

`packages/game-catalog`继续拥有64角色稳定ID、中英名称和实现状态。`packages/game-text`拥有规则/阶段/原因术语、完整句子模板及格式化；两者不依赖后端引擎。后端角色查询和前端角色标签引用同一资料。

- Locale仅`zh-CN`和`en`，缺省中文；每个调用显式传值，不修改全局“当前语言”。
- 中文/英文key集合与占位参数集合必须完全一致；内置缺key、参数缺失/多余/非法值明确失败，不用语言回退掩盖。
- 角色名只从game-catalog查询，不建立另一份七角色或64角色词典。
- 内置技能说明的中英文查询都从共享模板取得。profile的label/skillBrief默认兼容声明也从共享目录生成；构造器显式定制文本视为调用方原文，在两种语言都保留，不借用同ID内置译文替换。
- 未知历史角色/阶段可原样显示稳定ID，主动游戏配置仍严格校验。
- 玩家昵称、人格、发言、遗言、自爆理由和模型原文不翻译；参数按原值嵌入模板。
- 根词典冻结，交错中英文调用不产生共享可变语言状态。

I01先交付目录和契约，英文对局入口仍需I02–I04全部接通、审查和验证后开放。基础七角色的英文技能说明描述当前实现，包括尚待P4修复的末神禁枪；不能在翻译阶段悄悄修改规则。

## 接续实现边界

1. I02逐局locale传递到规则/目标/提示、实际SDK游戏工具及参数、游戏/审计MCP sidecar、拒绝、终端和审计摘要。审计关闭的fallback也得到展示语言；字符串启发式成对覆盖中英文，证据ID不翻译。
2. I03新记录统一phase/stage/原因机器ID，展示消息使用key/params；公开版本/新writer/旧reader/精确转换同时提交。旧中文仅已知别名转换，未知保留，用户原文不改。
3. I04前端与Remotion locale/时区为显式输入，工作台语言不修改replay；同frame同输入输出稳定，中英E2E验证。

T04内部动作录制与公开复盘分别有版本政策：旧动作录制可以按严格engine/hash拒绝；历史公开播放器档必须由显式reader/转换继续读取。不能把二者混为同一个兼容承诺。

## I02：工具协议先行

游戏和审计各有一个`ToolProtocol(locale)`纯构建入口，SDK实际工具、MCP注册输入/参数描述及静态schema查询都从它产生。输入JSON Schema使用draft-7、`io: input`，审计的notes/missing_info仍允许省略并取空数组；不把Zod输出默认值误写成模型必填字段。

World持有只读游戏locale，审计上下文持有任务locale。ACP registry固定当前任务语言；loopback控制面仅将`AWA_TASK_LOCALE`传给对应sidecar，缺省中文，未知值启动失败。工具名、参数key/enum、turn_id、证据序号和业务接受/拒绝code保持稳定；这笔只接工具描述，提示和人类拒绝文案继续由I02后续批完成。runner尚不开放英文整局。

本地隔离ACP需要可读取workspace公共包的真实目录。若`/home`被tmpfs遮蔽，仅挂node_modules的symlink不够：把`packages/game-catalog`、`packages/game-text`和已有replay-contract一起加到`ACP_READONLY_ROOTS`，均只读，不扩大到凭据目录。本地provider只改这些挂载并保存0600备份；验证使用合成认证，不启动真实模型。四条实际bwrap内MCP通路均核对完整schema/查询，并确认公共包不可写、运行配置/记录/另玩家canary/宿主认证不可读。

测试使用安装的真实SDK和本地HTTP响应，以及四个同时运行的中英游戏/审计MCP子进程。逐项比较SDK/MCP完整输入schema、参数说明和静态查询；旧turn和未授权证据仍拒绝，中文玩家原文在英文任务也原样提交。源代码fingerprint纳入game-text，内部动作录制继续遵守严格版本策略。

## I02：共享玩家提示

身份、语言指令、板子规则、角色私有状态、阶段说明、目标提示和行动约束通过同一个PlayerPromptPolicy按World.locale渲染。SDK/ACP只提供各自提交说明；SDK无有效动作的递进重试使用同一语言。角色renderPrompt支持显式locale，默认语言在bootstrap时绑定到该局，查询不改共享目录。

内置StageDirective和用户hint以共享messageKey渲染；显式注入的Profile/阶段字符串仍为调用方原文。显式昵称、人格、结构化事件中的玩家text、JSON字段与可见seq不翻译。新局未提供昵称时按当前游戏locale生成中文“玩家N”或英文“Player N”；历史已保存名字和用户明确填写的“玩家1”均当作原文，不按字符串形状翻译。对照测试覆盖七基础角色、十四阶段和约束/私有信息；并发ACP初始化/行动提示与真实SDK HTTP消息分别验证实际入口。

这一批保持现有规则，包括P4待修的猎人末神禁枪。英文runner仍需完整拒绝、审计、终端、记录/旧档和前端/视频完成后开放；当前API可构建英文工具与玩家提示，不代表P3全链路已交付。

## I02：结构化拒绝反馈

内置规则callback返回`RuleViolation { code: RuleError }`，RuleError是共享目录中冻结的稳定枚举，文案由game-text拥有。规则注册器返回`RuleViolation | null`；现有定制callback仍可返回string，非空string成为`custom_rule_error`并保留原文，即使文字恰为`guard_repeat`也不猜测或翻译。空string保持既有“不拒绝”语义。可显式返回结构化code选择内置解释。

API兼容变化：`ToolValidationResult.error`以前是中文理由，现在是稳定code；新增`message`供显示。`ToolValidationRuleRegistry.validate`以前返回string/null，现在返回RuleViolation/null。使用者应按error/code判断业务，把message视为人类说明。SDK/ACP游戏和审计工具的失败结果新增message，不改变原error、turn_id、证据序号或成功/拒绝条件；SDK过期turn反馈只提示本人的当前turn_id。通用error解释不要求回合上下文，动态turn/tool补充由单独模板渲染；error.*模板均无必需占位。旧ACP bug回调可继续返回error-only，registry为其补当前任务message。SDK与ACP尚未统一全部业务接收逻辑，该职责由P4完成。

内部gateway逻辑记录只保存code作为reason；旧玩家工具轨迹和旧logic理由保持既有原文，不从中文句子或字符串形状猜code。旧私有动作Tape按source/lock指纹严格拒绝跨引擎回放；旧公开复盘读取仍保有独立兼容承诺，格式转换由I03处理。

MCP输入Zod schema的诊断文案在每次builder中设置，禁止修改全局Zod语言。SDK自身的协议包装前缀保留，但参数诊断内容随当前任务语言。真实MCP测试验证schema拒绝后当前turn仍可接受合法调用。Loopback认证、会话及路径检查不变，解析/派发异常只返回固定code和当前任务解释，不把内部异常或输入片段回传给模型。

验证包括十二个gateway拒绝判例分别中英执行、守卫连续目标、私有技能资源/存活/票权不变、同形定制原文、SDK实际HTTP纠正过期turn和不可用解药后提交none、MCP游戏/审计拒绝和控制面认证/坏JSON。未通过翻译修改规则；猎人、药效和ACP业务接受等已登记P4待修项保持该阶段处理。

## I02：审计任务语言与输入边界

SDK和ACP审计共用system/turn提示模板，检查与总结分别按当前任务locale构建。ACP初始化明确没有有效turn_id，不同时指示立即getContext；实际回合才读取授权工具上下文。玩家声称、诈身份和策略分歧不等于引擎故障，原始玩家/模型文本及证据序号保持原样。

BuildDebugSummaryInput显式携带locale和displayLocale；generator/pipeline把locale给检查任务，把displayLocale（缺省跟随locale）给总结任务。并发重试捕获当前检查任务语言，不依赖可变全局环境或audit profile内隐含语言。runner已经传入解析的两语言字段，但英文整局入口仍等待P3所有边界完成。

审计的agent_logic不会接收llm_action_provider原异常、任意input/output。该scope仅投影白名单seq/op/actor/phase/status与稳定失败reason；action_provider_error归为runtime_error，未知诊断明确标transport_diagnostic_omitted。玩家时间线内部fallback原因使用同样白名单。原始记录未被修改，普通领域code/参数和获授权玩家原话继续保留，不靠扫描原话中类似令牌的文字泛删证据。公开发言摘要读取当前playerId及旧actorId，保留作者。

实际验证包含中英检查/总结的SDK HTTP和四条ACP进程→session→注入MCP通路；完整generator→pipeline以两种相反检查/展示语言组合并发运行。检查每个真实任务的sidecar语言、授权payload、过期turn拒绝、原始返回文本和有效Agent/MCP PID已经退出；只使用合成数据，无外部模型或真实认证。

此批仅交付任务提示、语言传播和审计输入边界。Markdown暂沿用已有英文标题协议；确定性renderer、关闭AI时的fallback展示、启发式中英判例与标题/证据parser合流仍待下一批。不能据此宣称整个audit或P3已完成。

## I02：审计摘要与确定性检查

确定性检查返回稳定check code和MessageRef（key/params），观察计数也用同一结构；不在分析时生成语言相关的结论。两个renderer共用标题、metadata和统计格式，在展示阶段按displayLocale渲染。关闭AI、无report及模型摘要被拒绝时，都使用相同展示语言。winner为null显示“无”/None；时间保留精确ISO值，证据序号不翻译。

SDK/ACP总结提示、writer和证据parser共用中英标题。新生成摘要采用窄Markdown协议：可选一个首行一级标题，依序使用“对局/Session”“问题上报统计/Bug Report Stats”“审查事项/Findings”、可选“观察记录/Observations”、“待办/TODO”或“结论/Conclusion”、“审计流程/Debug Pipeline”。标题唯一、顺序固定；不接受未知/混合语言/缩进或闭合井号变体、HTML/comments/CDATA、代码栅栏、缩进代码、Setext标题、引用块或列表内标题。

Findings必须为空标记独占一行，或每项以“- ”开头的一行。每项仅一个evidence=标记，序号为正安全整数，且在当前总结上下文的findings.evidence与全局有效集合交集中。其他段落中的显式引用也遵守该权限。任何未知格式/未授权引用使模型摘要回落为当前语言的确定性摘要，不用跳过段落掩盖。

展示原文时编码换行、HTML和原文中的evidence=，避免昵称、旧phase、message/source等自由字段伪造标题或引用；源对象和录制原文不变。原模型摘要通过验证后原样使用，不对它做自动翻译。旧已保存Markdown仍是原文文件，本批不改写；`validatesMarkdown`用于新生成摘要，默认en对应原API，生产入口明确传任务语言。它的格式门槛变严格，自动checks/observations的message从string改为MessageRef，是本批明确的内部API迁移。

请求元数据仅识别四个机器phase及精确中英历史别名；未知phase即使文字自相等也标异常，不猜测转换。原话词面筛选覆盖成对中英bug/策略/药与角色关键词，不翻译输入后再分析；它是候选线索筛选，可能误报或漏报，不能视为完整自然语言判定。守卫提及和用药声称明确提示可能正常诈身份/玩家声称，需要核查，不能据此认定引擎故障。

本批保持游戏规则、受众和资源不变。实际SDK/ACP/MCP审计检查/总结与完整generator两语言组合均回归；无模型时的双语输出、人工check/evidence oracle及恶意格式反例单独验证。后续仍需终端、I03记录兼容、I04前端/视频和阶段总验收，英文runner尚未开放。

## I02：终端事件说明

ScriptEventRenderRegistry的chat/judge/live查询接收逐调用locale，缺省中文；typed handler得到同一语言，registry不保存“当前语言”。ConsolePresenter及runner的stream/final chat路径显式传displayLocale。阶段、行动、夜聊、遗言、警长、胜负说明引用共用模板与术语；名称查询支持64项目录，但显示名称不等于运行许可。

发言、遗言、wolf_discussion_ended.reason和模型ACP文本均当作原文，不翻译或替换其占位字样。工具/进程日志中的程序状态ID保留。展示切换不改GameEvent对象、输出kind、记录stage映射或玩家投影受众。null winner显示None/无，未知历史ID保原样。旧广播Contributor导出保留兼容，值由共享资料生成；显式注入的定制字符串仍是调用方原文。

本批保持原终端观测策略：终端是运行者观测渠道；原printPrivateEvents只有查验输出显式受控，其他god/夜聊/技能输出按既有规则。没有将该开关重新定义成公开玩家投影，也没有改变AI/前端权限；权限矩阵随P4完善。中文列表标点及缺省空名单显示得到规范化，事实及票权不变。领域公开类型中的空刀目标展示为原有null字面值，不能因翻译格式化抛异常；行动合法性仍由网关拥有。

逐事件/分支对照覆盖空刀/空守、药/查验、发言与结束原因、警长报名/退水/投票/徽章/方向、遗言/枪/白痴/自爆和自然/空胜者终局。原文、输出kind和输入不变验证与后台整局/回放回归同时运行。I03/I04与阶段总验收仍待完成，英文runner尚未开放。
