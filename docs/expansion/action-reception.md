# 共同动作接收（P4 A01）

## 职责与状态

SDK 与 ACP 使用 `ai/agents/player/action_reception.ts` 中同一套 `ActionReception` 和逐回合 `ActionTurn`。传输适配器持有回合；引擎持有动作应用、资源消费、事件与阶段推进。没有统一 Agent 基类或通用生命周期框架。

流程：`开放回合 → 校验提交 → 选择一个动作 → 引擎再次校验 → 结算生效`。

- 错误回合 ID、未允许工具、无效参数、规则拒绝、未满足回合约束均不选择动作，不关闭可重试的当前窗口。
- 成功选择一次后封口；重复、已关闭、已到截止时间或超时后的调用不能再选择动作。关闭后也不能靠传输返回的 `finalAction` 伪造动作。
- SDK 的真实多工具响应把额外提交交给同一回合负责人返回结构化拒绝；不会通过第二次回调覆盖第一次动作。显式 transport `stop` 的通用语义仍保留。
- ACP 的 session 绑定由原有控制面负责；错误 session 得不到当前回合信息。仅属于同一 session 的错误 `turn_id` 可得到当前 ID 和重试说明。
- 同一回合请求目前交付单动作结果；没有把约束中的多个动作扩展为未经实现的累积协议。

## 接受与生效反馈

两条游戏通路成功均返回：

```json
{"ok": true, "accepted": true, "applied": false, "action": "use_potion"}
```

`accepted` 表示动作经过共同预检并成为该回合唯一选择；`applied: false` 明确资源、伤害、投票与公开事件尚未结算。后续是否生效以引擎动作/领域事件为准。最终校验仍检查世界状态的变化，不能把预检当成资源预约或已完成的结算。

拒绝均使用稳定 `error` 与当前对局语言的 `message`；约束失败附 `details`。活跃同会话的错误 ID 附 `expected_turn_id` 和字符串/空值的 `received_turn_id`。不返回其他玩家私有资源或目标身份。

这是现有游戏协议 v1 的补充反馈字段：旧调用者可继续读取 `ok`/`accepted`，精确比较整个成功对象的调用者应更新。ACP 注册表构造现在需要该局 `World`；没有无规则校验的默认构造路径。审计工具的成功反馈协议不变。

## 校验唯一来源

1. 请求的 `allowedTools` 是引擎授权；模型提交的字段不能扩大允许动作。
2. 参数 schema 从现有 `ToolSpec.llm.parameters` 通过当前锁定的 Zod 转换，保留必填项、类型、enum 和 `additionalProperties`，没有第二份手写参数表。
3. 保留十进制数字字符串座位号的有限归一化；必填项不能被修复器默认补齐，字符串布尔值和任意对象不能靠 `Boolean()`/`String()` 转成合法输入。修复后再次检查 schema。
4. 使用原有 `ToolGateway` 清洗及 `ActionValidator` 的角色、存活、目标和资源规则。中英文系统身份前缀均清洗；玩家正文仍保留原文。
5. P4 A01最初从stage/trigger识别死亡请求；现已由[G03窗口](death-action-authority.md)进一步要求World持有的actor/tool/day/phase/generation及生命版本授权，最终消费点再次校验。提交参数不提供授权开关。非弃票的警长票必须有当前请求候选列表，且目标属于列表并仍存活；缺列表直接拒绝。
6. 共同回合约束在选择前检查；选择结果拷贝保存，传输拿到的可变对象不能改写已选择动作。

预检不写 `gateway.validate_tool_call` 领域操作；实际引擎验证照常记录。SDK 的接入拒绝仍记录在 `llm_action_provider` 诊断作用域，与 Tape 的领域操作比较分开，离线重放不制造第二次领域验证。

## 本批边界

A01子批复用当时业务规则，其后女巫刀口/保护、猎人死因/授权、警长零票、狼队历史权限与完整判胜均由G01–G04独立修正验收；混合装配/整回合deadline/关闭资源归属由A02交付。当前完整范围见[P4验收](reviews/p4-activation.md)，A01本身不代替这些专项。

## 验证

- 各动作 schema 的缺参/多参/类型反例；有限数字字符串、bool 严格类型；guard 重复、角色/存活/目标、候选票、药/枪和死后授权。
- 实际 SDK HTTP 与注入的 stdio MCP 在中英文下，按同一人工序列得到完全一致的业务反馈：过期 ID → 错工具 → 参数错误 → 自救 → 无药 → 非法毒目标 → 合法提交 → 重复拒绝。
- 验证拒绝与接受均不消费资源、已选择对象隔离；SDK 忽略伪造 finalAction，完成/超时之后的回调被拒绝。
- 实际双语六人/十二人四个人工完整场景通过 SDK/ACP 运行并严格 Tape 重放，验证无重复领域日志；固定种子观察模拟作为规则回归补充。
