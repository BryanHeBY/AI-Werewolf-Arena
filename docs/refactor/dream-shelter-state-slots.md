# 摄梦人与庇护状态槽

本 C17 切片让摄梦人与明辉庇护的初始化、状态访问、具体写入和政策身份编码归各自状态槽。实际基线为 `e1aec71c528530a5e165c85a1d137ab908e0a3db`，范围 29 个路径：删除旧摄梦状态叶，四个新职责模块及一个新测试。

## 所有权与校验边界

- 摄梦状态槽使用原 JSON 复制函数创建和校验安装数据；读取仍返回同一库存引用。目标、日期、历史按原顺序写入，历史失败保留此前写入。
- 庇护 `prepare` 只做原 JSON 复制；`schema` 是原严格 reader。两者接受范围不同，不能在原生安装时增加严格拒绝。选择和玩家投影返回独立数据。
- 庇护夜间执行仍先提交已付效果、再记使用次数、最后对原状态执行 `Object.assign`。函数查找先于状态读取，字段写入失败保留已提交前缀。
- 共享纯数据辅助函数真实服务庇护和黯月两个 reader。黯月历史、借用、首死、已付效果与关闭规则仍由原 frame 等模块持有，不合并两者的状态和资源政策。
- 通用安装器与 scope 使用相应槽；完整生命、能力来源及租约仍由原所有者核对。政策编码仅保持既有运行身份，不是新归档格式或授权凭据。

文件职责头和关键数据／失败顺序使用中文，明确“准备”与“严格读取”的区别。两个状态槽不反向导入通用安装器，能力数据模块只使用纯庇护状态 reader。
