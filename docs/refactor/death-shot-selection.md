# 死亡枪选择的完整规则组合

本批对应 C24／C28。实际修改前 Git 为 `1428a210d931d4c043fb8d018f21e36c818fd05c`，两个旧源码与八个控制输入均按该提交捕获，开始时工作树全字节一致。源码范围是 DeathResolution、梦魇 ports、新规则模块和新单元测试，共四路径。

## 职责与原顺序

原 `collectDeathShot` 完整 149 行（含原说明和空行）迁到 `rulesets/death-shot-selection.ts`；原四字段 `DeathWaveActions` 同批迁到实际消费者的唯一声明，不保旧类型转发桥。规则组合负责恐惧检查、完整资格捕获、打开原死亡动作窗口、登记同一许可、三次有界请求、等待前后复验、工具校验、候选原生命与魔术师目标映射。日期、阶段、死因、原生／赠枪政策、重试及首错误顺序保持。

DeathResolution 原角色钩子回调直接返回新所有者的唯一 Promise，没有新增 async 转发或微任务等待。回调只创建读取原结算器的五个 getter，未提前取得 World、事件、gateway、状态或规则。原参数仍在原调用位置求值；`this.collectDeathShot` 私有方法退休。

枪的资格与库存仍由既有共同所有者和角色死亡钩子持有。组合返回选择，不支付弹药、不标死或关闭许可。空枪仍只返回原许可编号；实际弃枪消费归后续钩子。DeathResolution 保留原追加死亡回调的 `permits.splice(0)` 关闭及外层 finally 的剩余许可关闭。提供者、校验、映射、钩子或发布抛错仍保留已提交前缀，不补偿库存或死亡。

梦魇 ports 只新增原四参数 `nightmareFearBlocks` 的同函数导出；首次死亡可否保留恐惧仍由调用方明确传入原 `true` 参数。魔术师和猎魔人消费既有公开端口，具体原体、名单和生命权威不迁入规则组合。
