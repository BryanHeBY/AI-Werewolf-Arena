## 实际职责

`roles/abilities.ts` 在原查询、状态判定和数据复制之外，完整拥有原生准备结果的库存提交，以及启停、借用退役、死亡到期、起效日、次数的五个通用命令。原字典、实例和退休 ID 数组保持唯一引用，没有另建库存。

授予和转移的两个实际提交尾也归此处：目标字典安装 → 发表 → 返回，以及原槽删除 → 退休 ID 追加 → 转出发表。`night-ability-grants.ts` 仍完整负责来源、目标、状态政策、复制与 World 复验。蚀日侍女仍先安装自身状态，再在原位置清空能力字典；清空失败保留已安装状态。

`ability_changes.ts` 保留完整的七种原生 payload 准备分派，包括 Pair 原角色限制、各族 reader／复制和原调用顺序。六个 state-slot 的实际原生提交直接调用共同库存。旧 `prepared-native-install.ts` 删除；旧准备叶的五个元数据出口退休。机制根继续提供原有 120 个公开符号，新增的四个内部提交／清空接口不从根出口公开。

共同 `roleOf` 和 `emit` 仍只有 `night-ability-change-runtime.ts` 的原实现。原生资源、生命、原体、租约、借用抑制、已付效果和 Demon 审计不迁移。通用次数写入保留 `lastUsedDay` 后 `uses` 的顺序；Demon 的独立审计写序不改。

## 顺序与失败

- 原生准备先完成复制和政策校验，库存提交先建立原字典，再读取退休 ID 修订编号。来源冲突保旧实例；匹配只替换 state，保留元数据和计数。
- 启停按原 ID 查实例，死亡到期不能重开。值已一致时不发表；先写 disabled，再发表，发表失败不回滚。
- 授予在发表失败时保留目标实例。转移只在目标安装和发表成功后删除来源，随后逐项退休、发表；不新增事务退款。
- Eclipse 原槽安装、字典清空、借用和付款之间没有新增生命周期调用或补偿。

这次代码移动新增局部调用帧、模块依赖和真实内部 API，并改变声明物理路径；不声称任意 CommonJS 重绑定、私有反射或整个初始化环境等价。原 readonly 视图、宽 live cast 和 JSON 复制接受集合保持，没有补全各族 schema、失效或归档 codec。
