# 按职责命名的机制公开端口

本批扩展C04的公开端口约定，支持机制根的 `setup-ports.ts`、`ability-ports.ts` 等具名端口。开局窗口和普通能力查询若都从单一 `ports.ts` 加载，已有工厂／hook装配可能形成循环；独立端口可以保持公开消费边界，同时分别加载真实所有者。

这是明确的公开文件命名约定。除原 `index`、`contracts`、`ports` 外，机制根、kebab-case前缀且以 `-ports` 结尾的 `.ts`／`.mts`／`.cts` 文件可作为公开端口。嵌套目录、下划线、近似命名和任意内部实现继续拒绝；应用／引擎／预检仍不能深导状态或控制器。领域和浏览器依赖限制不因名称改变而放宽，没有机制特例或债务豁免。

公开端口应声明消费方、真实输入输出、状态写权和失败语义；具名导出所属实现，不新增注册、服务或生命周期层。使用方仍必须独立核对真实API与依赖图，文件名不能证明权限安全或消除循环。

本批只改一个门禁判断及新增独立合成依赖图单元，不改游戏规则、历史债务或私有配置。

验证采用三个新增case：公开消费、五类伪公共路径、领域／浏览器限制；首两个预期写错诊断顺序／已有错误名称，保留首失败，只修新预期并运行失败两项。最终新增三不同case共8断言，原三项私有／公开／嵌套边界精准case一次4断言。两根有限tooling类型一次退出0。没有重复全量门禁、对局或模型。
