# 对局周期持有夜间生命周期接收方

`night-lifecycle-plan.ts` 拥有夜间实际装配、开夜和关闭顺序。pipeline 的十二个具体 Unit 保留原状态和资源职责；三个交换机制仍共享魔术师的原交接标志。入口前的孤独少女、野孩子和初始身份 opening 保持原 pre-try 位置。

每个 PhaseManager 周期创建一个接收方，pipeline 在原晚交接点将实际 Unit 逐项交给该周期。成功移交的对象与原 cleanup 所有者相同；移交后发生结果 getter 异常，也不会丢失已交接引用。交接选项通过 thunk 在交接时才读取，绑定不提前读取 World 或配置。

八个 Unit 以原终结函数引用作为接收方法；贵族继续使用原非枚举结果接收边界。未交接时的 native terminal 保留原早期失败行为。manager 按原位置读取当前 World／日期和配置；六个正常终结分别检查 currentness，原内层、外层和重复 abort 保持，外层不新增捣蛋鬼清理。

本批不引入通用清理框架、全局 receiver 存储、资源退款、关闭去重或新 acquired guard。伤害、阶段推进、随机流、必需记录和结果字段仍走原路径。新增三个机制 public entry 只导出实际 readiness／opening 绑定，动物死亡入口也使用原函数。

本批范围为 16 路径。两个引擎完整文件按精确登记片段核对；构造顺序、helper 原操作、同实例与函数身份由两个独立方向检查。四项局部测试验证实际接收方、World 读取、失败前缀、逐项 currentness 和重复清理，结果 4 通过、0 失败、22 项断言。当前多批源码／测试类型检查实际退出 0；局部门禁文件头和新增依赖失败为零，43 条历史债务继续登记。见[证据](generated/cycle-night-lifecycle-evidence.json)。

原测试字面板子缺少必须字段及 hooks 形状的诊断保留，修正仅针对新增测试。原导入减少造成的四条新依赖身份及三个 public entry 的职责头诊断也保留；通过真实 public 函数绑定和准确时序说明修正，没有更新债务豁免。

完整 RulePlan、其余业务扩展与最后同输入全量验收继续执行。本批没有改归档版本或把运行接收对象写入记录。
