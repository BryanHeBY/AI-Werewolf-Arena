## 顺序与失败

同步顺序仍为：可读性 → 故障及必需记录 → 原来源封存 → 基础来源 → 猎魔保护 → 夜之贵族夜仆到期／关闭 → 原生命与当前来源筛选 → 贵族／猎魔事实 → 链前活人快照。领取、付款、封存和当前性仍由各机制检查，真实标死与追加死亡仍由经理的死亡结算器执行。

运行视图 getter 只捕获经理，不提前读取 World、配置、事件或故障计划；回调在原表达式时才查询原经理方法并保 receiver。空来源保持 `originalLives === undefined`；非空来源仍逐目标读取 `night.deathLives` 并返回最后一次原表。故障可以先换生命再写必需记录，后者失败不退款或继续封存；随后来源、事实与快照失败也不回滚已发生前缀。

新 API 是同步具名函数及其运行视图／结果。新增查询对象、结果对象和函数调用栈是实际布局变化；接口只读不是运行权限屏障，返回值不是 JSON DTO。未承诺任意私有方法反射、模块初始化顺序或外部猴子补丁环境完全等价。Engine 结果和生命类型只有 type 依赖，没有规则组对经理的运行导入。
