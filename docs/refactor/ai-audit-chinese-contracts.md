## 补充的真实边界

- 审计诊断不授予游戏行动权，不直接写角色库存、胜负或录制。外层审计编排拥有重试、失败任务名单及结果汇总。
- ACP 每任务登记独立 registry、等待控制器与会话。默认工厂另建进程和工作目录；路径与提示本身不构成文件权限隔离，自定义工厂的隔离由提供方负责。初始化提示只改变提示内容，正式 turn 仍在初始化兑现并复核取消后开放。
- 取消辅助函数结束等待，迟到创建仍可能兑现并由原回调尝试退役。同一会话引用只登记一次退役任务，关闭 helper 原有普通失败后的强制尝试仍保留。主错误、关闭错误和执行器清理账本持有各原错误；有界 close 不承诺底层创建全部终止。
- SDK 传递原 AbortSignal、六步上限和工具回包；协议确认提交后才停循环。原 close 无操作，不代表正在运行的 turn 或底层请求池已回收。
- registry 按原 session／turn／模式校验。原任务 context 同引用保存；查询包装新建，payload 同引用返回，不深复制、冻结或隔离 getter。证据序号范围不等于事实验真；source 由任务上下文赋值。提交先清 pending，再读取字段、构造结果并 resolve；后续失败不恢复已清前缀，也不保证该 Promise 完成。
- MCP sidecar 原启动地址／token 被捕获，四工具只查询协议与当前任务、提交审计诊断。它不自行增加期限、HTTP 状态拒绝或文件接口；启动与回收归实际 ACP 所有者。此处不限制外部 agent 的其它能力。
