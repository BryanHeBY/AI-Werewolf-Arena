# F01：生产回退的玩家观察策略

本政策对应 C33a，单独改变旧回退决策；不属于旧新完全等价的机械迁移。实施前冻结以下输入、选择和预期，保留 P0 真实阵营反例及旧轨迹，不修改旧 seed、golden 或规则合法性。

## 决策边界

默认 SDK、默认 ACP 及运行装配的生产 fallback 只把共同 `PlayerObservation` 交给策略。投影适配器可以持有 World，策略不能获得 World、原 RoleComponent、隐藏阵营或未告知历史。自定义生产策略也通过 `decide(observation)` 接入。

原 ActionProvider 回退注入迁为明确的特权测试接口，保留其原请求身份、取消与期限测试用途；真实生产配置和装配不注入该接口。旧 Baseline/profile callback 仅作为明确的 mock、smoke 和特权规则测试驱动，不进入默认生产决策。

## 固定选择政策

复用既有 ObservedBot 的具体工具 handler 和竞争型风格，选择列表中第一个可见候选，使用固定 `next() = 0`，不读取或推进游戏 RNG。这不是新的全局随机流。候选、已知存活、队友、己方能力与历史仅来自本次观察；仅凭真实阵营的变化不得改变选择。

65 个公开工具名中，既有观察 handler 覆盖 64 个；诊断工具 `report_bug` 不由回退伪造，单独请求时返回 null。

发言和狼聊保留对应原两语 fallback 模板与狼聊 end_chat=false；警长方向仍按原席位奇偶选择。其他工具保留既有观察策略的具体行动形式；没有适合的观察行动时返回 null，不根据真实 World 合成目标。引擎继续重检目标、资格、库存、许可与付款。

严格回合仍先执行 `allowsActionFallback()`：禁止回退时不调用策略、不投影、不生成必选动作。取消、最早 deadline 和 provider 关闭继续由原传输编排负责，策略不延长预算。

## 独立预期

- P0 六席反例：1 狼、2 隐狼、3／4 村民、5 预言家、6 守卫，N1 无可见事件。2 号隐藏真实 camp 的改变保持 observation 相等；新狼刀两次均选择 2 号，旧 Baseline 原来分别选 3／2 号。新旧差异明确记录。
- SDK 和 ACP 默认路径必须使用相同观察边界；运行器不再注入旧 Baseline。
- 观察中明确提供的候选、已知队友、查验知识和本人资源可以改变选择；未知隐藏阵营、真实未公开死亡、其他角色私有库存不能改变相同 DTO 的选择。
- 女巫首夜无可用救人信息时保留 use_potion none，目标为本人。没有候选的枪／票保留原工具允许的 pass，不伪造目标。
- 自定义观察策略收到脱离且冻结的 DTO；显式测试 provider 仍收到原请求。
- 禁回退、已撤销／取消以及超时的门禁仍由既有 owner 证明，不能把策略返回当作领域提交。

## 交付与审查

实现需要一起迁移默认 SDK、ACP、运行装配、可注入生产策略及旧注入测试消费者。独立审查核对全部生产入口、输入权限、具体工具覆盖、两语和付费失败前缀；使用有限真实默认传输假客户端及 DTO 反例，不调用计费模型或重跑全量游戏。

C33／C34 的完整观察与事件投影、C36 的角色贡献拆分以及 C44 的其他旧出口另行收敛；本政策不能替代它们的验收。
