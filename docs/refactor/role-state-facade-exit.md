# 角色状态门面退出

本批删除 `roles/private_state.ts`，将 100 个真实消费者的 175 个名字直接接到原来的 15 个状态 owner。

同机制内部读取使用原 `state.ts`；跨机制、AI 和运行器使用该机制实际的 `ports.ts`。九个新端口只导出已被消费的本机制函数，不创建包装调用、第二状态仓库或跨角色出口。Seer／Witch 现有端口补齐实际初始化命令，RoleInspection 职责头删除失效门面描述。

完整范围为 113 个路径：100 个消费者、九个新端口、三个既有端口修改和一个旧门面删除。原回调、输入、常量、数组、预期和类型适配保持。门面下的 102 个静态导入和五个动态解构全部迁移，没有命名空间或反射消费者。

## 动态导入边界

四处单机制动态导入只更换原 owner 路径。一处测试同时读取 Seer 与 Witch 的 setter，改为一次 `await Promise.all()`。其内部 Promise 调度与旧导入不同，不能声称微任务顺序完全一致。

实际静态值导入链 `bootstrap → default_specs → catalog → Seer／Witch profile → state` 确认这两个模块在测试回调之前已加载。迁移不增加它们的首次初始化；其后的回调程序与原文相同。

## 验证与审查

- 100 个非导入类型程序保持；175 个命名入口都终止于原函数声明。
- 删除之前，在新进程仅加载原 bootstrap 入口并读取函数身份，175 项均相同；没有调用 bootstrapGame、World、模型、网络或对局。
- 后端源码、测试与脚本类型检查实际进程 2781 退出 0；随后仅补中文职责注释；13 个头部的非注释后缀逐字保持、职责头检查无问题。
- Root 阅读实际门面与消费者，独立子代理核对终态摘要、完整调用退出及动态例外。详见[有限证据](generated/role-state-facade-exit-evidence.json)。

两次迁移工具的匹配错误被完整程序检查发现，原红结果与来源保留；修正匹配器和相应消费者后收口。没有重跑整局或全量发现。完整 schema／checkpoint、能力与观察迁移、其余旧入口和最终固定输入门禁继续执行。
