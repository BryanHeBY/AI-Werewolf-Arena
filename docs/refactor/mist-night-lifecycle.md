# 迷雾 / 渡鸦夜间生命周期

## 真实所有权

`MistNightUnit` 唯一持有原 pipeline 的 cleanup-transfer 状态，通过原位置的配置判断和移交决定是否调用失败清理。构造只保存延迟读取接口，不提前读取 World、阶段、事件、时钟或 RNG。

开夜与可选解封公告迁入具体 unit；业务伤害捕获仍位于原较早位置，只有原较晚位置才移交失败清理责任。开夜部分写入或公告发布失败仍执行原配置条件下的清理。

PhaseManager 通过机制的公开 ports 调用原终结函数，仍在每个原位置传入当时的 World/day。正常关闭后的内部与外部 abort 都保留，不以新的 acquired/closed 标记跳过参数读取。manager 继续拥有阶段推进、死亡处理及判胜；frame 继续拥有规则状态与已付资源。

## 保持的边界

- 配置 truthy 与 `!== undefined` 原条件分别保持，不统一解释。
- 原 World、day、目标参数读取顺序与原异常传播保持。
- 原 frame、stage、state、库存和事实算法未更改；不新增第二个 frame store、结果字段或通用清理框架。
- 同一函数经公开 ports 以原 binding 导出，查询没有新包装或副本。
- request、checkpoint、Tape 和 MCP 中不加入运行对象或新的 revision。
