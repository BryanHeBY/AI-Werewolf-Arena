# 原生命死亡提交所有权

本批迁移死亡结算的实际写入职责，是 C27 的一部分。`DeathCommitter` 持有唯一的 `settledLives` 账本，负责原 `isSettledLife()` 查询与完整 `markPlayersDead()` 提交。`DeathResolution` 的三个查询、两个提交直接消费这个 owner，不保留第二份账本。

所有者在原账本字段初始化位置创建。World、事件数组与运行状态通过结算器的三个延迟 getter 读取，创建时不读取它们。原查询的一次 World 读取，以及提交的 15 次 World、10 次事件与 11 次状态读取，均保留原表达式位置和 receiver。默认参数和调用实参不变。

原顺序仍是首次生命判断、Wild Child 记账、Alive 修改、动物／贵族事实及必须记录、角色揭示、枪列表追加、能力过期、生命账本更新，再刷新四种继承。枪列表追加或必须记录失败时，已死亡的生命及已发布事实不回滚，账本不伪造完成；继承失败时此前账本已经提交。

关系闭包、遗言、警徽、角色死亡钩子和最终枪过期仍由结算器按原顺序推进。本批没有新增 TypedWave、提交回执或泛型死亡框架。

七个具体机制端口只公开被实际消费的原函数引用。新 owner 不直接导入机制内部；结算器四项继承也改经相同端口。原结算器仍有十四项内部依赖，继续在后续机制迁移中处理。
