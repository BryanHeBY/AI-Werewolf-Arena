# 角色私有状态容器的读取边界

## 实际职责

`RoleComponent.privateState` 的普通读取类型是 `Readonly<Record<string, unknown>>`，属性本身也只读。普通消费者不能替换容器、添加任意键或删除键。运行时仍是原来的普通对象；没有冻结、复制、解析或增加另一份存储。角色与阵营字段、提示渲染的行为保持。

`RoleProfile.init` 接收具名的 `RoleInitializationComponent` 写契约。注入的自定义 profile 继续支持任意扩展键以及容器替换，catalog 仍将原角色、原 context 和原 profile receiver 交给回调。该契约只表达初始化的已有写权，不是新的运行时授权机制。

实际机制 owner 只在原写表达式恢复自己具体槽位的类型。能力与枪的安装、退休及转移仍由原 owner 执行；没有通用可写角色接口或任意键 setter。Fragrant pair 的左值容器读取仍先于能力安装，嵌套 `??=`、删除、退休及事件顺序保持。Order Prince 与封印 Demon 的替换仍在原身份、描述符、JSON、生命与当前性检查之后。

## 保持的记录边界

checkpoint 的特殊贡献优先级与普通 `structuredClone(role.privateState)` 保持。schema 2 的独立记录 DTO、扩展键、可选字段省略、严格 source/lock/RNG 身份及六个独立 verifier 均未改变。归档推导账本继续可写，未被替换为生产状态或命令。运行 AST 等价不表示新源码可以接受旧 sourceHash。

## 本批证据

本批实际范围为 23 个生产文件、63 个既有测试／支持文件及 1 个新单元测试。作者与独立审查分别从实际 Git 输入核对生产运行程序；独立方向另核对 37 个控制文件的原始字节。

既有测试／支持文件只添加 133 处类型断言：93 处原槽位写入、38 处原容器替换、1 处 Guard seed 以及 1 处 Seer 已安装副本的历史变更探针。去掉这些明确断言后，完整原类型 AST、运行程序、输入、动作及断言保持。650 个注册语法节点保持；它们不被声称为重新发现的展开 case IDs。

三个新单元用例检查原对象形状／描述符／引用、自定义初始化的原参数及 receiver／读取顺序、Hunter 原左值读取和返回引用，共 22 次断言。编译负例检查普通读者不能替换、写入或删除私有容器。完整 backend 源码／测试类型项目实际退出 0；87 个有限职责头检查通过，没有新增依赖失败，3 条历史债务保留。[本批证据摘要](generated/role-private-container-evidence.json) 保留输入摘要与最终进程结果；未重复运行完整对局、测试发现或全量门禁。

## 后续边界

这完成普通容器的静态读取边界。通用能力查询的可写句柄、其他 payload 读取、全部角色 schema／编码、自定义 profile 完整编码贡献、阵营身份以及核心提示渲染依赖仍需迁移。内建裸槽访问全部归 owner 后，核心容器应退出可搜索 Record 表面。此批不将整个 P3 或机制矩阵标为完成。
