## 四个真实窗口

- Initial：保 prepare／scope 安装及原 new 点；await 两侧、gateway 后、最后付款前保原 predicate 先行再核租约。原交换／Role→Camp→Victory 或 retained 全部写、status complete、原 close 和 scopes.delete 都成功后，才 complete true，且先于 data／选择事实。
- Wild：原选择窗口／factory／await／gateway／commit 顺序保；state commit→setup complete→windows.delete 全返回成功才 true，随后原事实。
- Lonely：保库存与选择→Victory→choice／membership／status／isCurrent 全部付款顺序；返回 camp 后 true，再发表原事实。不得用已被付款改变的 pending predicate 重新判成功。
- Wall：保两次 provider 前 sameAuthor、allSettled 首 rejection、逐作者读／gateway／两库存写、过滤／排序／RNG／发布顺序。两写都成功才该作者 true；第二写失败保第一写。已付效果发布不读取已经 closed 的 request current。最后逐个关闭所有未付款 turn，一人的通知抛错不能留下其它作者许可。

共同许可关闭和结算状态分开。查询只关许可；真实窗口才 complete／close。先写 settled／closed 再通知，事实或 true 通知晚抛仍已 true，finally 不二结算。Provider 返回不自行付款；Trace 在正常返回与领域提交之间保持 pending。未付款／取消／墙未接受纸条最终 false close。原 body 与原 cleanup 同时抛时仍保旧 JS cleanup 优先；新增 false 通知错不覆盖该已在传播的错误，无旧错则正常传播新通知错。只用各窗口局部 finally，没有通用清理框架或回滚新增规则。
