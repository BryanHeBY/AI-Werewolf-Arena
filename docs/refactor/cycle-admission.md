# 周期与阶段跳转的同步重入准入

## 范围与归属

本批对应 C22–24，基线为真实提交 `c41940ed1ef0401a6ad366b839252f20540f9b0a`。只迁移有限、同步的机制组合，不扩展玩法。

| 所有者 | 本批职责 |
| --- | --- |
| `rulesets/cycle-admission.ts` | 周期的 8 个原判断及婚约局部读取；跳转的 3 个原判断，保留首错误与原短路 |
| 同一 `RulePlan` | 两个 readonly 原政策函数绑定，实际供经理调用 |
| `PhaseManager` | 周期登记、Mist 跳转前置检查、终局快照、最大日数、阶段时钟、行动装配、死亡／判胜和原清理 |
| 各机制 | 原活跃窗口、准备状态和夜间提交证据；端口只直接导出同一函数 |

源码范围为 9 个路径：经理、计划、新政策、新单元测试，以及明辉蚀影、孤独少女、野孩子、盗贼／千面人、墙上留言的 5 个端口。端口新增 6 个原查询绑定，没有包装查询算法。

## 原时点与失败政策

周期在原 `runSingleCycleInternal` 开头调用同一计划的 `cycleAdmission`。经理传入 getter，每次 `runtime.world` 或 `runtime.state` 才读取经理对应字段；不预先收集日期、终态或窗口快照。

原顺序为明辉夜、猎魔人、婚约、孤独少女、野孩子、初始身份设置／夜窗、初始身份已提交、留言窗。婚约对象只在原局部声明处读取；其 `status`、准备检查及提交检查保留原短路。两种初始身份错误仍在命中后查询 `initialIdentityKind`，再使用原模板和 `thief` 默认值。

跳转在原 Mist 周期检查之后，依次执行猎魔人、婚约、孤独少女准入；通过后才执行原 `phaseRevision.advance()` 和 `setPhase()`。原 Mist 的 `pureWhiteStartedDays` 判断及外层周期登记、`try/catch/finally` 未迁移。

终局保留各原 `gameOver` 短路，无条件的活跃窗口检查仍执行。政策同步抛出首个原错误；具体 owner 已付效果、提交标记和设置状态不因准入拒绝撤销。终局返回、清理和最终判胜仍由经理拥有。

`CycleAdmissionRuntime` 的 `readonly world` 与 `Readonly<Pick<RuntimeSnapshot, "day" | "gameOver">>` 是运行查询类型，不是快照、序列化对象、租约或运行时权限屏障。

## 明确变化与后续限制

- 新公开政策／运行类型、端口导出与 RulePlan 两个自有字段改变 API 形状；同一计划仍沿原构造冻结。
- 新模块加载路径、额外 getter 端口对象、函数接线和错误调用栈有意变化，不承诺任意模块 monkey patch 或整构建二进制相同。
- 源路径、注释和模块接线进入新执行来源指纹；历史旧指纹保持，不提供跨构建复现豁免。
- 本批不声称 C22–24 全部余债清零。后续规则组合、其他生命周期、架构门禁仍由对应阶段验收。
