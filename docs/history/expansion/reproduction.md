# P2 T04 动作录制与离线复现

## 记录的内容与边界

游戏runner和受限观察模拟在记录作用域中生成内部`reproduction.json`，manifest给出该文件路径。公开`replay.json`保持原播放器格式，不带这份内部录制。

P2最初录制为v1；P4 G04起当前录制`schemaVersion: 2`，包括：

- 引擎源码SHA-256、根`bun.lock`SHA-256及可获得的Git commit。源码范围是core/game/app、共享game-catalog/game-text以及实际执行的replay-contract；commit用于来源追踪，源码/lock用于兼容判定。
- RNG实际seed、算法/版本、完整命名路径与分流版本；配置格式对应的归一化领域BoardConfig、规则集/规则版本、locale和天数上限。
- 随机/固定发牌模式、初始角色/阵营/昵称与脱敏的Agent绑定（仅kind/name/model）。固定发牌仍需满足板子多重集。
- 按玩家/日/阶段/个人回合序号录制实际请求和决定；另存开始时已完成的决定数及实际结束顺序，以恢复并发中的首个失败及关闭取消顺序。请求去除不可复现的墙钟deadline，实际响应/不行动仍保留。
- 初始及每轮的阶段、结果（outcome/decidedAt）、显式victory归属、存活、身份/资源/票权/警徽/印记；中途失败记录未完成的轮次及安全错误类型。
- 原始领域事件和引擎操作，保留接受/拒绝及实际效果证据；原始事件不从前端数据格式反向推导。

没有provider对象、API key、URL、env、认证文件、进程参数或原始传输异常消息。失败只保留安全错误类型/代码；原错误仍由runner抛给调用方，不能为录制替换掉运行错误。玩家原始文本仍按事实记录。

## 资源与严格落盘

SessionRecordManager拥有录制作用域和文件写入，Trace仅维护动作/检查点。先停止后台任务、关闭Agent，再完成最终保存。manifest、公开复盘、内部动作录制均为严格写入：所有必要写入都等待结束，失败统一保留，录制失效不能冒充成功。

处理中可写`finalized: false`的前缀记录；其严格写入失败也保留到最终异常汇总，即使后续完整发布成功，也不把该次保存报告为无错误。有未结束决定或检查点失效时拒绝生成最终录制。即使内部录制失败，仍尝试保存公开部分复盘，保留其他保存错误。封口在首个await前进入closing，禁止新后台调度并排空已有写入；完成后不能再被前缀覆盖。角色视图与审计辅助文件保持既有尽力写入策略；完整离线复现的事实在必要录制中独立保存。

## 可用回放命令

从项目根目录：

```bash
bun run --cwd backend replay:actions --record ../record/<session>/reproduction.json
```

可选`--record-root`指定重放输出根目录，相对路径按CLI当前cwd解析；默认新建项目根record下的唯一复现目录，不覆盖原对局。

回放读取内部录制、核对版本和配置，按照已记录的动作及响应结束顺序推进真实bootstrap/阶段管理器/网关/技能/结算/投影/记录。每个请求的本人观察、每轮状态、规范化领域事件及领域操作全部核对；时间戳规范化，校验操作数量/内容必须一致。无法继续的因果序列明确拒绝，不能永久等待下一项不存在的动作。

随机发牌从记录的seed/path重建并验证初始牌面；明确的固定夹具按原固定模式重建。失败对局重放到对应异常和部分状态。终止原因和gameOver/result关联：失败轮次只能是有cycle错误证据的runtime_error；非终局只接受有错误来源的runtime_error或完整边界停止的runtime_timeout；自然终局应匹配引擎胜负原因。初始化、清理、记录、控制器的外部错误以安全来源/类型保存，只核对其来源数据及引擎状态，不宣称离线重新启动了那些外部操作。实际API/ACP会话不由离线动作回放启动；传输测试仍在T5/P4覆盖。

## 兼容政策

- 不支持的录制schema、引擎/lock、RNG、规则版本明确拒绝。未封口、动作未消费、观察/事件/资源状态不一致也明确拒绝。
- 当前采用严格源码与lock一致性；源码hash包含文本变更，不将不同引擎自动判断为兼容。Git commit不同但源码/lock一致可以复现。
- 本批没有提供跨引擎的自动转换；需要旧引擎时使用记录对应的隔离checkout及依赖，不覆盖当前源码或用户凭据。历史公开播放器档案继续读取，不等同于具有可复现动作的录制。
- P3完成后支持zh-CN/en执行与复现；metadata.locale显式绑定到World，不改译原始名字/动作文本。兼容性仍严格检查source/lock/RNG/规则集，未放宽旧Tape政策。

## 验证

- 六人/十二人各25固定seed录制并逐局离线动作回放，观察/检查点/事件/操作完全核对。
- 独立篡改schema/源码/lock/RNG/规则版本、seed、决定、观察、状态、操作及获胜摘要时拒绝。
- runner传输抛错和畸形动作导致的部分对局可复现；认证及原始错误片段不在内部录制中。
- 多个必要文件同时失败全部保留；未完成决定不能生成成功录制，公开部分档仍保存；旧运行异常与收尾错误回归仍成立。

角色规则的人工oracle仍由T02负责；本模块核验实际对局的可复现性，不能以“复现了旧行为”代替规则正确性审查。
