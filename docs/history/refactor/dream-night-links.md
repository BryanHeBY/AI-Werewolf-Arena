## 唯一数据所有者

`dreamer/night-links.ts` 用一份 `WeakMap<object, DreamNightLink[]>` 持有同一夜状态的原数组。`object` 只是原运行对象身份，既不是 JSON，也不是权限品牌。第一次追加或读取时建立数组；随后只读查询、可写追加及 Frame 都取得同一数组，不克隆、冻结、重抓原角色或产生通用字段镜像。

通用 `NightStageState` 不再依赖私有 `DreamNightLink`，也不携带 `dreamLinks` 必填数组。Pipeline 仅移除原空字段；没有增加开夜调用、生命周期清理、当前性检查或退款。**空数组的分配／登记从原流水线状态构造点推迟到第一次本族使用**，是明确的存储 API 差异，不宣称所有外部反射行为等价。

本族私有可写入口仍在原 `push` callee 点读取状态／数组。历史、次数、开夜提交及 `applied` 已先落下，随后才构造原 link。原 `captureRadiantPaidEffect`、政策读取、生命／版本、来源和事件字段顺序不改。数组／条目构造失败不撤销已付前缀，不发布尚未构造成功的 `dream_applied`。

`readDreamNightLinks` 经 `night-ports.ts` 给真实规则组合调用；公开端口只导出读取，不导出追加或替换登记。普通 state-slot／abilities 聚合没有因这次新增公开路径被反向加载。首次读取也会登记空数组，所谓只读是数组的类型视图，**不是无副作用或不可变性的运行保证**。

`installDreamNightLinks` 仅用于真实非空关系 fixture 接入原数组；不增加来源、付款或有效性验证，不能因为登记了数据就把它当行动许可。两个故障用例直接取得本族已拥有的数组，不安装虚构许可。
