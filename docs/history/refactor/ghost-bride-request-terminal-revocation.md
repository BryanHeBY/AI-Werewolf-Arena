## 新读取与错误渠道

setup 保留原构造器、创建请求及 provider receiver。新增 provider 前守卫在实际 getter/callee 准备之后执行，防已失效 turn 继续调用 provider。局部 `Reflect.apply.bind(Reflect)` 的查找、绑定分配和参数 tuple 在末守卫前求值；guard 后只调用已捕获 invoker，provider 返回后的原 guard、校验、付款、事实与 finally 保持。这增加明确的 current/domain/clock 观察和 Reflect／bind／调用栈／错误渠道，实际 JavaScript 有意改变，不能称机械等价或对任意全局反射改装完全透明。普通 descriptor／JSON 的宽度不新增 schema 或深冻结。

查询捕获错误先记录适用终态，再抛同一个 Error。原领域付款与原 finally 继续决定真实异常优先级；已 true 的通知、已写 pair／票／Victory 或已发表事实不会因为晚异常被反结算。
