本批修复 [d94b482c 架构检查点](architecture-checkpoint-d94b482c.md) 的三个引擎新增依赖问题。最终八路径与完整程序证明见 [证据](generated/death-feature-contributions-evidence.json)。

## 实际归属

动物梦境的既有 `AnimalDeathWavePreparation` 收走真实运行回调装配，以及初始河豚揭示／整波事实、追加目标事实的完整程序。引擎保留实际标死与原调用位置；准备过滤、白猫到期、原因修正和事实权限继续由原机制拥有。

实际生产装配使用 `fromRuntime`，World 和事件通过原位读取端口传入，不提前缓存生命或权威。没有新增状态、另一死亡账本或通用清理框架。工厂没有命名为 `bind`，因此保留构造器原有的 `Function.bind` 使用方式。

野孩子的原完整处理函数作为必需的已提交整波贡献，在 EventRegistry 的实际装配中登记。原顺序为整波 Alive 提交 → 野孩子榜样转换 → 梦境记录 → 遗言 → 后续死亡动作钩子。旧注入的 HookRegistry 仍只有原两个构造参数和原方法，无需新增方法，也不能替换或跳过这一原本必需的动作。

Noble 的 `isNobleBodyBoard` 是 resolver 的未使用导入，直接删除。Noble 原权威仍由 DeathCommitter 的真实端口消费，没有改动其算法或加载目的。

## 数据与失败说明

初波保留逐目标原角色／死因判断、河豚事实先于整波事实的顺序。追加目标仍在标死后立即公布原来源集合，再进入原枪事实、关系通知和继承流程。晚读取失败保留此前已发表事件及已经提交的死亡，不回滚。

贡献发布函数不自行标死或授予死亡权限；调用方仍负责在原已提交时点调用。新具名方法和贡献列表是明确 API 增加，不宣称 EventRegistry 或 Animal 实例的任意反射／键枚举与旧对象相同。

职责头、运行端口、必需与可替换钩子的区别、初波／追加事实及失败顺序使用中文注释。
