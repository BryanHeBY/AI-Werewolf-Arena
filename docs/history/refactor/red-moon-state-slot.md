# 赤月使徒数据槽职责

本批迁移原赤月使徒的初态、属性描述符校验、同引用读取和玩家字段投影。内部审计中的 JSON 解析、候选浅副本、完整容器编码以及三项有序写入也由同一状态所有者提供，实际初始化和恶魔猎手转换均使用这些实现。

## 保持的契约

- 原五字段校验保留非枚举、只读数据属性的接受范围，代理对象和访问器仍被拒绝。原角色和阵营检查先执行，成功后返回原状态引用。
- 初始化先读取左值 `privateState`，再查找原初态函数并读取配置政策。政策供给回调保留原配置读取位置，不提前缓存。
- `JSON.parse` 查找先于审计字符串读取；`JSON.stringify` 查找先于完整容器展开。候选仍是原浅副本，完整容器的其他字段保留。
- 三项写入按 `blastDay → exileDay → expirySettled` 执行，每项候选字段读取紧邻写入。后项失败保留先前写入，不回滚或重新读取角色槽。

原生命、末狼判断、夜窗口、请求租约、完整私有容器失效、可写预检和最终审计更新仍由恶魔猎手权威负责。状态槽的失效读取沿用原状态校验，不是完整租约。内部审计编码不等于严格档案读器或跨构建复现验收；独立归档审计算法保持原职责。
