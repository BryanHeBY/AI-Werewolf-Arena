## 原生角色展示

全部 55 个内建角色的完整展示读取离开 47 个 profile 的运行装配，归入游戏侧捕获模块。捕获按原点读取字段，立即提交具体纯数据片段给 `game-presentation`，再继续下一次读取；纯格式化不接收 World、角色、写句柄或回调。部分参数包含前一片段产生的本地化子文本，因此准确称为纯数据展示片段，不声称整个参数包都语言中立。

原生能力与当前请求的 `ability_id` 绑定能力保持不同选择，特别是女巫、守卫、查验和镜女；不能用行动观察的 `ownState` 替换角色私有文案。原 JSON.stringify(undefined) 的错误路径也保留。

领域 RoleComponent 仅保留 role、camp 与不透明 privateState 数据。游戏侧创建函数及唯一展示绑定负责默认语言；尚未初始化的角色只显示原 component.role 标签。Catalog 初始化后才消费原生／自定义贡献，保留当前 role 晚查询、自定义方法两次读取、原 receiver 和晚 World 参数求值。

内建 profile 的 `renderPrompt` 调用入口作为明确兼容项继续存在，真正调用完整捕获及纯格式化。它保留普通浅拷贝、原型继承与 Proxy 包装；不能通过读取新 descriptor 字段使原自定义通用回退执行额外 getter。这一入口及其提前加载捕获模块的依赖仍属于 C36／C44 后续工作，不声称三个贡献已经独立装配。

## 领域展示属性退出的明确 API 差异

Role 对象不再有领域 `renderPrompt` 属性。旧 init 把角色冻结后，原 Catalog 会在 init → locale 后因赋值失败；旧 init 为该属性安装拒绝 setter 时，会在 init → locale → setter 后抛出原错误。新展示绑定不写这一退休属性，两种绑定均成功。

旧 Git 完整方法与新路径的字面轨迹分别保存并测试；这属于已授权领域展示 API 退出，不冒称所有自定义初始化失败前缀机械相同，也没有新增玩法、回滚或重试政策。一个原组件键集合断言明确迁移；其余字面规则输入、结果与断言按完整程序核对保留。

## 完整行动预检

游戏 Gateway 拥有 ActionReception 的全部允许工具、第一次使用 schema 缓存、参数修复、机制请求作用域、领域校验和回合约束。所有原特殊分支及读取顺序保留，不增加第二次 Tape validation，不消耗库存或处理领域完成。

ActionTurn 继续拥有选择、截止、拒绝计数和 `applied:false`；其窄接口只声明 locale 与 validate。运行对象仍是原接收器和 World，类型接口不是新进程隔离或运行权限屏障。

约束的数据与判断归游戏侧，AI 保留两项文案渲染。两个实际装配者、三个额外约束消费者、39 个原测试与动态导入全部接到实际 canonical owner；旧 action_reception 叶删除，不建立游戏到 AI 的反向导出。21 个公开机制绑定到达同一原函数，网关公开边界规则也检查类型查询。
