# 身份查验状态槽与实际安装写入

身份查验族的原生状态访问、创建／政策校验、两条历史写入、运行政策身份字节和局部 payload 失效检查，实际归 `role_inspection/state-slot.ts`。原内部 state 叶删除，原 policy 实现和 abilities 重导出退出，九个生产与两个测试导入直接接同族所有者或公开 ports。AI 使用公开端口，原文、规则、工具名及字段不变。

实际原生角色为石像鬼、通灵师、镜女、纯白之女、狼巫，以及觉醒隐狼晚学习，共六角色／五政策；受赠、复制、转移仍复用原实例库存，不增加支持角色或规则。

## 唯一写权与顺序

状态槽保留原 JSON 复制 → policy 校验；两条 append 分别保持捕获状态与三次 ability.state 读取。政策身份保持 JSON.stringify 函数查找先于两个状态字段读取。生命、id、来源、激活、阶段及完整租约当前性仍在原夜间 owner，局部 payload 相等不重新授权。

Root 审查发现首候选依赖环及 ports 的库存写权说明不准确，首候选未提交。完整原生安装的 35 行实际存储、退休 ID 修订、冲突检查、state／source／metadata 写入与返回迁到独立 prepared-native-install 所有者；普通安装器和查验状态槽两个真实调用方消费它。复制与校验仍先于实际库存读取，source.role 保留原晚读取，同一实例仍只换 state。

Slot 不反向调用普通安装器，abilities 不重导出 policy；实际 21 个相对运行模块图确认两个指定反向路径不存在，prepared 所有者没有运行导入。它实际拥有完整写入，不是转发壳或第二库存。ports 明确安装 setter 会写原生库存，普通查询和展示不会授予请求。
