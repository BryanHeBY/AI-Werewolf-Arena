# 警长请求构造的显式装配边界

## 真实职责与接口变化

基于实际 Git `c3dc932647f67499b430253f5c77d2fb9cb363f1`，本批九源：领域动作契约、警长选举／方向／警徽选择、DayPipeline、DeathResolution、两个原单元测试及一个新风险单元。不存在 `sheriff_mechanism.ts`，没有新增运行包装、全局默认或框架。

领域新增纯类型 `ActionRequestFactoryConstructorPort`，承诺原 `new(world, readonly events, day)` 参数并仅返回既有 `create` 端口。选举和方向输入、警徽选择末参数明确要求构造依赖；实际 Day 两处、死亡结算一处及原测试八处使用 getter 返回真实 `GameActionRequestFactory`。三个警长模块退出对 engine 工厂的值导入。依赖是装配接口，既不序列化也不授予资源、行动租约或死亡写权；readonly 事件参数不复制、冻结或收窄原工厂接受面。

这是一项显式 API 迁移：旧外部调用缺少必填依赖不再满足类型契约；有效构造路径无 fallback。新增依赖 getter、对象分配和类签名是真实接口／布局变化，不主张任意旧入口、私有反射或外部猴补环境全部等价。警徽调用点新增依赖对象只捕获 getter，不提前读取构造器。

## 原构造点与生命周期

选举仍在原活人收集后构造一次，同实例贯穿上警、竞选、退水、投票和 PK。上警先创建全部请求才并发调用；竞选按座位串行，其余原收集和生命复验顺序未改。方向在原 disabled／无警长返回之后独立构造，未共享 Day 自身工厂或选举实例。

警徽选择在原持有人和候选检查、开放死亡行动许可之后，且进入原 try／finally 才读取构造依赖并 new。构造器抛错仍经原 finally 关闭该 permit，不执行 Provider、不提交警徽或退还已发布前缀。原 request／context／World／events 引用、期限、Gateway、await 后原体复验及最终写入保持既有所有者与顺序。
