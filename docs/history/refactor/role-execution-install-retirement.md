# 身份安装失败后的共同执行退休

此批是 F05a 的独立失败政策，基于实际 Git `bd2e04894509f7777d2909632f768a3329e3b57a`。本提交范围是初始身份安装 writer、新的领域执行退休集合，以及四个新增风险用例；联合批次分别接入野孩子转换、夜能力与赠枪资源、狼队执行和自爆窗口。不删除 `RoleComponent.camp`，不调整构造器或扩大角色组合支持。

## 唯一职责与失败范围

`role-execution-authority.ts` 用私有 `WeakSet<RoleComponent>` 记录实际角色对象的永久执行终态。它没有阵营、World、库存或公开 DTO 镜像，没有恢复接口。重复退休幂等，冻结角色也无需写属性；同一对象被恢复字段或放进另一个 World，仍保留此终态。未退休只表示没有触发此失败政策，执行还须经过原生命、来源、库存、阶段和许可检查。

初始身份在原准备、完整 scope／delivery 复验、能力消费及物理换牌之后，开始安装新 Role。仅围住原 Role→Camp→Victory 三项安装：任何一步抛错，永久退休已准备的候选对象，重新抛出同一 Error。catch 使用原局部引用，不重新查询 World，不退休旧角色，也不回滚牌、组件、库存或选择前缀。Role 安装回调在落组件之前抛错时，候选同样退休；已经尝试的失败对象不能稍后绕过原安装结果重新执行。

早期构造／自定义初始化／准备错误不属于此核心段；全部安装、关闭及 delivery.complete 成功后的事实错误也不触发退休。原外层异常、finally 清理、关闭错误优先级和通知决定完整保留。

## 执行、数据与已付效果

资格查询单独读取退休标记。World 原组件查询、名单、目标、历史身份知识、记录和库存数据不隐藏失败对象。夜能力 `isOwnerCurrent`、赠枪 `isCurrent` 和已消费原生枪延期提案仍分别持有原体／来源／生命约束，不能把新行动拒绝扩大成已付效果取消或死亡清理跳过。

死亡请求的 `permissionCurrent` 保原正文及原执行资格依赖；赠枪分支本来使用 `captureDeathGun.isEligible`，会经新的 active 查询拒绝退休对象。真正已付提案使用的纯当前性与请求执行资格分别审查，不能仅凭函数名声称所有传递依赖不变。

赠予夜能力的库存提交新增必填、已在原读取点捕获的 `sourceRole` 内部参数，用于目标容器 getter 后重检双端退休；不是 JSON 许可或新 World 换体政策。各资源模块仍拥有付款与写入顺序，迟到的拒绝保留已写前缀。
