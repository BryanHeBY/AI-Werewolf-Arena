# 历史复盘 reader 的中文维护说明

在白天流程和角色状态迁移并行推进时，本批只补充四个已有复盘契约文件的中文注释：历史标签兼容表、角色别名快照、错误诊断与数据描述符检查。

职责头和关键逻辑说明明确：

- 兼容标签只按精确名称匹配，未知字符串保持原文，玩家／模型正文不被扫描；`Object.hasOwn` 排除原型属性。
- 中英文角色旧名称属于历史输入，已有别名不能被翻译或替换；别名表不声明当前角色支持范围。
- 诊断只归档白名单字段和重试建议。直接断言与先复制描述符的 reader 是不同入口，记录建议不等于执行重试。
- `isRecord` 是浅层检查；递归描述符检查单独拥有原型和字段限制。`seen` 避免循环遍历，不证明输入可被 JSON 编码；反射仍可能触发 Proxy trap。

[程序保持证据](generated/replay-reader-chinese-comments-evidence.json) 使用真实 `ace6eb6b` Git 原文，四个完整类型程序与八份 ESNext／CommonJS 输出一致；实际职责头和中文检测均无诊断。[独立审查](generated/replay-reader-chinese-comments-review.json) 复核了真实正文、原文和说明边界。

历史标签、机器码、字段、范围与失败顺序均保持。仅注释变更不重复类型、行为或全量检查；运行源码注释会改变新的来源指纹，历史档案原指纹不回写。本批不表示全仓中文注释已完成。
