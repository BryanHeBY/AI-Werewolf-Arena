## 注释说明的实际约束

- 旧层级扫描只检查字面模块名；不会执行表达式猜路径，路径通过也不代表角色和包边界全部合法。i18n 扫描不检查注释，例外按完整文本及精确次数约束。
- 窗口文件只导出标识，不自行授予权限或执行中断。时点、启用、提交和失败处理留在实际阶段流程；纠正旧警长窗口说明的误导时序。
- 故障计划只消费显式离线输入；生命替换与计划消费先于同步记录器。记录失败保留已写前缀，任一应用失败永久终止该计划，不能恢复原字段后重试。
- 终端 ACP 缓冲按玩家、文本类别及 messageId 合并；工具更新只以显示状态去重。此状态不属于行动准入或领域提交。
- 双构建快照分别拥有 workspace 与复制依赖，摘要核验不是文件系统写保护。历史预言家探针仍复用当前外部依赖，不能冒充同样的完整冻结工具。
- 差分仅移除已声明的构建身份及产物地址；未知字段、库存、知识与因果边界仍比较。它证明机械等价，规则正确性另由独立预期验收。
- fixture 来源路径与当前位置分开，observed 带字面证据、unknown 保留原因。关联歧义不任选候选，字节保持不授予验收；纯关联函数不核实际文件摘要，生成器另核固定 Git 和当前输入。
- 测试声明、参数化表达式与执行日志分开；同名执行项保留 occurrence，汇总重复不加案例。退出成功还须核输入完整性、标题发现与汇总。

这些说明覆盖数据、顺序与失败边界，不给直白赋值逐行加重复注释。机器协议、错误、测试标题、样本字符串、标识符、JSDoc 类型／tag 与工具指令保持原文。测试中的“源码头注释”字符串仍是被冻结的样本数据，不当维护注释翻译。
