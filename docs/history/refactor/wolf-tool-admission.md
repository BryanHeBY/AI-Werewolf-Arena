# 普通狼工具准入组合

## 职责与范围

以真实 Git `f524203283956d8c59eb40bb673f071a6b1ec104` 为基线，共七个源码路径：删除普通狼私有 `validation_rules.ts`，新增 `rulesets/wolf-tool-admission.ts` 与一个定向单元测试，调整普通狼装配、共享能力端口、鬼魂新娘公开端口及狼刀查询说明。五份既有源码在保存 before 时均与该 Git 完整字节相同。

规则集现在拥有狼聊、狼刀、自爆三工具的完整可写校验表。普通狼装配与 `wolf/ability-ports` 直接引用同一表；鬼魂新娘端口只追加 `weddingMember`、`canSubmitWeddingTool` 两个已有权威函数的具名出口。原生命、婚礼回合、狼队政策、实际刀权与提交仍归原所有者，不增加角色／来源门槛、库存写入、快照、随机数或租约。

## 保持的读取与首失败顺序

- 狼聊先查询当前狼队权限，再检查夜间阶段。
- 狼刀先走婚礼权威，缺省日次仍为 `0`；否则先狼队刀权、阶段、工具名、pass，再查询目标。普通非 pass 且首个目标非 null 分支保留三次 `args`、两次 `target_id` 读取，目标访问器错误仍在原前缀处上抛。
- 自爆先排除原婚礼限制，再读角色自爆政策，依次检查阶段、窗口成员、阶段与窗口关系、已取出的 `allowSelfDestruct`，最后工具名及 confirm。参数解构仍先取全部原公共字段，后面的分支检查不等于延迟解构 getter。
- 狼刀候选组合仍为雾鸦狼刀圈→夜之贵族政策→存活名单→恶夜骑士→梦魇。绑定只捕获原 World，四个绑定的创建顺序不变；现场允许结果不能代替实际提交权限。
- 普通狼共享表可写；派生展开仍捕获原 callback，狼美人覆盖回调仍在每次调用现场读取共享表并保留原 member-call receiver。注册表现有晚角色规则与构造期 fallback 算法未改。

狼刀查询入口的英文职责头、两个方法说明与只读查询数据说明已改为中文。新规则组合就地解释婚礼优先、pass、目标短路与自爆首失败顺序；单元夹具说明区分实际提交许可与局部 getter 输入。

## 明确的 API 与验证限制

旧 `wolf/validation_rules` 物理公开路径退休，不留转发叶。共享 `ability-ports` 保留实际装配公开职责，继续公开新唯一规则表；CJS 模块的命名 reexport descriptor／声明位置有意变化，不承诺调用方任意覆盖模块 namespace 等价。

修改前对虚拟新 owner 捕获的静态值图为 398 个模块，没有返回新 owner、旧校验叶或普通狼装配的路径。鬼魂新娘广义公开端口会额外加载 setup、请求工厂及机制出口；这份图不冻结所有共同依赖，也没有把函数内延迟 require 当作冷执行，不宣称全部历史初始化或任意 cold entry 相同。

本批没有执行完整门禁、全类型集、全角色矩阵、完整对局或模型请求；源码／emit 证明不代替全部行为验收，也不宣称 I04、C33 或整轮重构完成。持久证据和冻结源码表见 [结构化证据](generated/wolf-tool-admission-evidence.json)。
