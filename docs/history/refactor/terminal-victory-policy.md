# 终局候选规则归属

本批基于 `0cbe610f5e5293d6b3f4d64628fb750759a4a0e4`，只修改四源码，收拢 PhaseManager 中完整胜利配置选择和婚约封盘前检查，并直接组合原咒狐结果改写。经理仍拥有所有检查点、阶段与唯一终局写入。

## 职责与顺序

- `terminal-victory-policy.ts` 收完整原配置分支：婚约只接受唯一三阵营条件；其它板子依次返回多规则的原数组引用、旧单字段的新数组、屠城默认。每个原位置才读取 World／配置，不提前快照或缓存。
- 表的狐狸能力直接绑定原 `replaceWithFoxVictory`，经本族 `victory-ports.ts` 公开；原狐狸算法／个人 Victory 成员计算未动。不适用的候选仍保原引用。
- 原两个 `evaluateMany` 位置和参数个数分别为三／四，仍归经理。赤月到期前使用未改写的原始候选决定是否执行到期死亡；公开夜报之后才在原位置改写狐狸结果，phase 参数也在原位置读取。
- 封盘仍依次为 `gameOver` 早退、故障计划检查、婚约分配验证、原结构／成员／日期验证、唯一 result/gameOver 写入、原阶段关闭与事件发布。婚约不完整先拒绝，日期在成员核对之后读取；候选规则不标死、提交资源或发布事件。
- Beauty 放逐候选与 ordered override、胜利条件 registry 和结果成员校验器都有现有独立所有者，本批复用，不合并特殊胜利政策。

## API 和边界

新增具名规则表及两处查询闭包，退休经理私有 `resolveWinConditions`；新公开 facet 直接绑定原狐狸函数，没有旧私有转发桥、第二份配置或通用 registry。闭包创建、规则表查找与新的模块加载属于明确内部接口／初始化布局变化；完整证据不承诺任意私有 monkeypatch 或新旧完整冷启动可观察环境等价。

World/config/day 在原字段读取位置晚查询。封盘查询只返回已校验的数据，既不是付款回执，也不是行动授权。原 Fox、Ghost authority、条件 registry、结果 kernel 和 RulePlan 七完整源码作为真实 Git／当前字节控制。
