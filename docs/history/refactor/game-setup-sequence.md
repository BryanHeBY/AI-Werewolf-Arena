# 开局设置序列的规则组合

## 本批职责

真实基线为 `27fbbc0e556027119d452d4dcb1d0409b99b620f`。将 PhaseManager 中四个完整准备步骤归入 `backend/src/rulesets/game-setup.ts`，确定顺序仍为盗贼／千面人 → 野孩子 → 孤独少女 → 鬼魂新娘。

PhaseManager 保留夜晚阶段时钟、日期、原唯一当前性回调、中断快照、猎魔人名单检查、熊捕获和正常夜间流水线。组合负责原窗口的有序装配与串行推进；各具体机制仍拥有参与者、选择许可、库存写入和失败／取消关闭。

最终变更为 11 个源码文件：PhaseManager、具名规则组合、三个既有公开 ports、野孩子新的 `setup-ports.ts`、四个设置文件的中文职责头维护及一个定向单元测试。野孩子通用 `ports.ts` 已恢复原基线字节，作为独立控制文件。

## 时序与读取契约

组合采用同步生成器。PhaseManager 同步推进 `next()`，仅在原窗口的 `execute` 返回值处等待；四项都已准备好时不新增 `await`，最后成功返回也不增加微任务边界。

每个准备判断仍现场读取 World。命中未准备步骤后，保留原构造器查找 → World → 网关 → 事件 → 初始身份种类的参数读取顺序；`execute` 仍以原实例为 receiver，再读取原板子、provider、日期和同一个当前性回调。没有提前收集 World、板子或参与者快照。

每个窗口结果仍使用 `!ready || !nightIsCurrent()`。结果为 false 时立即短路，不补一次当前性查询，不启动后面的设置；成功尾部没有额外查询。异常向原 PhaseManager 生命周期清理路径传播；组合没有自己的回滚、finally 或资源账本，拒绝的 Promise 仍由原具体窗口完成清理。

## 实际发现与修复

首候选曾使用 async helper 与无条件 await。独立审查指出这会在全部准备就绪时新增微任务等待，也会在窗口完成后增加 helper 完成边界。保存该真实候选全文后改为同步生成器，不将首候选误称最终等价。

新增野孩子通用 ports 的类出口曾形成实际静态值环：`ports → setup → action_request_factory → agent_visible_event_feed → mechanisms/index → hook_registry → ports`。最终将准备类置于具名公开 `setup-ports.ts`，保持同一个真实 class 绑定，并恢复通用 ports 的原字节。其余三个机制继续通过已有 ports 公开同一准备类。

本批没有放宽依赖规则、添加豁免或通用设置框架。首候选结构检查时工具识别通用 ports／index／contracts；具名公开 facet 的识别由独立 C04 切片支撑，此功能批不修改 gate，也不宣称 R01 已完成。
