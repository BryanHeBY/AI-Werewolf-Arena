## 有限预设与继承参数

- `winConditions=[slaughter_side]`；死亡不公开身份 `awa_hidden_v1`，遗言 `awa_initial_wave_v1`。
- 警长开启：`awa_nomination_offstage_pk_v1`、`awa_holder_choice_v1`、票重 1.5、平票 `no_elimination`；首日警长先于夜死公布。自爆未完成的选举按现有 AWA 中断规则结束，不承诺实现二级资料中的“双爆吞警徽”赛事版本。
- 放逐采用 `awa_one_pk_v1`、平票 `no_elimination`；普通狼刀票平按 `min_id`。全员合法弃刀且存在雾时的随机另按下文规则。
- 摄梦保护固定为 `netease_2026_night_immunity_v1`；狼鸦额外刀为本板显式穿透例外。预言家 `awa_alive_v1` + `awa_required_when_legal_v1`；白痴沿用现有一次放逐翻牌存活并失去票权规则。
- 四个 hooks 均开启；普通狼的自爆窗口明确为 `on_pre_election`、`on_daybreak`、`on_per_speech_gap`、`on_pre_vote`。自爆后先完成唯一的待定夜结算，再在非终局时结束当日进入下一夜，不继续剩余发言或放逐。
- 首批只接受这组参数，预检、bootstrap 与独立 Tape 均拒绝未验收组合；不同摄梦、选举、窗口版本若扩展，须另补配置矩阵和交叉审查。

## 炼金魔女

两个独立的一次性资源，初始均可用，无毒药；允许同夜先用雾，再于该夜对应的白天用蛇：

1. **未明之雾**：夜间狼聊／投刀前选择三个不同的当前存活号码，可包含自己和狼人；可明确跳过，跳过不消费。少于三个合法号码时不请求使用。有效选择后当夜普通狼刀只能在三者中产生；自刀许可不能把雾中狼人全部排除。
2. **法老之蛇**：尚未消费时，私下得知普通狼刀的原目标；在公布本夜夜死之前，救除该普通刀伤害。可以跳过，只有明确使用才消费；仅首夜可自救，夜序取待结算夜而非当前 Day 阶段或首次用药的时间。刀已被梦境防护抵消时仍可对已知刀口用药并消费，不能根据隐藏保护结果偷取信息。

资源状态、目标及选择作用于原生命；施法者／目标、角色状态、夜序或阶段在等待期间改变，旧响应不得生效或重新领取库存。合法跳过与缺失／非法／迟到响应分开：本板新增技能及规定必答的狼聊／狼刀请求失败直接保存失败前缀，不能由模型 fallback 代用药。这一承诺不扩大现有发言、选举和放逐的缺失响应策略。

## 狼鸦之爪

- 初始封印：狼队知道它，它不知道其他狼；不参加狼聊／普通投刀。
- 每个真实夜间开始时按当时实际存活的狼数判定，少于 3 狼才解封；恰为 3 狼不解封。解封永久保留，得到解封当刻仍存活的狼人队友知识及普通狼聊／刀权。AWA 明确不补发解封前已死亡狼人的身份；已获得的队友知识在其后死亡时仍保留，不能直接用遍历全部原始狼人的通用查询代替知识快照。白天减少狼数不提前解封，尚未公布的本夜预定死亡也不提前计数。
- 解封后获得一次独立额外刀，位于普通狼投刀后，可当夜使用或保留。合法目标是其他当前存活玩家；不能靠同号码的新生命续接授权。
- 额外刀使用单独的伤害来源与事件，穿透本板的梦境保护和炼金救治；命中摄梦人仍按真实死亡引发梦游者牵连。普通刀同中一个目标时分别保留来源。
- 额外刀不受雾限制；狼鸦全局不能自爆，包括解封后。这两条见[狼鸦词条的补充设定](https://bkso.baidu.com/item/%E7%8B%BC%E9%B8%A6%E4%B9%8B%E7%88%AA/57919220?fromModule=lemma_inlink)，属于二级汇编来源；已读的官方公告／攻略没有逐条写出，继续核验角色卡原文。初版按这份公开常见口径冻结，不从“普通刀权解封”推导额外自爆权，也不将雾的普通刀目标范围误用于独立额外刀。

## 雾内无选择的边界

普通狼刀有雾时必须产生一个合法刀口。所有有效回复都明确弃刀时，使用独立可重放 RNG 从当前仍有效的雾内目标选一个；已死亡／替换生命排除。集合耗尽则无刀，不另选圈外对象。随机结果作为引擎事实保存，重放使用同源 RNG。

传输错误、必答回复缺失、取消或非法工具参数不属于上述“全员合法弃刀”，按严格失败处理；不能把 API 故障转换成系统随机并声称成功对局。

## 延迟公布的所有权

只由 PhaseManager 持有一份待提交的本夜夜间结算，状态单向从“待决定”到“正在提交”，再到“已提交”或“已中止”。救治窗口在首次 await 前领取；重入、jumpTo、重复 cycle、取消或授权失效不得再领取请求／药量。内容包括：原普通刀、额外刀、梦境来源、防护、原生命和待定伤害事实。夜末在本板只冻结独立伤害及直接连梦来源，不提前展开 linked，也不提前写表示最终伤害已确定的 night_damage_resolved。原普通刀口即使受保护也单独保存；冻结所有可能被梦牵连者的原生命，不能只保存初始死亡名单。救治后删除普通刀独立来源，再由同一 DreamNightFrame 确认一次牵连。DamageResolution 不在白天重复消费 marks；DeathResolution 仍是实际死亡及追加连锁的唯一拥有者。

本夜开始时炼金存活且解药未用，进入延迟公布流程：夜间选择结束 → 天亮／首日警长流程 → 放逐发言 → 炼金一次私有救治决定 → 提交最终夜死和连锁 → 判胜 → 尚未终局才放逐投票。解药已用或炼金在夜前已死亡时，使用普通公布顺序。

在公告前，预定死者仍保持原实际 Alive，可参与应有的选举／发言；玩家候选、票权、狼队知识、终端及播放器都不得借待定伤害提前显示死亡。炼金本身受致命伤害也不提前剥夺这个决定窗口；是否可救自己另按首夜限制。

白天自爆中断的 AWA 裁定：公开自爆后，先由 DeathResolution 提交该自爆者的实际死亡及警徽处理，再给出唯一一次救治决定，最后提交待定夜死；自爆者是末狼也不得在救治及夜死结算前判胜。救治信息限于已发生的发言，不能直接跳入下一夜，也不能在正常尾部再次请求。本板没有可追加伤害的白狼王或死亡枪，但保留 DeathResolution 的死亡所有权。

- 若普通刀原目标已自爆：保留炼金可知的原始刀口，但它已死亡，救治请求只允许明确跳过，药量不消费，绝不能复活；夜死公告不再重复标死该号码，原夜刀证据仍保留。
- 若普通刀为空，同样在原定时点发送只有跳过选项的私有请求，不提前关闭延迟流程，不因无合法救治对象泄露隐藏事实。
- 若自爆者是警长，警徽转移发生在救治之前；可转给仍 Alive 的待定夜死者，该玩家随后实际死亡再正常处理一次警徽。前端与 World 在救治等待中都已将自爆者标死。
- 已在正常发言尾部完成救治后，`on_pre_vote` 自爆不得重新打开窗口。救治失败仅保存一致的失败前缀：已公开且已实际死亡的自爆者及已发生的警徽处理保留，待定夜死不提交，不能自动救人。

二级狼鸦词条也提到自爆后的救治窗口；以上实际死亡、警徽和统一判胜的具体工程顺序属于 AWA 裁定。

**梦境连锁必须延后确认。** 普通刀中的摄梦人获救后，撤销尚未成立的“因摄梦人死亡而牵连”；梦游者的独立致命来源保留。不能只从已经展开的名单删除摄梦人而留下错误牵连；待定 linked 原因缓存及事件必须一并撤销或重算，已发生的梦选择及连续目标历史不回滚。连续摄梦的直接致死与被刀死亡牵连分开记录，救普通刀不能抹去其它致命原因。

### 救治与梦境的人工账本

D 为摄梦人，M 为本夜梦游者；“救”只消除普通刀来源，不保证最终存活：

| 夜间事实及救治                       | 最终结果                                       |
| ------------------------------------ | ---------------------------------------------- |
| 普通刀 D，救 D，无其它伤害           | D、M 均活，无 linked 牵连事件                  |
| 普通刀 D，额外刀 M，救 D             | M 仅因额外刀死亡，无 linked 牵连事件           |
| 普通刀及额外刀均中 D，救 D           | D 因额外刀死亡，M 被牵连                       |
| 连续摄梦 M 且普通刀 M，救 M          | M 仍因连续摄梦死亡，不删除该直接原因           |
| 普通刀 M 已被梦保护抵消，选择救 M    | 正常消费蛇，工具反馈不透露保护生效             |
| 普通刀与额外刀同中普通目标，选择救治 | 正常消费蛇，额外刀仍致死，不返回不同的秘密错误 |

## 公私事实与双语

- 炼金本人：各资源、自己的雾选择、仍有解药时的普通刀口及救治选择；消耗解药后不再收到刀口。
- 普通狼及已解封狼鸦：当夜雾内合法刀口集合；不得看到炼金身份、药量或私有选择原因。
- 封印狼鸦：不获得狼聊、队友身份或普通刀口。解封私有事件只给狼鸦本人，字段限定 awakened 与解封当刻 knownTeammateIds 快照；普通狼不接收此私有事件，可从随后正常狼聊参与者得知其入群。公众不获得解封事实。已知队友后续死亡仍保留其已知身份，不补发历史狼聊或先前死去的狼身份。
- 公众：已发生的自爆、最终夜死与正常胜利；不公开炼金身份、雾施法者、谁用了救治或额外刀。
- 上帝记录保存稳定机器字段、原选择与效果来源；玩家 DTO 采用独立白名单。中文、英文系统提示、动作提示、错误、终端、复盘和帧渲染共享语义，机器 ID 不翻译。

## 人工判例与分批提交

1. 配置及原生状态：精确板型、两个独立资源、非法组合、默认往返、中英规则，审查 R/A。
2. 夜间阶段：雾的 3 个不同目标、普通刀必选／随机、解封阈值 3/2、额外刀独立库存、生命及晚响应，审查 A/T。
3. 延迟结算：正常发言后用／不用药，首夜自救与后夜拒绝，解药已用恢复普通顺序；自爆前／中／后与重复关闭，审查 R/A/T。
4. 伤害交互：普通刀／额外刀同目标和异目标，梦保护、连梦、救回摄梦人、梦游者独立致命源；末狼／末神／末民在救治前不得提前判胜。
5. 完整闭环：实际 SDK/ACP/MCP 中英完整与失败对局、受限观察者及 20–50 固定种子、独立 Tape 账本拒绝库存／目标／RNG／公开时点篡改；前端公告前后、回退与最终 checkpoint。
6. 在夜间结束、首日警长结束、每次发言后逐帧断言尚未因公开自爆实际死亡的待定夜死者仍 Alive；不得因待定夜死提前发布夜死、梦死、警徽或胜利。已公开自爆的实际死亡与警徽交接按上述明确顺序正常发生。覆盖正常尾部、四种自爆窗口及公告前后回退；Agent DTO、终端、播放器与 checkpoint 一致。Tape 拒绝提前死亡／胜利、重复救治、删额外刀来源、伪造梦牵连和救回摄梦人后仍保留 linked 的记录。
7. 至少三组只读交叉审查，主任务修正并由原审查者复查；同源门禁后按可构建功能边界提交。本卡在候选被实际验收前不改变角色目录状态。
