# AWA Miracle Merchant 1.0.0 规则卡

<a id="miracle_merchant"></a>

规则集 awa_classic 1.0.0；ID `miracle_merchant`，奇迹商人／Miracle Merchant；核验 2026-10-09。采用奇迹商人的验／毒／守赠予版本，与黑市商人验／毒／枪及次夜生效版本分别实现。

## 第一方依据

[2020-06-10 官方发布帖](https://www.taptap.cn/moment/19875502311345790)作者显示“狼人杀丘比酱／官方版主／《狼人杀》官方小助手”。正文规定一局一次、先于其它角色选择另一玩家，赠验/毒/守；给狼人不授能力、次日商人出局。Q&A 允许幸运儿当夜或后夜任选一次使用，并明确同一持有者的原生与幸运技能：同夜不重复验/毒/守同目标；守护还需避开自己前夜两种操作守过的目标；幸运守护与解药仍适用同守同救，不能读取其它原生神职的行动。

[2020-06-11 官方上线稿](https://langrensha.com/news/official/20200611/26904_885985.html)核三种能力及 10/12 人角色组成；[2020-06-18 官方表演赛](https://langrensha.com/news/official/20200618/26904_887512.html)实际展示首夜不赠、后夜赠毒并当夜使用。[2026-03-06 官方沙龙说明](https://langrensha.com/news/official/20260306/26904_1289873.html)明确梦保护可挡商人给狼造成的反噬，咒狐可收附加幸运技能；摄梦人及咒狐已有各自有限实现，具体赠予与保护交互见[摄梦人卡](awa-dreamer-v1.md)、[咒狐卡](netease-cursed-fox-v1.md)及[支持边界](../contracts/mechanism-support-boundaries.md)；来源说明不因此开放整个沙龙板。

以上未明确受赠者获商人 ID、商人即时获成功结果、复活/转移与全部精确阶段、错误/撤权等细则。下面明确标为 AWA 选择；百科、个人攻略或小说不作为这些规则的来源证明。

## miracle_merchant

本 AWA 版本：

1. 原生最多一名，Good 神职、Good 胜利；无原生狼队信息/刀权、自爆、枪或豁免。`roles.miracle_merchant` 仅 `{}`，任意库存/时序/反噬开关拒绝。
2. 原生 125 阶段（静默重置后、其它实际角色行动前），任意夜可 `bestow_ability {target_id:number,skill:check|poison|guard}`，另一实际活玩家；不可 self/dead/null。可不调用工具等待：只关本夜，不花全局一次。合法提交才花该次机会；三次无效回复不冒充合法等待。
3. 提交点按真实 camp 分类，明确伪装标签不参与；Wolf 目标不获技能、不知被选择，商人反噬列入本夜伤害提案。非 Wolf 获一个独立、一次性的幸运能力，不改变原 role/camp/胜利或原生资源；第三方的实际组合随后续角色卡与矩阵验证。
4. 当前主动板子白名单：Merchant/Wolf/WolfKing/HiddenWolf/Seer/Witch/Guard/Hunter/Dreamer/Villager/CursedFox。parse 与 direct bootstrap 均验证；含咒狐的组合还须满足[咒狐卡](netease-cursed-fox-v1.md)的单屠城等约束与双方角色白名单，列表不代表任意组合。机械有限板不联合开放。其它已实现牌不单凭枚举自动声明组合支持。
5. 幸运技能在独立 700 阶段、普通对应角色行动后，获赠当夜即能使用，也可留后夜。每夜一次可选请求：无工具等待或合法空守/none 用药不消费一次库存，但关闭本夜机会；实际验/毒/非空守才消费一用。无合法验目标时无请求/虚假报告。用尽后不再请求。
6. 幸运查验为 `seer_check`／`check_identity`，按规则 camp 标签、允许跨夜重复、不允许自验。幸运毒为 `potion`／`use_potion`，仅一毒、无解药/原始刀口；毒可选自己或其它存活玩家。none 可等待，target_id须本人编号；不能用none掩盖非法/虚构目标。幸运守护为 `guard`，可 self 或活人/空守，只挡普通刀，按既有 Guard/Heal/Dream 结算。
7. 原生与幸运能力各有库存，不共享使用次数。目标联合约束只按同一玩家已实际接受的操作：每一相同技能 kind 同夜不能重复同目标（不同 kind 可选同目标）；守护次夜避开此人前夜原生和幸运守过的全部目标。不同玩家互不约束，不能用世界印记/他人事件作为预检过滤器。
8. AWA 用 per-World、按稳定玩家 ID 的私有行动账本实现上述联合约束；只记录本人自己的 day/kind/target/幸运标识。校验、目标提示与观察 DTO 读取同一事实，不能依靠一个实例 lastTarget 猜另一个实例。机械原生特殊技能不冒充普通幸运技能。
9. 一旦实际死亡，附加幸运能力永久 disable；复活不恢复或补资源。已实际提交的毒/守等本夜效果仍保前缀与原生命范围。转移保原库存/关闭夜/幸运政策/禁用，不重置；附加幸运能力不作为本版可复制的原生技能。未来复制角色须冻结自己的来源政策，不能用低层 grant 自称完成该玩法。
10. 收者私下知道获得的技能与库存、不知道商人 ID；商人只保存自己的选择/消耗，不获即时 success/目标 camp。God 保存分类及因果，失败目标无通知。能力 ID 不编码商人 ID，`sourceDisclosed:false` 同时裁掉事件/DTO 的 source actor；合法公开结果可被玩家推理，不扩授隐藏信息。
11. 反噬是独立 `merchant_backlash` 死因，不被普通 Guard/Heal/机械盾挡，有效 Dream 可挡。挡住也不返交易次数，目标仍无 gift。原 Merchant/生命/角色状态失效不伤新身体；分类在合法提交冻结，不因 Wolf 目标随后死亡/变阵营回写。
12. 阶段只提交能力或 typed 反噬提案，不写 Alive/judge。Damage 计算实际伤害，DeathResolution 统一全部遗言/徽章/钩子/追加死亡后 PM 判胜。首夜初批反噬明确有遗言；其它夜晚/追加波次沿 AWA 原策略，反噬及复合反噬禁枪。
13. actor/target 原生命、角色/阵营/私有库存、phase 与赠予提交/能力消费在 await/gateway/实际应用处复验。撤权不花新 owner 的资源；已花库存与记录前缀保留。完整夜流程提交后同 World/day 重入拒绝，不丢已付交易或保护。
