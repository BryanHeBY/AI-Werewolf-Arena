# AWA Gravekeeper 1.0.0 规则卡

awa_classic 1.0.0 角色扩展，ID `gravekeeper`，守墓人／Gravekeeper；来源核验2026-10-08。

## gravekeeper

- 好人神职、好人胜利归属；不获狼队身份/夜聊/刀权，没有原生主动夜间工具、次数资源、死亡技能或放逐豁免。
- 从第二夜开始，在女巫行动后、预言家查验前，被动获知上一日真正被放逐出局玩家的阵营查验结果。首夜无放逐反馈；不向玩家发伪造的查验/确认行动。
- 只处理放逐主目标：白痴翻牌免死、弃票/无人放逐、自爆、骑士决斗、枪击及其它追加死亡不产生此反馈。上一日没有实际放逐时不重复更早结果，之前已获得的信息仍保留。
- 放逐定案、进入死亡结算前冻结目标的共享 `camp` 查验标签（通常等于真实camp；明确伪装按profile标签），不冻结具体牌。目标随后变化或遗言/死亡钩子不会反向改变已经定案的反馈。
- 框架camp查验结果为 `good|wolf|third_party`，私有typed result不转换成具体身份或胜利归属；未来角色伪装/第三方组合必须按各自卡另验，不据本卡宣称那些角色已支持。
- 反馈时当前仍存活的守墓人获得一次结果；当夜尚未统一结算的狼刀/毒标记不提前阻止反馈，已死亡者不获新结果。变成其它角色后不继续获得此技能，旧已授权历史仍属于原演员。
- 多个守墓人各自收到同一合法结果，逐人独立状态；同一夜重入不重复发事件或记历史。无反馈不改变资源/生命/阶段、选举或判胜。

## 信息与所有权

PhaseManager独占上一日放逐事实，作为内部NightPipeline输入；没有把待反馈信息提前放进角色私有DTO或提示。本人状态只保存实际已交付的历史（exileDay、receivedDay、targetId、camp result），没有待反馈目标/底牌。

`gravekeeper_reported {actorId,targetId,exileDay,receivedDay,result:{kind:"camp",camp}}`仅actor可见，公开发言若主动引用是玩家原话，不自动认证具体牌。上帝复盘可保完整反馈，其他玩家投影无此事件/状态，终端该事件的直播行仅在printPrivateEvents启用时展示。operator若另启printLlmIo/printThinking，仍可能看到包含本人已知反馈的prompt/思考；这些独立诊断开关按[日志矩阵](../history/expansion/runtime-display.md#p4-m21sdk--acp-日志开关)工作，不是发给其他玩家的信息。回放消息/前端文案使用同一双语result标签，不改变席位生死。

## 来源及AWA改编

[Melbourne Masters组织者板子与夜晚流程](https://melbournemasters.org/setups/shi-xiang-gui-shou-mu-ren)规定每夜告知上一放逐环节出局玩家好人/狼人，首夜只确认角色，后续位于女巫后、预言家前。该来源是组织者规则，不充当所有平台统一规范。

AWA对无实际放逐不重报、主目标与追加死亡区分、冻结标签时点、同夜去重和复合/未来camp明确采用上述规则；来源没有提供这些全部细则。不与“跑跑狼人杀”尸体感应技能混用。P5普通狼＋守墓人的6/12示例保留；石像鬼已独立交付，放逐后的守墓人反馈等证据见[石像鬼卡](awa-gargoyle-v1.md)及[交叉审查](../history/expansion/reviews/p6-gargoyle.md)。单个交互验证不表示已复刻来源完整板子。

## 参数与支持边界

默认被动规则无需额外参数；`roles.gravekeeper`只接受空对象，未声明的真假牌/主动查验/重复反馈开关拒绝。原Day/Night/Voting、遗言/徽章/判胜仍由现有流程负责。额外授予的夜间能力按原能力授权/调度另行执行，不由被动技能取消。normal profile可与已经支持的基础/狼王/白狼王/骑士做下列明确测试；新身份变化/特殊伪装必须补组合门槛。

## 必须验收

初始无历史/首夜无请求；普通狼与好人放逐反馈；伪装/目标后续变化/typed第三方边界；白痴免死/无放逐/自爆/决斗/枪击不误报；多守墓人、死亡/当夜待死与同夜去重；终局不产生下一夜反馈；本人/他人视图及中英提示、公开上帝复盘/受限DTO；六人/十二人完整字面计划、SDK/ACP/混合双语接入与Tape、每板固定种子受限模拟、终端/前端/browser/Remotion帧，三路交叉审查。
