# AWA 寻香识命十二人板

状态：implemented；[完整技术验收](../history/expansion/reviews/p9-fragrant-pair-stage-acceptance.md)及三路复核通过；交付时目录快照与门禁冻结输入见该记录，不代表当前重构源码全量通过。`fragrant_phantom` 与从 P9f 前置的 `awakened_seer` 使用联合政策 `awa_fragrant_pair_seer_v1`。只开放本卡的原生有限组合。

## 来源与配置

2026-10-11 核验 [网易 2023-03-02 公告](https://langrensha.com/news/official/20230302/26904_1076159.html)：十二人包含寻香魅影、3 普狼、4 村民、觉醒预言家、女巫、猎人、守卫。觉醒预言家双目标查验只获知其中是否存在狼人；魅影首夜随机知道一名其它狼，起初不入狼队，其余狼全灭后才有刀；可以每夜重新绑定，但整局死亡牵连只触发一次。

公告附带的[角色规则图](https://nie.res.netease.com/r/pic/20230302/22942bd0-99f5-47b8-9449-ae8b4ad8eb56.png)明确魅影不自爆、不参加通常狼聊／刀行动；[官方配置图](https://nie.res.netease.com/r/pic/20230303/45d0a2a7-f33d-47fc-8662-a1f7a02cdaf3.jpg)区分十二人女巫禁自救与十人首夜可自救。本卡只支持十二人，不将两种人数规则混合。资料没有写明的期限、弃用、同波消耗和晚授权在下文标为 AWA 裁定。

固定配置：屠边，死亡隐藏身份、初始死亡波遗言；启用警长提名／退水／警下票／一次 PK，票重 1.5、持有人移徽、票平无警长；放逐一次 PK、票平无放逐，狼刀票平取最小号码。首日先完成警长流程再公布夜死。普通狼仅在选举前、放逐前自爆；魅影始终不能自爆。守卫使用真实连续夜不可同守政策，允许自守／空守；女巫禁止自救、仅有解药时见原刀口、原生每夜最多一药；同守同救沿既有板规。猎人保持默认合格来源枪，牵连不是合格来源。不含其它觉醒、赠予、复制、复活、第三方或特殊狼人。

## 固定夜序及知情发布补充

本有限板固定：真实夜初开夜／上一周期绑定到期／首夜唯一已知狼提交／本夜刀权冻结 → 原生药重置100 → 魅影绑定150 → 普通狼聊200 → 守卫300 → 狼刀400 → 女巫500 → 双目标查验600 → 普通夜伤及PM原有首日警长先于夜死流程。不同数字为独立阶段优先级；不复用单体预言家查验或猎魔板的提前死亡公布分支。

首夜已知狼使用游戏命名随机流 `["night", "fragrant-known-wolf"]`，对原始三个普通狼号码升序列表以一次 `next()`、`floor(next * 3)` 取索引，恰抽一次；不是每次prompt重抽，也不洗牌后取首位。首次成功提交其知识即属于魅影，本夜后继失败不退款。基础草稿／纯状态测试不是实际随机或接入验收，最终账本另独立核seed、抽取及唯一事实。

实际触发receipt中的关联根死者／追加目标／同波区别字段仅God与独立审计持有，不能直接拿actual state渲染玩家；公开 `additional_deaths` 仍按既定时点发布实际追加死亡号码。本人随机知识及合法选择成功后即时知情；一次触发是否已消耗，只能由已公布、属于本周期原绑定生命的真实死亡推进知情状态。损伤提案、待公布夜死及原始God触发不得使竞选提示提前显示used／triggered。未来能力uses/status及所有metadata也沿同一知情约束。真实下一夜开夜完成后才清当前已知绑定；单独的phase_changed入夜不等于完成到期。原选择日期与号码及唯一已知狼作为历史保留。

活人阶段的请求租约与已付关系分开：租约关闭／失败不抹掉本周期已付绑定；原施法者第一次真正死亡后仍可按卡的枪链触发关系。替代身体、死亡后复活或原技能实例替换不能继承旧关系。纯状态函数不控制夜序、阶段、原生命或公开死亡授权；这些由唯一World owner及DeathResolution证明。

## 双目标查验

- 首夜起，每夜一次，从当前存活号码选两名不同玩家；允许包含自己、重复以前查验的号码或整对。**AWA 请求政策**：存在两名候选就必须选择、不得空过；不足两名时不发请求、不伪造选择或结果，阶段结束仍由 PM 正常判胜；不能提交同号码两次，也不能只提交一个再由系统补齐。
- 唯一结果为 `containsWerewolf: boolean`：两者至少一个真实狼阵营则为 true，两者均好人为 false。不返回数量、哪个号码是狼、单独阵营或具体角色；本有限板没有伪装角色。统一布尔值是 AWA 协议表达，自查时玩家可以结合自己的已知身份推理另一目标，协议仍不另返单体阵营。自查、跨夜重复也是本卡明确的有限目标政策；公告未逐项枚举这些细则，不冒称全部来自官方原文。
- 正规化目标对只用于去重和历史表达，不改变玩家 ID。结果及目标对只给本人和 God，不通知目标、狼队或其他好人。原始工具返回、MCP、事件、system/current prompt 和错误信息都须同样遵守。
- 必须有独立的双目标请求／能力契约，不能把两次普通预言家查验拼成一次后依赖文案隐藏单个结果。跨 await 同时复验两个目标的原生命及原 Role/Camp 查验身份、施法者原能力、阶段和库存；任一失效，整次不提交、不消费、不产生半份结果。

## 狼队信息和刀权

- 魅影属于狼人阵营并计狼人胜利，但从不参加普通狼聊。普通狼彼此互认，不知道魅影。魅影首夜由专属确定性随机流，从其它三个初始狼人中抽出一人，只通知该号码给魅影。
- 首夜抽取仅一次，重放使用同一随机来源，不调用全局随机数；空过／失败／重入不重抽。该已知身份作为历史保留，不额外获知其他狼身份或其私聊。使用单号码历史知识投影，不能配置识别整个 Wolf 类而旁路返回全部三狼。
- 刀权只在真实夜初冻结。其它狼已全死时，魅影取得一个普通狼刀投票权，依然没有普通狼聊，也不能自爆；同夜中途的死亡不补发另一刀。该夜的持刀资格在真实开夜提交时只告知仍存活的本人，即使牵连已耗尽、没有绑定请求也通知。刀权DTO只含夜次、资格布尔值及已授权的接刀历史，不返回其余狼数量、存活／身份表或冻结判定理由；历史已接刀知识与仅当夜有效的实际许可分开。它仍可在同一夜绑定。
- 本板不禁止普通狼误刀未互认的魅影；普通狼合法目标表不能因为魅影身份而排除其号码。魅影拿刀后可以明确空刀，刀及女巫刀口沿普通机制。

## 绑定与 AWA 期限

1. 首夜起、技能尚未触发且魅影夜初存活时，可选两名不同存活玩家（可包含自己）或明确空过。绑定选择自身不改变刀权或胜利归属。
2. 一次绑定覆盖本夜及随后白天，下一真实夜开始先到期；该夜重新选择新的绑定。明确空过表示本周期没有绑定，不延续上一对。魅影在白天已死时，下夜到期后不会创建新对。
3. 已提交的绑定不因魅影当夜或白天死亡而倒销。绑定存续期间，任一目标真实出局即消费整局一次触发，另一目标若还未进入同一死亡波则追加牵连死亡。已有独立致死来源、同时进入该波的另一人不再重复死亡或追加虚假的牵连来源，但这对绑定仍视为已触发并耗尽。
4. 狼刀／女巫毒／放逐／普通狼自爆／猎枪造成的真实死亡均可触发；被保护而没有死亡、无效攻击、空枪或投票未放逐不触发。猎人因牵连出局不能开枪；猎人原本已因独立合格来源进入同波的资格不被重复附加牵连改写。
5. 追加死亡进入既有 DeathResolution，先完成所有遗言、警徽及枪链，再统一判胜。最后一狼和最后神民同时受牵连时，本板固定采用 `awa_good_priority_v1` 的既有屠边顺序：先查全狼出局，再查神或民清空。全狼与最后一神同时出局时 `winner=good`、`reason=all_wolves_eliminated`；结构化 outcome 为 victory，primary 是 good faction，additional 为空，winningPlayerIds 由所有好人胜利归属（含已死者）确定，不能在关系刚触发时提前封盘。
6. 同波两端同时死亡只触发一次；循环通知、重复事件、失败重入不能再消费。关系持有原双方生命、创建夜序、到期夜序和原能力所有者；替代生命不得承继旧关系。

### 死亡波与遗言冻结

AWA 初始波政策在本板增加首夜牵连来源：N1 刀死 A 并牵连 B，二者同属初始夜波，均有首夜遗言；N2 起二者均无夜死遗言。D1 放逐 A 牵连 B，只有 A 的放逐遗言，B 不因合并入初始波取得资格。猎枪打 A 再牵连 B 属追加波，二者均无遗言。不得仅以 firstBatch 推断牵连有遗言；须显式检查来源及真实死亡阶段。

沿 DeathResolution 保留原始输入波顺序，将新增牵连目标追加在后；全波真实死亡标记 → 该波合格遗言 → 按波顺序处理全部警徽，再按波顺序处理全部死亡枪 → 下一追加波 → 全链判胜。手写场景固定 A 后 B 的波顺序，检验遗言 A/B 在各自警徽和枪之前；B 为持徽者时移徽后才进入下一波。`additional_deaths` 只公开新增实际 deaths，不携带绑定、施法者或私有关系原因；不能用私有绑定事实提前标死。

## 信息与失败

绑定对只给魅影本人和 God，两端不获通知。真实牵连出局的公开播报不能暴露魅影号码或其它仍未公开的私有关系；God 原始事实与各受众 DTO 明确转换。夜间私有绑定、随机身份揭示、到期本身均不改变前端 Alive。公共规则须清楚说明“一次触发、每夜可重选”“下一夜到期”“同波不附加虚假死因”。

新增双查、绑定以及本板规定的狼聊／狼刀均采用 `error/no fallback`，严格区分合法空过与 missing／invalid／late；普通日间发言、选举、投票与可选自爆沿既有策略。取消、阶段切换、原能力／原目标生命改变即撤回请求；已经提交的知识／绑定不因随后的失败退款。失败时保留真实前缀，不伪造双查结果、自动选对、重抽已知狼或静默跳过晚校验。

## 人工判例与交付

1. 好好、狼好、狼狼双查均只得到布尔值；本人＋狼合法、重复同号码非法；跨夜同对合法。
2. 交换两个目标顺序不改变结果或泄露额外信息；仅第二目标换生命，或保留同一 Alive 而替换 Role/Camp 查验身份时，整个请求失败且库存不动。
3. 首夜随机已知狼可重现且只一个；改变无关随机流不改变该抽取。已知狼死亡后，另两狼身份仍未知。
4. N1 绑定无死亡，N2 改对／空过；旧对在 N2 不再牵连。未触发不耗整局次数，实际触发后不再有绑定请求。
5. 绑定一狼一民，狼被放逐／自爆时民牵连；保护成功无触发。魅影自己与猎人绑定，魅影毒死，猎人牵连不得开枪。
6. 同对分别受刀和毒、同时独立死亡，只记一次触发，死亡各一次；猎人本身合格刀死仍开枪，不被附加关系原因误禁。
7. 猎枪打绑定端，再追加另一端，涉及警徽及末狼，整条链后才有一个 game_over。
8. 魅影不在绑定中，同夜被毒杀，猎人被普通刀杀；初始死亡波已包括魅影后，猎人枪杀绑定端，本周期绑定仍牵连另一端。该场景能通过真实 pipeline 到达，无需在已结束的放逐阶段注入虚构枪。另测未触发绑定下一夜正常到期。魅影是最后狼时，已封盘不再生成后续关系行动。
9. 最后普通狼前夜死亡后，魅影次夜取得普通刀；前夜尚活时不提前拿刀，也不泄露真实队友表。
10. 双语 SDK／ACP／混合完成本板角色闭环；Tape 独立推导抽取知识、两目标布尔、期限／资源、实际死亡来源、每一请求及 checkpoint。拒绝单体结果泄漏、伪造第三个目标、错误重抽、旧绑定续期、重复触发及无资格 error/pending。
11. 独立账本必须拒绝成功 decision 与 event 双删后同时回退 checkpoint；以 resolved night 的应请求角色机会核验完整性。固定 seed 手写已知狼号码及抽取次数，禁止复用生产抽取器生成预期。
12. 首夜刀 A→牵连 B 两人遗言，第二夜同路径均无遗言；放逐 A→B 只有 A 遗言；枪 A→B 均无遗言。末狼与末神同链死亡，精确断言 good / all_wolves_eliminated 与全体好人 winningPlayerIds，仅一个 game_over。
13. 前端／终端／Remotion 在选择、双查返回、夜公布、白天链、下一夜到期各帧一致；私有事实不提前公开身份或改变存活，回退／刷新及最终 checkpoint 一致。

提交顺序：规则冻结 → 双目标能力及独立 DTO → 有限绑定/到期与夜初刀权 → 死亡链／撤权 → 严格录制与双语 → 公开配置、受限模拟、实际传输和界面验收。R、A、T/L/D 三组审查；三组文档预审及原意见复核已完成，修正了不可达枪链例、死亡波／遗言、判胜优先级和严格失败边界；运行、录制／Tape、双语实际通信、受限观察、前端与同源全支持门禁已通过，范围见[完整技术验收](../history/expansion/reviews/p9-fragrant-pair-stage-acceptance.md)。
