# AWA 觉醒狼王 1.0.0 规则

<a id="awakened_wolf_king"></a>

角色 `awakened_wolf_king`／Awakened Wolf King；政策 `awa_awakened_wolf_king_v1`，核验日期 2026-10-15。**已实现下述原十／十二人两板；觉醒女巫来源板在其独立交付前仍拒绝。** 本卡不替代普通狼王的[独立规则](awa-wolf-king-v1.md)。

- 同稿[原板配置图](https://nie.res.netease.com/r/pic/20231113/76bb6e3a-626e-4088-8252-2f1c7fc76af2.jpg)明确：十二人是 3 普通狼、觉醒狼王、4 平民、预言家、女巫、奇迹商人、摄梦人；女巫不能自救。十人是 2 普通狼、觉醒狼王、4 平民、预言家、女巫、奇迹商人；女巫仅首夜可自救。
- [2024 觉醒女巫发布稿](https://langrensha.com/news/official/20240805/26904_1171626.html)另有十二人组合：3 普通狼、觉醒狼王、4 平民、预言家、守卫、猎人、觉醒女巫。

来源没有逐项规定传授时点、每夜数量、同人叠加、精确死亡源和空枪。下文标为 **AWA 补全** 的部分必须进入具体政策及独立预期，不宣称是官方完整细则。

## 身份、范围与配置

1. 真 Wolf、沿狼队胜负与屠边侧；双向互认仅队友座位，不自动公开具体狼牌、受传者和库存。共用狼聊、刀票；可自刀、刀队友和空刀。普通自爆仍不附带枪。
2. 原生至多一张。当前交付只接受上述原十／十二人两份精确牌池；已核验的觉醒女巫十二人板须等待觉醒女巫完整实现后另批启用。缩编测试须明确为测试输入，不登记来源板。额外牌、复制、复活和身份改换组合不开放。
3. `roles.awakened_wolf_king` 初版只接受 `{}`。死因政策固定复用本卡列明的 AWA 狼王允许集合，不暴露任意布尔组合。日后支持确有来源的不同传授／禁枪版本，应另具名政策并逐板验证。

## 亲传、资源和死亡状态机

4. 初始两个独立爪单位。**AWA 补全**：从 N1 起，在狼聊后、狼刀前每夜一个 `bequeath_claw {target_id:number|null}` 窗口；null 合法空过且不耗爪。目标为另一原活且当前已知狼队成员；不能自己、死人、未知隐藏狼或已持一个未用亲传爪者。每夜最多传一个，可跨两夜给两名不同队友；已传单位不收回、不补发。
5. 提交点复验原身份／生命／能力源／库存／目标，随后同步从本体扣一个并安装唯一亲传能力实例。记录源、受传原 life、receipt 和剩余数。传授成功后施者死亡不撤回；受传者死亡后技能按其绑定实例结算，不借活着的传授者再授权。目标被换 body 或能力撤销不能让新 body 获取旧爪。
6. 本体实际死亡且满足许可时，按死亡窗口依次处理其仍持有的爪，至多两个。每次 `shoot {target_id:number|null}` 选当前原活目标；null 明确放弃并消耗该单位，不因第一枪成功自动消费第二枪。**AWA 时序补全**：第一份非空枪同步付款，交 DeathResolution 真实提交目标与其完整追加连锁，再开放第二决定；第一枪造成的真实死亡者不会再出现在目标域。第二决定失败时保留第一枪已付／死亡／词徽／连锁前缀，第二未付单位不扣。不能在 hook 内只攒两目标数组再整体抛错丢第一份，也不能把 action accepted 当真实死亡。
7. 受传者只有一个亲传爪，使用同一动作／窗口和允许死因，不能转传。其本来拥有的能力不被覆盖；不在本卡支持闭包中的叠枪角色仍拒绝装配，不靠“理论可组合”开放。
8. **AWA 补全**：狼刀、真实放逐、Shot 可授爪；毒、梦游／梦殉情、自爆、决斗、普通魅惑、未知源不授爪；复合来源必须全部允许。来源集合沿[AWA 狼王](awa-wolf-king-v1.md)，不能因为持有两爪而绕过毒与梦禁用。奇迹商人赠验、赠毒、赠守和梦保护分别使用原政策，不把传授当商人赠礼。
9. 夜间刀／毒／梦先按本板原保护结算，只有实际死亡进入爪窗口；爪为死亡追加波，不受已结束的普通守卫／解药阻挡。**梦保护另按来源传播**：原狼王十二人板显式采用 `roles.dreamer.protectionPolicy=awa_night_damage_v1`；原夜死者黎明使用的爪仍携夜间来源，被梦者可免该枪，爪仍消耗，不能伪造击杀；若爪实际击杀原摄梦人，其当夜梦游者追加 Dream 亡。白天放逐所生爪没有夜源，既不受旧梦保护，也不触发旧梦牵连。每波先真实标死，再该波全部遗言、全部警徽、死亡能力和追加波；完整链后由 PhaseManager 判胜。末狼持两爪时仍须完成其合法决定，不提前判好人胜。
10. 遗言与徽沿本板基础时序：首夜合法原刀和真实初批放逐可获词；追加枪不额外授词，普通自爆不授词；警徽只随真实死亡处理一次。第一枪完整连锁后再选第二，通过具名 death-action continuation 交给 DeathResolution 拥有波次与继续点，不由 feature 递归真实死亡或引入全角色中央分支。即使第一枪后人数已经满足终局条件，仍在完整已授权死亡链后的既有检查点统一判胜；第二请求前原角色／私库／能力源被撤换则按原 paid 许可明确拒下一请求，不向新 owner 请求或消费资源。原语与本族的独立反例覆盖首枪及其后代真实死亡后再请求、原许可先关闭、第二请求失败保留首枪完整前缀。

## 知情、失败和实现边界

11. 私有传授事实只给授予者和受传者各自必要字段，不向其他狼或目标公开来源／剩余数。成功公开枪使用中立枪击事实，只公开 actor／target；God 另保原始角色、爪单位、源实例及因果。终端／Web 不通过 type、stage、文案提前泄露受传者原身份。
12. RequestLease／RequestDelivery 绑定原 World、owner、life、阶段和截止时间。跨 await、网关及首扣库存前复验；接受动作不等于消费。迟到、阶段撤销、错误目标、实例换主不得扣新库存。付款后记录异常保资源和已发布前缀，未实际死亡不能补造生命变化；清理和业务错误分别保留。
13. `features/awakened-wolf-king/` 持原生爪与亲传窗口；实际枪能力复用 `features/death-actions/` 的能力源和死亡窗口，不复制第二套库存。`rulesets/` 持精确支持、顺序、死因贡献；engine 保唯一死亡提交和最终判胜。公共合同只放惰性 DTO，观察不返回库存容器／World／授权句柄。现场 checkpoint 与独立 `recording/verification/` 规则分开。
14. 新角色、亲传、剩余数、空过、拒绝、枪击、审计和复盘中英文齐备；名称为“觉醒狼王／Awakened Wolf King”，机器 ID 和用户发言不翻译。两语实际 SDK／ACP／mixed 走相同授权链，不能只在 mock 内有效。

## 示例与回归边界

支持 `awa_awakened_wolf_king_10_v1` 与 `awa_awakened_wolf_king_12_v1`，配套 game 及各自 `_en`／`_acp` 入口见[两语完整示例](../examples/awakened-wolf-king/README.md)。女巫自救和十二人摄梦保护显式配置；觉醒女巫来源板按其独立规则开放，额外角色和未知参数仍拒绝。

回归分别核对本体与亲传消费、双爪的完整后代链、原生命和独立库存、末查询双方换体、未来夜开窗、第二枪缺失／迟到及已付前缀。玩家只收到获准的私有事实；公开中立枪击不披露额外技能来源。受限整局、同构建严格重放和本地合成传输不等于真实模型质量评测。
