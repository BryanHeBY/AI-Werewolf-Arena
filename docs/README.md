# 项目文档

本目录维护当前玩法 spec、运行契约和开发指南。阶段计划、迁移台账和逐次审查产物不作为长期文档维护；需要追溯改动时查 Git 历史。

角色入口见[支持矩阵](contracts/gameplay-support-matrix.md)，机制与配置边界见[机制支持契约](contracts/mechanism-support-boundaries.md)。开发要求和验证方法分别在维护指南中维护，阶段进度及逐次审查结果从 Git 历史追溯。

| 问题                                     | 入口                                  |
| ---------------------------------------- | ------------------------------------- |
| 角色来源、规则版本、特殊机制与可配置变体 | [规则 spec](rules/README.md)          |
| 公开板子、游戏入口与两语教学归档         | [运行示例](examples/README.md)        |
| 配置、行动、事件、玩家观察和归档格式     | [接口与运行契约](contracts/README.md) |
| 模块归属、状态写权和生命周期             | [架构 spec](architecture/README.md)   |

| 关键设计选择及理由                       | [架构决策](decisions/README.md)       |

## 维护约定

- 完整玩法只在对应规则卡维护；代码说明职责与约束，并引用规则卡。
- 角色的资料状态不代替运行支持。具体板子还须通过 schema、角色组合和 ruleset 校验，边界见[机制支持契约](contracts/mechanism-support-boundaries.md)。
- 公共复盘、逐玩家视角及私有严格复现分别处理；可序列化字段不能授予运行权限。
- 自维护代码使用有效中文注释，说明重要数据结构和关键逻辑，要求见[新增机制指南](guides/add-mechanism.md)。

各目录索引维护当前有效内容；规则卡保留来源、实际行为和可复用判例，不追加交接指令、阶段计数、临时工作目录或逐次执行日志。敏感信息与归档发布要求见[仓库隐私维护](guides/repository-hygiene.md)。
