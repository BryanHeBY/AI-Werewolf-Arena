# 本地工作台

工作台把配置、对局运行、ANSI 日志和已有复盘放在同一个本机页面，继续使用 `configs/` 与 `record/` 文件。

首页首先显示可启动的已保存游戏；板子和游戏配置默认进入本地列表，查看、编辑、复制和新建分别操作。初版还包括 Agent 平台向导、三类删除、独立进程与 ANSI 日志、结束后复盘。持续要求与定向验收见[初版交付要求](../architecture/workbench.md#初版交付要求配置管理快速启动与删除)。

尚未准备好首局时，首页显示 Agent → 本地板子 → 游戏的配置进度，各步标明“已保存”或“待配置”并提供入口；主按钮指向当前缺失的步骤。示例规则只作为新建板子的模板，不向本地目录批量灌入占位 Agent 或游戏。

外观复用视频与网页已有的哥特／简约主题、授权字体、语义色板和哥特素材。首次默认采用视频的哥特主题及夜间色调；已有网页主题偏好继续保留。侧栏可切换主题与明暗，回放页共享同一外观控制器，终端采用相同主题的夜间色板。

## 启动

```bash
bun install
bun run workbench
# 打开 http://127.0.0.1:4310
```

根命令先构建客户端，再启动本地服务。已有 `configs/`、`record/`、`output/` 都保留。首次访问配置 API 时，缺失的 `runtime/backends.json` 和 `runtime/agents.json` 自动补为 `{ "schemaVersion": 2, "items": {} }`。已有文件（包括空文件或坏 JSON）保留原内容，不自动导入占位连接、认证或游戏。首页和 Agent 页引导“配置 Agent”，通过平台向导填写自己的认证；首个 Agent 自动成为默认值，后续添加保留已选择的默认 Agent。

```bash
bun run workbench -- --configs-dir ./my-configs --record-root-dir ./my-records --port 4311
```

默认端口 `4310` 被占用时，入口会显示明确提示并退出。可以打开已经启动的工作台，或使用 `bun run workbench -- --port 0` 让系统选择空闲端口，按终端打印的地址访问。也可以通过 `--port 4311` 固定其他端口。CLI 提示语言可由 `--display-locale en` 切换；Vite 开发代理仍指向 API 的 `4310` 端口。

监听主机通过 `--host` 配置，缺省为 `127.0.0.1`；支持 IPv4、IPv6 和可解析的主机名。例如：

```bash
bun run workbench -- --host 0.0.0.0 --port 0
# 局域网客户端使用这台机器的实际 IP 和终端打印的端口访问。
```

`0.0.0.0`／`::` 是监听通配地址。工作台包含配置编辑、认证读取和对局启动能力，当前没有用户登录体系；网络绑定应限于受信任网络。请求 Host 白名单与同源写入检查继续生效。

目录参数相对于根命令的当前工作目录；默认指向仓库的 `configs/` 和 `record/`。工作台启动登记放在忽略的 `.workbench/runs/`，可通过 `--state-dir` 改变这个私有状态根，不作为游戏录制或公开发布材料。开发时同时使用 API 与 Vite，浏览器打开 Vite 的 5174 端口。

公共入口遵循[统一路径解析要求](../architecture/workbench.md#wb-path-01统一路径解析)：显式相对参数按调用目录，缺省数据目录按项目根，配置内相对文件引用按配置所在目录；内部切换工具运行目录不改变这些含义。

## 选择、创建与修改

- **快速开始一局**：首页选择一个已保存游戏，核对板子、人数与默认／覆盖 Agent，点击“开始对局”。启动检查读取实际保存文件，草稿不会被悄悄用作启动配置；成功后进入本局终端。
- **查看已有配置**：板子和游戏页先显示本地列表。选择项目查看摘要，点击“编辑”后才进入表单／源码草稿；“复制为新配置”要求新 ID，不覆盖原文件。
- **新建板子**：点击“新建板子”，从独立标记的示例模板选择人数与角色，再填写 ID、阅读规则并调整。即使模板已复制为同 ID 的本地板子，原始示例仍可选；修改本地规则不会改变模板来源。支持的字段来自实际运行 schema；复杂结构和原生扩展仍可在 JSON 编辑，保存不会丢弃未展示字段。
- **配置 Agent**：Agent 页先显示已有项，可查看和编辑。新增时选择 LLM、Pi 或 ACP 平台、认证方式、模型与思考等级，可复用匹配的已有连接；连接参数与逐玩家模型选项分开。
- **新建游戏**：没有 Agent 时显示明确提示及配置入口，保存和启动均不可用。点击“创建游戏”，选择板子、已配置默认 Agent，按需添加角色或座位 Agent／姓名／自定义指令。检查并保存后进入详情，再启动真实对局。取消不写文件，再次新建获得独立草稿。

板子和游戏的配置 ID 是文件名，以小写英文字母开头，只接受小写字母、数字、下划线和短横线，不含 `.json`。输入框给出中英文说明；ID 无效时就地提示，不能检查或保存。新建和编辑都使用“保存”按钮，长规则表单的顶部操作栏随滚动保持可见。

表单和 JSON 显示同一对象及保存状态；目录刷新、旧请求迟到和保存响应不能重置正在编辑的新内容。保存期间新增的输入继续保留为未保存草稿；“重新读取”和“显示密钥”在读取期间暂时锁定输入，显示密钥还会核对文件版本。旧版本的配置检查响应不会给较新的草稿显示“检查通过”。外部修改发生摘要冲突时，页面保留当前草稿并要求重新读取／合并。

同一局可混用 LLM、Pi 和 ACP：选择已保存的默认 Agent，再按角色或座位选择其它 Agent；座位覆盖优先于角色覆盖，其次是本局默认与 runtime 默认。它们都通过相同的游戏行动工具接收校验，具体模型、认证和会话仍归各自后端。

名字缺省时仍只显示编号。附加指令沿用 Agent → 本局 → 角色 → 座位的 append／replace／clear 规则。

认证默认显示保留标记；未改标记保存时恢复同版本原值。校验与运行通过既有解析器在临时对象中读取环境，保存时 `${ENV_NAME}` 保持原占位符。明确显示密钥仅用于本机编辑；目录、运行列表和模型目录不返回认证。Codex 订阅按钮在服务端读取固定的 `~/.codex/auth.json`，不向浏览器返回令牌。

新增连接与 Agent 是两份独立文件。如果后续保存或订阅认证导入失败，已经创建的连接保留，页面显示具体阶段并可复用、修正或重试认证；新建 Codex 连接的导入失败后可在原向导继续重试；复用已有认证连接时不改写它的认证。外部编辑导致摘要冲突时，保存拒绝且当前草稿保留；重新读取后合并。该协议不锁住任意外部编辑器。

### 测试连接

新增 Agent 保存成功后，以及已有 Agent 的编辑页，均可显式点击“测试连接”。未保存修改时按钮不可用，测试只读取磁盘中的配置；可能消耗所选模型的额度，不在打开页面或保存时自动执行。

- LLM：通过现有 AI SDK 发送一次短文本请求，关闭本次 SDK 重试。
- Pi：使用现有内存模型／认证容器和空工具会话，关闭本次自动重试与缓存预热。
- ACP：按保存的命令、环境和会话选项启动进程，完成初始化与短回复；不挂载游戏 MCP，默认使用独立临时工作区，显式配置的 cwd 仍按声明文件解析。

请求限时 30 秒，结束或取消后关闭会话及进程，再清理本次创建的临时目录；不创建对局或录制。页面只展示后端、阶段、耗时、HTTP 状态及脱敏诊断，不返回模型原文、认证或原始错误正文。测试成功表示短请求可往返，真实对局的游戏工具与配置完整性仍在开局时检查。

### Pi 内置平台与认证

Pi 的内置 OpenAI、Anthropic、智谱和 Kimi 平台自带 API 类型、默认地址与模型目录；界面的灰色地址是缺省提示，不会自动写成覆盖配置。仅在使用代理、自建网关或确实要改变连接地址时填写 `baseUrl`，此时才写入原生 `models.providers`。模型与思考等级保存在 Agent options；同类连接可复用，不能把不同平台或认证模式误认为同一个连接。

API Key 与订阅 OAuth 分别选择：Codex 订阅显式从本机 Codex 认证导入，API Key 可直接填写或保留环境占位符。原生字段及多平台目录语义以 [Pi models.json 官方说明](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/models.md)为准；AWA 保持 Pi 原生配置对象，在内存中使用会话，不启用默认文件读写工具。

## 删除配置和记录

已有游戏、板子和对局列表／详情均有删除入口，确认对话框明确对象与范围：

- 删除游戏配置只移除选定的 `games/<id>.json`，保留板子、Agent 和既有对局。
- 板子仍被已保存游戏引用时禁止删除，并展示引用；部分游戏文件无法读取时也不会猜测“无引用”。示例模板和本地板子属于不同来源。
- 对局先停止并等待保存结束。进程活动或无法确认实例退出时不能删除；删除范围是该 session 的录制、日志和相应工作台登记，保留其他 session 和 `output/` 成片。

删除使用当前文件／记录的 revision 检查。外部改动、引用冲突、过期状态或重复删除返回明确错误；取消不产生文件变化，成功后刷新列表与当前选择。

## 运行与回放

每局使用独立 CLI 进程。终端页是只读 ANSI 输出，没有交互式 shell。刷新页面会补读本局日志。进程退出、对局是否打完、核心录制是否发布分别显示。录制目录中的 `runtime.json` 提供实例身份、心跳与运行状态，`completion.json` 提供核心文件发布回执；胜负来自已录制的终局事实。过期心跳只表示状态需要重新核对，不表示进程已经停止。“核心录制完整”表示 manifest、replay 及启用时的 reproduction 已发布；可选玩家档案／摘要与严格复现验证各有独立结果。

“停止并保存”通过本局私有控制端口取消行动，关闭 Agent 后保存已有记录。关闭工作台服务不会主动停止已经启动的游戏。外部终端启动的新 CLI 也会在相同 record 根登记、保存日志并被工作台发现；历史无登记的记录显示为历史录制，不伪造活性或完整性证明。

停止与删除授权核对进程启动身份及系统启动 ID：Linux 使用 `/proc`，Windows 使用固定 PowerShell 查询，已有定向 CI 验证。无法确认实例身份时保持 lost／interrupted 或未知状态，不仅凭 PID 或过期心跳提供停止／删除操作。macOS 已实现 `ps`／`sysctl` 只读身份查询，尚无与 Windows／Linux 同级的 CI 证据。

已有 replay 文件的对局可打开现有复盘界面，格式问题由播放器显示。God 回放仍为全知数据；切换席位不授予私有档案或改变事件可见性。私有玩家档案仍通过原播放器的显式导入操作读取。

## 独立入口与平台

```bash
# 仓库根：独立后端对局
bun run run -- --game-config-name twelve_player_standard
# 仓库根：独立复盘页面
bun run dev:frontend
bun run replay:dev -- --input ./record/<session>/replay.json
# 独立应用目录命令；路径以 apps/game 为调用目录
bun run --cwd apps/game config:check --configs-dir ../../configs --game-config-name twelve_player_standard
```

本地工作台、Pi／LLM 对局和复盘使用跨平台 Bun API。Vite、TypeScript、ESLint、Prettier 与 Playwright CLI 都显式使用 Bun 执行，避免工具的 Node shebang 切换运行时。Linux 的 `bwrap` ACP 隔离脚本不适用于 Windows；不因工作台能在 Windows 启动就宣称该脚本具有 Windows 隔离能力。

## 开发与验证

```bash
bun run dev:workbench          # API，默认 4310
bun run dev:workbench-client   # Vite，默认 5174，代理到 4310
bun run check:workbench
bun run test:workbench         # 独立临时配置和合成 localhost 模型
bun run build:workbench
bun run --cwd apps/workbench test:e2e
```

浏览器测试需要与锁文件版本匹配的 Chromium，可先运行 `bun apps/workbench/node_modules/@playwright/test/cli.js install chromium`；也可用 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指向本机可执行文件。测试不调用真实模型、订阅认证或个人配置。

### 已执行的定向验收

本轮已验证配置列表与详情、连续新建、取消、保存／读取的异步保护、三类删除和引用冲突、被外部修改的游戏拒绝启动。空目录浏览器场景覆盖“自动空运行骨架 → GUI 添加首个 Pi Agent → 添加本机合成模型 Agent → 创建板子 → 创建游戏 → 重载与修改 → 真实 CLI 启动及复盘”；反例覆盖缺少 Agent 时禁止保存、非法 ID 提示和已有默认 Agent 的保留，并核对本地同 ID 的修改不会遮蔽原始规则模板。平台场景覆盖内置地址不写隐式 override、Codex 导入失败后重试、既有 Agent 修改与 Claude Code 隔离环境。

混合对局使用真实公共 CLI、LLM／Pi SDK 和 ACP 进程，连接本机合成服务完成六人两夜对局，以狼人全部出局自然结束，并发布可打开的复盘；该验收没有借用期限结束或回退行动制造终局。对应测试位于 `apps/workbench/tests/e2e/` 和 `apps/workbench/tests/integration/`。

完整回归继续由 GitHub CI 并行运行；定向测试通过不表示最新提交的全部 CI 已通过，应以该提交的 checks 最终结果为准。视频生产、结构化在线观战、多用户认证与游戏状态恢复不属于这一版的交付范围。
