# 视频美术与动效规范

本规范记录哥特主题的实现与制作约束。现已接入64种角色小纹章、原创材质道具、类型化视觉意图、局部阅读衬底及有限动效。规则以项目规则卡和结构化归档为准；能力复用视觉家族，不等于每种角色都有独立人物插画。

全量对应关系见 [视觉覆盖清单](../../frontend/design/visual-coverage.json)、[64 角色美术简报](../../frontend/design/role-art-briefs.json)；背景与中央阅读区的可交互构图研究见 [中央衬底研究](../../frontend/design/center-surface-study.html)。研究使用既有真实背景与道具，示意文字不属于真实对局，也不代表生产渲染器已改造。

## 范围与现状

审计基线为 `6b41efed`。代码闭合集合为 64 个 RoleId、217 类事件、98 个行动请求阶段、79 种工具、4 个 Phase 和 5 种 God fact。另有 206 个当前录制注册表中的已知 stage 字符串；归档 stage 本身开放，不能与 98 个请求阶段混为一谈。

公开示例有 104 个 board ID，其中 12 人 76 个、6 人 25 个、10 人 3 个。相同人数与角色配方有 75 组，其中 12 组存在多种政策；这不是官方的“75 种玩法”。board ID 可扩展，不能把 104 写成所有可能玩法的上限。

上述审计基线当时只有17类显式场景及5张图片。`visual-coverage.json` 保留该历史快照，不能当作当前完成率。当前 `visual-routes.ts` 显式登记217类事件和98种请求阶段，`visual-vocabulary.ts` 定义31个复用家族和86种事件模板，`visual-intent.ts` 只依据类型载荷生成报告、过程、参与者与目标。缺字段和未知事件保留中性记录，不从文字猜结果。哥特素材现为20张（2张环境、18张道具/报告叠层），详见素材manifest。

审计逐项列出 29 个逻辑视觉项。必须优先替换的包括：狼票与狼刀共用的折线狼头、盾牌成功勾、圆圈叉放逐、菱形十字占位、通用夜间播报眼睛、无蜡质感的可选“封蜡”，以及三处技能 Unicode 箭头。小型日月导航、LLM 徽记、金属角件、票型数据图和作者的矢量图层有实际用途，应统一材质或默认主题值，不应整体删除。

## 美术主轴

主体是中世纪村落、哥特旧铁、磨损黄铜、冷雾与血蜡。骨白承担阅读，暗红承担攻击与危险，冷银承担信息与仪式，低饱和鼠尾草绿承担救治；形状与标签同时区分结果，不能仅靠红绿。

AI 元素放在 LLM 徽章、古镜刻度、星盘、细小齿轮和精密蚀刻中。大环境与主要道具仍是中世纪，不加入霓虹线路、悬浮科技屏或巨型机械背景。整体不做纸墨 UI；纸张只作为局部票笺、密函或契约道具。

材质统一使用左上冷光、右下阴影、低饱和反射。主道具在 1080p 画幅中通常 320–440px，参与者圆章 96–144px；身份纹章是小型金属浮雕，不能把简线徽记放大冒充主道具。狼爪采用暗红血色三道撕痕与狼形负空间，边缘少量湿润高光；不让血迹遮挡座次、身份、字幕或票数。

## 环境与中央空间

历史版本使用接近不透明的整块中央底板，遮住环境。当前舞台骨架透明，按发言、技能、票型、通知分别承托内容；普通通知图标与正文作为紧凑组居中，不为不存在的动作预留大片空白。

默认 stage 改为透明的布局与裁剪骨架，保留坐标、镜头和作者图层契约。取消包围空区域的大金属盒；标题铭牌、阅读区、票图与小型结果牌分别按需要承托。

| 场景           | 环境与内容安排                                               | 初始衬底参数与面积预算                                                                             |
| -------------- | ------------------------------------------------------------ | -------------------------------------------------------------------------------------------------- |
| 发言           | 上方露出环境，正文位于中央偏下；署名、正文、作者说明各自明确 | 局部暗色 `#081219`，alpha 0.76–0.88，骨白字；通常占 stage 35–60%，上限 65%，同镜头按最大页固定高度 |
| 技能           | 道具、施法者与目标直接位于环境；只在道具后给低对比径向暗衬   | 不用整块板；结果下方 alpha 0.80–0.90 的小衬条，面积通常不超过 stage 22%                            |
| 投票           | 票型紧凑排成票笺矩阵或分组票条，保留四周环境                 | 仅图表占据的区域用 alpha 0.88–0.94 衬底；不画整屏投票大厅背景                                      |
| 上帝播报       | 1–3 行紧凑说明，旁边为中性印记或实际机制徽章                 | 文字条局部 alpha 0.80–0.90；无相关机制时不用眼睛或狼头                                             |
| 黎明与生命结算 | 出局席位并列，原因在证据允许时附注；环境自然露出             | 不绘制重复的大牌；生命提交与原因文字各有明确来源                                                   |
| 阶段与终章     | 小型昼夜/选举/终局铭牌，赢家分组清楚                         | 铭牌局部衬，环境大面积可见；胜利不是统一死亡叉                                                     |

参数是制作初值，实际字底对比才是验收依据。白天保留冷灰雾层、屋顶与地面，夜晚保留蓝黑雾、月光和远处微弱血色；两者默认同用骨白字与局部暗衬，避免日夜切换后突然出现一整张白纸。浅色阅读面作为显式可选模板，minimal 主题仍可使用自己的白色局部底。

字区背后限制高频石纹、树枝、月亮与强高光。环境资产应登记主体位置与 HUD 安全区；月亮、屋顶等识别点避开常驻名册，必要时选定固定裁切，不能在阅读中自动移动背景。正常正文的最差字底对比目标至少 4.5:1，大号标题至少 3:1；不能只测平均背景色。优先提高局部衬底、改变局部渐变或布局，再使用细阴影；禁止厚描边与满屏黑罩来补救。字幕阅读期背景静止，正文范围没有粒子。技能落点可短暂出现雾、血痕或碎屑，但持续装饰不跨越阅读安全区。

空间留白有职责：保留道具动作、场景深度与视觉休息；空的姓名/模型栏继续自适应回收。不能因为中央透出背景就把字幕铺满，也不能给隐藏信息保留空框。

## 字体与文字层级

标题使用现有 Noto Serif SC 方向的衬线体，正文与票型使用 Noto Sans SC 方向的无衬线体。长发言不再因哥特主题强制使用衬线体。拉丁模型名用清晰的无衬线体，只有必要的技术短码使用等宽体；座次与票数使用等宽数字特性，不把整段中文设成等宽。

字号均为 1920×1080 输出像素，720p 等比缩为 2/3；不能把现有组件的逻辑字号直接当成输出像素。章节标题 56，主标题 42–46，场景标题 40，默认发言正文中文 26、英文 24，技能结果与上帝公告正文中文 32、英文 30；两者使用独立主题 token。名册姓名 28，身份 24–28，模型/次要信息 22–24，非关键辅助文字 22。短文不自动放大，48px 正文保留为显式大字选项。长文保留完整原话并优先利用可用阅读宽高，超出后连续滚动，不因内容过长继续缩小字号。

正文行高 1.40–1.48，正文槽最大 1280px，并受两侧名册实际占宽约束。发言卡按内容居中，最高使用约八成舞台高度，短播报收紧衬底。保护角色短词、座次、模型标签和标点边界；超长无空格内容仍允许断行，不能靠nowrap裁掉原话。强调仅来自作者明确范围或结构化事实，不对玩家原话自动做阵营推断。

座次、姓名、身份、模型分别排版，两列位置真正镜像，文字保持正向。姓名缺省时不制造空名称；身份、阵营、生命、警徽与临时能力分别展示。显式LLM/素材头像保留，缺省auto头像使用当前许可角色的主题徽记；未知身份使用中性材质章，不能读取未来底牌。显式neutral、隐藏头像和旧计划保持原意。出局后整卡灰化，金属章斜向覆盖头像；右列旋转方向镜像，不能遮座次。

本地字体须固定来源、版本、字重与 SHA256，保留许可证。官方 Noto CJK 的 [Sans 许可](https://github.com/notofonts/noto-cjk/blob/main/Sans/LICENSE)与 [Serif 许可](https://github.com/notofonts/noto-cjk/blob/main/Serif/LICENSE)均为 OFL 1.1；实际交付文件须核对内部 family 名称与 SC 命名，不只根据文件名登记。现有 `VideoFonts` 已支持本地字体快照和等待加载；项目已内置完整SC字库 Noto Sans SC 2.004 / Noto Serif SC 2.003，许可证、上游固定提交及压缩文件SHA256见 `frontend/src/themes/fonts`。网页与视频使用相同字节但各自注册别名；项目同family字体可显式覆盖内置字体。正式导出不得悄悄使用缺字 fallback，不得将系统字体直接复制进仓库。

新广播自动编排默认保留全文一页，溢出时使用“首屏停留→匀速上移→末屏停留”。阅读时钟在纯数据层统一计算，浏览器只在固定字体就绪后测量真实溢出像素；暂停、倒看和直接seek不累积scrollTop。正文与播放中的卡片尺寸不逐句跳变。作者显式duration/captionPageFrames、hold和旧计划保留原分页约定，不能静默重写导演时钟。减少动效取消装饰运动，必要的原文阅读滚动仍保留。未来TTS复用同一god/player来源及时间接口，本轮不接语音服务。

## 边框、徽章与连接

框体承担层级，不承担装饰数量。固定名册使用薄旧铁框、极小黄铜角件；当前发言者可有一次边光后停稳。中央阅读衬不再套多重全框，标题用短铭牌和两端线；结果仅一枚小印章。角件、内线、阴影最多两层，避免每个框内部再加一个框。

1080p 主边线约 1.5–2px，主动高亮 2.5–3px，小角件 12–20px；主铭牌可以更厚，但不挤压正文。描边随输出缩放，亚像素线需在 720p 检查。转角以轻微倒角或 2–4px 小圆角为主，保持同一金属体系，不混入大型胶囊和发光圆盘。

技能连接使用绑定真实席位/道具锚点的路径，统一旧金属/冷银轨迹；通常 请求/资料线 1.5–2px、效果主线 2–3px、主动作轨迹可用 3–5px，端点 16–24px。虚线表示选择或待确认，实线表示契约明确证明的实际作用路径，断裂表示撤销，回流表示明确反射。箭头端点与动作含义一致，查验的信息回传和攻击方向分别设计。禁止用一个 Unicode 箭头排在图标下方替代路径，也不能据此改变原始请求目标与实际落点。

网页共用色板、字体、角色徽记、状态章和图标语义，工具栏仍维持信息工具的密度；不把视频的雾景、大道具、血迹和镜头震动搬进每个网页卡片。网页主题选择与视频项目继续独立，minimal 与旧椭圆布局保留兼容。

## 五层视觉契约与复用

1. **身份层**：64 个 RoleId 显式登记纹章简报与中文名，独立于玩家头像/姓名/模型。名义阵营不代表当前阵营、查验标签或获胜归属。
2. **能力层**：按古镜、药瓶、狼爪、决斗、枪、盾、契约等道具复用。借用枪不改变真实角色；共享道具不表示共享权限。
3. **过程层**：选择、提交/支付、发动、取消/被封、阻挡、失效/到期、解决分别表达，由有对应字段的记录驱动。
4. **阶段层**：4 个 Phase 提供大环境；98 个请求窗口和已知录制 stage 提供明确子标题/家族映射。不能给每个夜间节点都放古镜。
5. **结果层**：查验报告、资源、关系状态、生命提交、胜利各自呈现。技能发动、实际阻挡、目标死亡属于不同事实。

制作可按九大视觉组复用，角色简报仍逐项登记：攻击与决斗、查验与反馈、炼药与保护、关系与牵连、映射/反射/增强、授予/复制/转化、动物/被动/延迟、发言与表达、选举与终章。清单另显式登记 31 个细分设计家族、86 个事件模板，不按 217 类事件各生成一张大图，也不能以“大组相同”为由省掉结果分支。

| 狼队           | 单人刀票是选择票笺；权威刀口才出现血狼爪；撤刀为断痕/熄灭；真正出局等生命提交                    |

## 动作节拍

所有时刻由源帧决定，一个 owner 负责对象变换。以下数值以 30fps 为基准；其它 fps 的自动预设由编译器统一换算和取整，作者显式帧值保持其项目帧率语义。移除 `sin(frame / 24) * 3` 的永久浮动及内外重复缩放；不以 CSS 时钟、随机数、音频进度或上一渲染帧决定画面。跳到任意一帧必须得到同一结果。

以 30fps 的普通技能为制作起点：0–7 帧建立参与者与标题，8–23 帧发动/行进，24 帧命中或报告揭晓，24–35 帧短反馈，36–39 帧落定，40 帧起稳定阅读，至少再留 90 帧或更长的实际阅读预算。按实际文本、单局脚本和未来音轨加长稳定段；快速记录使用更短预设，不能机械给 217 类事件都播放四秒。第一页从 impact 可见，但应保留 settled 后足额的静止读时：例如 impact=24、settled=40、首结果页阅读预算 180 帧时，首张结果页在第 220 帧才翻页；后续页各给完整阅读预算。显式作者分页仍优先。

“第 24 帧揭晓”是预设例子，真正揭晓必须与 `scene.cues`、原 seq / fact seq 和状态 cue 一起编译。改变预设需同步事实游标，不能只把图像提早。自动镜头时长不足时，编译器可延长镜头或选择明确的短版；作者显式时长保持优先，非法或无法表达的 cue 应报错，不能偷偷倒序或静默加长。

狼爪行进 8–16 帧、冲击 6–10 帧、余痕 12–20 帧采用可重叠包络，标准预设最迟第 40 帧全部停止；具名长版必须另行编译 settled，不能由 renderer 私自续播。只在命中周围允许短促震动，幅度不超过 2–3px，2–4 帧衰减，不震字幕与名册。默认无自动推拉；具名 focusPush 或作者明确安排时才对单一焦点一次推近，通常不超过 1.06–1.10，且不能与道具重复 scale。作者已有 shake/camera 时预设不叠加第二份震动；没有目的时不漂移、不拉远再拉近。结果阅读段无呼吸缩放、旋转或反复闪烁。

发言者边框短亮一次后常亮；正文直接完整出现，翻页短淡入。票型按目标分组一次归位，再稳定展示结论；不逐票重复报同一目标。多枪、多链式死亡、觉醒决斗逐链结算，不能为紧凑而并成同时杀死。反过来，同一已提交 wave 的连续生命批次只有在同一事实前缀且明确共享 `life_committed.waveId` 时同时生效。该可选正整数来自后端真实死亡单元身份；旧档无编号、不同编号或跨事件前缀时保守分别呈现，不能按相同afterSeq猜同波，也不能为表演路径顺序伪造死亡先后。host 始终使用完整的事件/事实双游标前缀，不能只挑当前展示的 fact；晚 impact 的第一页仍须完整可达。

减少动效模式保留同一揭晓与文字信息，取消路径位移、震动、闪光和粒子，改用静态分步或短淡入。自动时长将来可取阅读预算与已准备音轨结束加尾留的较大值，显式作者时长仍按项目约束校验。TTS 继续只保留 god/player 说话者、发声起止、结果 cue 与阅读停留接口；此规范不接入语音服务，也不让未来配音重算游戏事实。

## 代码落点与素材契约

现有链路为契约 reader → 唯一复盘投影 → `semantic-scenes` → 视频编译/字幕/状态 cue → `VideoFrameView` → 主题宿主/图层。改造应扩展现有职责，避免另造一套规则或重复视频编译器。

`VideoScene.visual` 已提供 camp/role/combined/pair/range/unknown 的报告联合，以及过程、原施法者、请求/实际目标、接收者、明确空落点、工具、药物、保护、决斗、生命与胜利来源。旧 `action.result` 仍供兼容展示，选材不解析该本地化字符串。role-only及pair非狼不能借用好人印记；普通骑士not_wolf也不等于好人。明确gun/claw/弩等工具优先于家族通用道具，不额外披露角色来源。

事实/生命仍由投影与 state cue 拥有。视觉意图保存 family、process、reportedOutcome、anchors、revealFrame 等展示语义；施法者、请求目标、实际受术者、反馈接收者与 God 旁白分字段，避免反射/借用/秘密行动误署名。视觉意图不能拥有“判死”“自动胜负”权限。God fact 与事件的 seq 空间保持独立，旧档缺字段只中性降级。公开枪击不披露来源时不得据画面推断猎人。

主题侧增加可序列化的 typography、surface、frame、connector、effect 与 motion token，主宿主消费 token；React 实现仍通过已有插槽 bundle 注册。缺少某主题专属效果时退到该主题的中性说明/文本，不跳回哥特大眼睛。作者显式颜色、路径、camera、layers、scene/body 覆盖保持优先，主题豁免必须具名、可序列化且不修改事实。

素材登记至少包含 `assetId / role-or-family / variant / status / file / dimensions / alpha / safeArea / lightDirection / provenance / checksum`。`status` 明确区分 brief、generated、reviewed、integrated、verified；只有 integrated/verified 能计入默认实现覆盖。纹章、主道具、结果叠层、轨迹、环境分资产，不生成带字截图或预烘焙狼身份答案的古镜。文字、票数和座次始终由代码排版。

可复用的制作依赖顺序为：先建立带类型的视觉意图与默认中性模板；再统一局部衬底/文字/框体/动画 owner；再接入狼爪、查验结果、保护和决斗等高频家族；最后按全量清单补齐特殊机制。每个家族完成静帧、过程和反向跳转验收后再扩量，不能把未经真实渲染的概念图当完成。

## 验收

64 RoleId、217 event、98 action stage、79 tool 与源码集合必须等值；开放的 board/stage 保留 unknown 分支。每项至少有明确模板/家族或有理由的中性记录，不要求为每个通知生成一张大图。角色资料的 implemented/verified 交付状态不能当作美术已完成状态。

有实际事件/事实的视觉家族须覆盖真实1920×1080定帧，静态通知不制造虚假动作；身份/胜利专用家族通过名册与终局验证。高频动作另导完整建立到停稳的MP4并抽帧核查；关键结果在 t−1/t/t+1 检查并反向 seek。重点成对用例：狼票/落刀/撤刀/生命，查验 good/wolf/role/combined/pair/未知，骑士成败与觉醒多链，未知/零/多份库存，同守同救与另一死因，复制/公共枪来源，映射原目标与实际落点，白猫延迟，警长权重/乌鸦/弃权/平票/PK/重投，个人与阵营胜利。

跨场景检查 6/12 席、中文/英文、长名/匿名/无模型、长正文、两侧资料缺省、day/night、720/1080、预览/PNG/MP4、hold/跳剪/脚本解说/强调。名册、文字和路径共享真实布局坐标；不遮座次、不裁角色、不越读区；字体字节一致，文件解码成功，读区实测对比达标。

概念与真实输出的差异应逐项比对：构图比例、背景露出、道具占比、材质光线、字体、边框密度、对齐、揭晓顺序和稳定阅读时间。只有定帧好看不够，只有数据正确也不够；最终验收同时要求真实渲染的连续过程和事实准确。
