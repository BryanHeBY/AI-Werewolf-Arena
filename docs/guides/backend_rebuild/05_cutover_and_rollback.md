# backend cutover and rollback

## 1. 当前代码详细文档

本文定义 V3 后端重构完成后的切换策略，避免“一次性替换”导致高风险事故。

切换策略（建议）：

1. 双栈并行：保留 V2 运行路径，新增 V3 独立入口。
2. 灰度放量：先内部压测，再小流量测试，再全量切换。
3. 指标观测：错误率、回合中断率、规则冲突率、平均响应延迟。

切换前检查清单：

1. MVP 关键规则回归全部通过。
2. 协议字段对齐验证通过。
3. 关键日志具备可追踪性（阶段、动作、结算、胜负判定）。
4. 回滚脚本或开关已验证可用。

回滚策略：

1. 触发条件：规则错误、流程中断、严重协议不兼容。
2. 回滚动作：切回 V2 服务入口，冻结 V3 新流量。
3. 数据处理：保留失败场景日志用于复盘，不做静默丢弃。
4. 修复流程：定位 -> 热修 -> 小流量复测 -> 再次灰度。
