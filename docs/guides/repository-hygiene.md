# 仓库隐私与发布材料

## 可以提交的内容

源码、规则、公开配置模板和合成测试材料可以纳入 Git。`configs.example/` 中的认证只用环境变量引用或明确占位值；真实 API key 可以保存在本地 `configs/`，该目录不参与版本控制。配置检查使用脱敏输出，不能把检查前的原始配置贴进文档或日志。

个人认证、OAuth access／refresh token、私钥、账户导出、本地配置和真实模型运行记录不提交。`.gitignore` 只阻止新增未跟踪文件，不能删除已经提交的内容，也不构成运行时访问控制。

## 示例与测试归档

路径使用仓库相对位置、临时目录或 `/ABS/PATH/` 占位，不把开发者 home、用户名或本机工作目录写进公开示例。测试使用合成凭据，并以名称、注释或本地假服务明确其用途；不得复制个人认证作为夹具。

God 回放、玩家私有档案和严格复现 Tape 分别审查。公开教学 God 档应明确其全知视角；未经检查的模型原文、人格、日志和 Tape 不作为公开附件发布。已经登记的冻结夹具保持原字节；需要脱敏时先处理来源，再生成新的明确版本，不能改旧指纹冒充兼容。

## 检查提交与历史

提交前检查实际暂存文件和内容，尤其是认证字段、URL 用户信息／查询参数、个人路径及运行输出。可以先用只列文件名的命令缩小范围：

```bash
git diff --cached --name-only
git ls-files -- .env configs record auth.json credentials.json '*.pem' '*.key' '*.p12' '*.pfx'
git log --all --oneline -- .env configs config configs.example '*auth*.json' '*.pem' '*.key'
```

内容扫描在本机进行，结果只记录位置、类别和必要的不可逆指纹，不回显候选凭据，也不通过调用真实 API 验证密钥。明确区分测试哨兵、占位值和真实凭据；抽样未发现问题不表示所有历史或不可达对象均无泄漏。

若确认真实凭据进入 Git，先撤销或轮换，再移除当前版本中的值。普通删除提交仍保留旧历史；改写历史和强制推送需按实际影响另行处理，快进合并不会清除历史内容。
