# 无人值守 TODO 循环准则

## 1. 当前代码详细文档

本文是本项目的默认执行准则，适用于后端与前端开发活动。

目标：

1. 所有开发任务必须显式写入 `docs`（优先写入 `docs/guides/**` 对应入口）。
2. 每个任务必须有对应验收项，且验收项可由命令或测试结果直接判定。
3. 进入无人值守模式后，按固定循环自动推进，直到 TODO 清零或遇到严重阻塞。

任务存放位置约定：

1. 架构与分阶段任务：`docs/guides/backend_rebuild/*.md`
2. 模块开发任务：`docs/guides/drivers/*.md`
3. 活动执行任务（开发/测试/发布）：`docs/guides/activities/*.md`
4. 规则与白皮书约束：`docs/specs/*.md`

## 2. 运行约束（长期生效）

- `R01` 新增任何 TODO 时，必须在同文档同步新增对应验收项与校验命令/测试文件。
- `R02` 无人值守执行严格遵守“单文档 + 单条 TODO”闭环，任何时刻只允许推进 1 条 TODO。
- `R03` TODO 勾选完成前，必须先执行对应验收项并拿到通过证据（命令输出/测试通过记录）。
- `R04` 每轮结束自动定位下一条未完成 TODO，继续执行循环。
- `R05` 仅允许两种停机原因：`all_done`（全部清零）或 `blocked`（严重阻塞并附细节）。
- `R06` 禁止写入当前执行者无法独立完成的任务（如双人评审、组织审批、外部平台流程）。
- `R07` 禁止使用脚本或批量替换一次性勾选多条 TODO/验收项。
- `R08` 每次只允许勾选“1 条 TODO + 其直接对应验收项”，不得跨文档连带勾选。
- `R09` 若发现未验收先勾选，必须立即撤销该勾选并补验收后重走流程。
- `R10` 若出现批量误勾选，必须先全量取消勾选，再逐条验收、逐条恢复。
- `R11` 勾选前必须同时核对功能代码与测试代码：功能实现需完整覆盖需求，测试需准确覆盖对应验收目标，二者缺一不可。
- `R12` 涉及测试验收的条目，必须在文档中写明精确测试文件路径或可执行命令。
- `R13` 若验收项缺少测试文件/命令，必须先补全文档，再允许执行该条 TODO。
- `R14` 每条勾选必须附带证据：代码检查结论 + 测试命令结果。
- `R15` 涉及可执行流程（如 `run:v3:*`）的条目，必须额外核对“流程完整性”：日志中需有阶段推进证据（如 `night -> day -> voting`）和终局证据（`game_over`、`winner`、`reason`），否则禁止勾选完成。
- `R16` 每次测试运行后必须人工检查完整输出；禁止只看退出码。
- `R17` 一旦在测试/运行输出中发现 `error`，必须先在 `docs/guides/activities/development_activity_driver.md` 新增对应 TODO（含复现命令与验收命令），再进入修复流程。

## 3. 强制执行流程（逐条循环）

1. 在单个文档中选择下一条未完成 TODO。
2. 完成该 TODO 对应代码或文档变更。
3. 执行该 TODO 映射的验收命令/测试。
4. 复核代码实现完整性（边界条件、流程联动、回归影响）。
5. 验收通过后，仅勾选该 TODO 与对应验收项。
6. 记录证据（命令、测试文件、关键结果），再进入下一条。

## 4. 合规判定

- `C01` 任意 TODO 可在同文档找到对应验收项与证据。
- `C02` 变更历史中不出现单次批量清空 TODO。
- `C03` 每条已完成 TODO 都有可复现校验记录。
- `C04` 执行日志可串联连续推进链路（上一条 -> 下一条）。
- `C05` 停止时必须给出 `all_done` 或 `blocked` 标记及原因。
- `C06` 任意任务可由当前执行者在本仓库内独立完成并验证。
