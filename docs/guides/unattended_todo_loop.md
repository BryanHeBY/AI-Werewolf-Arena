# 无人值守 TODO 循环准则

## 1. 当前代码详细文档

本文是本项目的默认执行准则，适用于后端与前端开发活动。

目标：

1. 所有开发任务必须显式写入 `docs`（优先写入 `docs/guides/**` 对应入口）。
2. 每个任务必须有对应验收项，且验收项可由命令或测试结果直接判定。
3. 进入无人值守模式后，按固定循环自动推进，直到 TODO 清零或遇到严重阻塞。

任务存放位置约定：

1. 架构与分阶段任务：`docs/guides/backend_rebuild/*.md`
2. 模块开发任务：`docs/guides/drivers/*.md`
3. 活动执行任务（开发/测试/发布）：`docs/guides/activities/*.md`
4. 规则与白皮书约束：`docs/specs/*.md`

## 2. 运行约束（长期生效）

- `R01` 新增任何 TODO 时，必须在同文档同步新增对应验收项与校验命令/测试文件。
- `R02` 无人值守执行严格遵守“单文档 + 单条 TODO”闭环，禁止批量勾选。
- `R03` 每完成一条 TODO 必须先校验，校验通过后才能更新状态。
- `R04` 每轮结束自动定位下一条未完成 TODO，继续执行循环。
- `R05` 仅允许两种停机原因：`all_done`（全部清零）或 `blocked`（严重阻塞并附细节）。
- `R06` 禁止写入当前执行者无法独立完成的任务（如双人评审、组织审批、外部平台流程）。

## 3. 合规判定

- `C01` 任意 TODO 可在同文档找到对应验收项与证据。
- `C02` 变更历史中不出现单次批量清空 TODO。
- `C03` 每条已完成 TODO 都有可复现校验记录。
- `C04` 执行日志可串联连续推进链路（上一条 -> 下一条）。
- `C05` 停止时必须给出 `all_done` 或 `blocked` 标记及原因。
- `C06` 任意任务可由当前执行者在本仓库内独立完成并验证。
