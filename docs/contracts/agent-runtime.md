# Agent回合预算、取消与资源

## 公开玩家名册

LLM／ACP／Pi 共用 `PlayerPromptPolicy`：系统提示提供全体玩家的 `{ id, seat, name? }` JSON 名册，观察 DTO 的 `players` 提供同一公开资料。未取名的玩家不附 `name`；自己的私有身份与队友知识仍独立投影。名册不携带隐藏角色、阵营、人格提示或模型接入配置，不因死亡删去玩家或附带尚未公布的生命状态。

玩家可以用编号或昵称交流，工具行动始终使用 ID。名册由身份组件显式列举字段，捕获后与 World 脱离；三种传输不能自行补全其他玩家的私有信息。

## 共同玩家提示

LLM／ACP／Pi 沿用同一 `PlayerPromptPolicy`，说明本局规则、本人获准知道的信息、当前行动与人设偏好。规则和协议是行动边界；发言结构、站边、诈身份、隐瞒或分享自己的查验、试探与调整策略仍由玩家决定。自然牌桌口吻和人设是表达偏好，不要求固定句式、固定打法或每次发言重复免责声明。

胜利目标依本局实际个人胜利规则解释，真实阵营不必等于个人胜利归属。混血、孤独少女和情侣等说明可以公开条件规则，不能为“讲清目标”而泄漏玩家尚未知晓的秘密分组或伴侣阵营。

消息理解区分上帝公开公告、个人技能反馈和玩家陈述。发言中可以自然使用“上帝报了”“我昨晚验了”等表达；来源区分服务于玩家自己的判断，不禁止战术谎言。事件名、工具参数和回合 ID 保留在提交协议中，不要求玩家把技术措辞念给全场。工具受理、候选接受与真正结算仍分别解释。

阶段提示组合彼此独立的信息：典狱长强制目标不遮掉女巫获准知道的刀口。目标候选遵循本轮绑定能力的目标政策与激活来源；普通复制、幸运儿和黑市实例不能互相借用自验或历史目标规则。候选文字不授予提交权限，最终仍由领域机制复验。

普通守护与解药同时命中同一目标时，两项普通保护抵消；梦、机械及觉醒保护仍按各自规则独立结算。警长选民范围按本局选举政策和轮次说明。公开发言、狼聊、伴侣私聊和调毒协商分别说明受众，识别交流轮次不扩大消息权限。

必需窗口按原约束提交；可选窗口可直接结束而不发动技能。非法提交仍按反馈处理，不能把非法行动自动算成合法跳过，也不能以重试提示要求玩家发动可选技能。自爆仍使用原二次确认流程。

## LLM 对话窗口与公共知识

LLM 会话的对话历史继续按 `maxPromptEvents` 限制发送窗口，另按玩家独立累计已收到公告中的出局、公开翻牌和最后公布的警徽归属。每轮提示附上紧凑摘要，即使旧消息被截断或后续仅提供事件增量，这些已知公告也不会消失。

摘要只读取玩家可见事件，不读取真实 Alive、隐藏身份或全局事件；进入白天、狼刀投票、玩家自报、私有查验与落空枪击不被升级为公开结果。翻牌记录表示公告当时的身份，摘要不包含玩家全部私有知识。结构观察复用相同的公开死亡解释；Pi／ACP 仍由各自会话维护上下文，不增加宿主对话裁剪。

## 回合执行

LLM／Pi／ACP的选择只通过同一ActionRequest及完成端口交给领域。回合绝对deadline取请求期限与provider预算中更早者；排队、初始化、工具循环和required-action retry共用，不因重试刷新。

provider内scheduler按明确provider ID共享限额，跨provider独立；不宣称控制同密钥别名或多进程的全局并发。关闭拒新工作、取消并等待本owner操作和lease释放；逻辑active／queued归零不等于任意注入传输物理资源已释放。

ACP wire session ID只在连接内有意义，内部registry key绑定具体owner，模型turn_id仍原短ID。MCP无效turn先核owner／开放状态；原JSON返回引用和受众不被文档整理改成新schema。

ACP 更新先处理工具授权登记与审计缓冲，再调用同步显示回调。显示回调抛错后仍消费后续更新，错误在本轮结束时报告；协议消费失败立即向调用方传播，不等待可能依赖工具授权的 prompt。prompt 自身失败仍排空已到达更新，多个独立错误一并保留，结束回调不能覆盖原失败。

创建等待中止不抢占任意Promise，也不等于向已建立会话发送cancel。晚到创建仍归原owner回收；有界close超时要报告未完成，不能先清计数伪释放。内置session／MCP／进程的取消、graceful、TERM／KILL和清理保各自实际捕获失败范围，不能承诺任意getter／wait／destroy／unref throw都已被统一catch。

Fallback可在原政策下处理模型失败或预算耗尽；外来TimeoutError／AbortError不因名字相同就当自己的取消。body、关闭、最终保存／observer flush真实错误不能被晚回调覆盖或静默二次兜底。

`runtimeState`是逻辑只读摘要，不含密钥／命令／actor scope。真实HTTP abort、子孙进程退出与控制面端口回收需要本机传输证据；完全离线unit不证明物理资源。运行方式见[指南](../guides/run-locally.md)，完整验收范围见[验证指南](../guides/validation.md)。

## 日志开关

两个传输沿用同一运行配置，开关只控制终端观察，不改变提示构建、动作接收、私有记录和资源回收。

| 开关            | SDK                                  | ACP                                                    |
| --------------- | ------------------------------------ | ------------------------------------------------------ |
| `printLlmIo`    | 实际请求消息与原始模型响应           | 首次初始化系统提示、实际每轮提示与合并后的模型 message |
| `printThinking` | assistant 文字、工具调用及结果轨迹   | 合并后的 thought / message 与工具状态变化              |
| `trace`         | 请求、排队、接受、恢复及安全失败诊断 | 同样的生命周期标记与安全失败诊断                       |

两种详细开关同时关闭时，不显示提示、模型 message / thought 或工具轨迹；单独开启 IO 不显示 ACP thought 或工具状态。SDK 的 assistant 输出与 ACP message 同时属于 IO 和轨迹，因此任一相关开关开启即可显示。ACP IO 从流式观察器输出一次，逐 token 合并及工具状态去重保持；没有额外复制整份 response。`createAcpConsoleLogger` 三参数 API 仍沿用既有轨迹输出默认值，runner 明确传入本局两个 flags。

显示标签按独立 `displayLocale` 渲染，原提示、模型文本与参数保留原文。开启 `trace` 仍会显示已接受动作的 args，这是既有 SDK 语义；它不是无内容日志。配置认证/env不作为日志输入，失败仅输出安全诊断。日志属于本地运行观察，私有轮次保存也不受详细日志 flags 控制；不要把这些输出当作公开复盘。

直播事件由终端 presenter 统一补齐 `[live]` 及本地化分类标签。已有席位、行动或阶段专用标签原样保留；熊公告等复用展示文案的事件按现有分类补前缀。明确空受众的 God 事实标为“上帝私有”，公开熊公告仍标为“上帝”。该包装只改变终端行，不改共享回放标签、事件字段或私有信息筛选；被 `printPrivateEvents` 隐藏的技能通知仍保持隐藏。

`printPrivateEvents` 统一控制直播事件中的底牌、狼聊／刀票、守护／用药、查验与机制私有通知。开启后可在本地上帝视角看到子狐选择、真实封刀效果及每只狼的刀权；关闭后这些非公开事件不打印，熊公告等公开事实仍打印。子狐本人只知道自己的选择，每只狼只知道自己的刀权；真实命中效果不通过终端文案反馈给任何玩家。

该开关只筛选直播事件，不覆盖独立的 `printThinking`、`printLlmIo`、`trace`、`printAllEvents` 或聊天汇总。录制的 `replay.json` 按现有契约仍是完整 God 视角；不能把关闭私有直播理解为已生成公开观众版归档。

## 共同私有输出端口

三种传输的模型输出使用 `AgentOutputEvent`，受众固定为 `private`。传输只归一事实；终端和 Web 共用 `game-presentation` 的分类、可见开关及语义色调，模型原文保留原语言。ANSI 只在终端 sink 添加。显示开关不影响原生输出收集与玩家档案。

`PlayerOutputObserver` 只负责公共上下文与输出派发。SDK 的步骤转换和逐请求录制缓冲归 `LlmOutputRecorder`，Pi 的本轮增量归 `PiRoundRecording`，ACP 轨迹仍由原会话捕获；各自先保存录制事实再交显示消费者，不在公共 observer 中按传输种类建立隐式缓存。

机制专用的阶段提示与可配置政策文案放在各自 `features/<mechanism>/presentation.ts`。公共提示层按固定次序选择阶段说明、组合规则片段；状态投影继续在原捕获点读取。阶段 renderer 只接收当前请求和必要的语言／板子查询，不查询未披露的目标或重算行动许可。典狱长强制目标与女巫刀口由组合层显式结合；警长阶段区分“没有匹配”和“已匹配但无需补充”，避免后续机制覆盖合法空说明。

正常工具调用在终端仅于完成时打印一行，失败打印警告；`trace: true` 时才额外打印开始和中间状态。所有结构化消费者仍收到完整工具事实，Web 可展开调用与回执。ACP 工具状态按调用 ID 去重，文本分段继续保护 Unicode。

私有输出端口不承接 ACP 权限登记。显示异常仍由原传输隔离、在回合结束时报告，不能阻断后续 MCP 工具授权或覆盖原始失败。工具接受和归档中的 `accepted` 只表示候选接受。未附执行反馈的 `applied:false` 仍只表示选择；带版本化 `feedback` 的回执按下节区分即时结果、登记与未知状态。

## 工具执行反馈

保留原 `submit_action`、`get_game_schema`、`report_bug` 和所有行动 ID。`ActionTurn` 只做选择与预检；机制在原位置复验、消费资源、写状态并发表事件，反馈通道不再次执行行动。没有配置反馈政策的投票、狼聊、攻击、死亡技能等仍返回选择回执，后续按原时点结算。自爆的提案和二次确认保持原语义。

工具规格的 `executionFeedback` 声明结果类别及可引用的事件类型，属于具体机制贡献。当前接入：

| 类别     | 行动／机制                                                                       | 回执含义                                                                                   |
| -------- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------ |
| 即时结果 | 预言家、具体角色查验、纯白／狼巫查验、觉醒预言家双人查验                         | 返回规则产生的本人报告，包括伪装、反射、换位等规则处理后的结果；不能读取真实底牌来补全报告 |
| 获得知识 | 机械狼／觉醒隐狼学习、盗贼／变脸者选牌、混血归属                                 | 确认本人已经获知的身份或选择；学会技能不等于技能已激活，保留事件内的生效日次               |
| 行动登记 | 女巫用药／不用药、守卫、摄梦、魅惑、机械模式及复制技能、商人交易、榜样／仰慕选择 | 确认已发表的选择或资源操作，不提前声称最终保护、毒杀、反噬或阵营变化成功                   |

接收与执行状态分别说明：

| `status`      | `applied` | 含义                                                 |
| ------------- | --------- | ---------------------------------------------------- |
| `resolved`    | `true`    | 本人可获知的即时结果已经发表                         |
| `committed`   | `true`    | 对应行动或明确跳过已登记，最终效果仍待原阶段结算     |
| `not_applied` | `false`   | 机制明确发表无效／未执行事实                         |
| `unavailable` | `null`    | 没有可授权确认的结果；不能据此推断没有消耗或资源退还 |
| `interrupted` | `null`    | 机制执行中断，保留已发表的可见前缀；不能声称整体回滚 |

示例（结果字段保持既有领域事件含义）：

```json
{
  "ok": true,
  "accepted": true,
  "applied": true,
  "action": "check_identity",
  "status": "resolved",
  "feedback": {
    "version": 1,
    "events": [
      {
        "type": "seer_checked",
        "payload": {
          "actorId": 3,
          "targetId": 6,
          "isWerewolf": false,
          "result": { "kind": "camp", "camp": "good" }
        }
      }
    ]
  }
}
```

运行时用真实请求的弱关联通道分开候选交付和模型任务收尾：模型交出候选后等待反馈，领域继续执行；夜间步骤及开局身份设置作用域在下一次串行请求前或步骤结束时交回结果，并等待模型任务、会话操作与录制收尾。限流槽不因候选刚交出而提前释放。声明反馈的机制当前使用串行请求；误改为并发时明确报错并收口，避免与限流槽形成等待环。

该通道不参与 `RequestLease`／Tape 的完成布尔值，不改变其付款、撤权或失败前缀语义。只有注册的合法期限别名继承关联，相同 JSON 或相同玩家编号不产生关联。关闭和期限耗尽会唤醒工具等待；候选已交出后发生传输或展示错误，保留失败与记录，禁止再次重试／回退消耗资源。

反馈只引用本请求之后、同一行动所有者及能力来源的已发表事实，再经过 `buildAgentVisibleEventFeed` 的原有玩家投影。回包去掉序号、时间和受众元数据，不附隐藏的实际目标、真实阵营、其他人的私有状态或上帝事件。本人查验仍是本人知识，不转成公开身份认证。下一轮正常事件流继续提供这些事实，不因为工具收到结果就推进事件游标或漏掉事件。

LLM 在 SDK 收尾前保存宿主回执；Pi 保存实际工具返回；ACP 在 MCP 路由留底，适配器不发原生结果时也能录制。结果放在既有玩家 schema 2 的 `tool_result.result` 中，显示开关不参与录制。终端与 Web 共用状态解码和自然语言摘要；普通私有反馈遵守原详细输出开关，不因新增状态自动公开。

## 自爆的二次确认

LLM、ACP、Pi 共用 `ActionTurn` 的确认窗口，仍只开放原来的三个游戏工具。`submit_action` 新增可选顶层字段 `confirmation_id`，协议版本 1 保持兼容；普通行动的提交方式不变。

- `self_destruct` 与白狼王的 `self_destruct_with_target` 在机制工具规格中声明确认要求。第一次即使带 `arguments.confirm=true`，也只返回 `ok=true, status=confirmation_required, accepted=false, applied=false`，附原行动参数、双语警示与随机 `confirmation_id`。`ok` 只表示成功处理请求，不能作为停止模型或选定行动的条件。
- 模型阅读警示后，再次提交同一 `turn_id`、`action`、完整 `arguments`，并在顶层附回执编号，才返回 `status=confirmed, accepted=true, applied=false`。确认时重新进行 schema、角色资格、目标和请求约束预检；实际生效仍以引擎最终校验和结果事件为准。
- 编号只存在于当前选择窗口的内存中，绑定当前会话 owner、玩家、日期、阶段、窗口与规范化后的完整参数。同样的首次请求重传只返回原警示；仅连续调用两次自爆而不带编号不会确认。改变目标或理由须重新提案，旧编号失效；错误编号不会自动变成新提案。
- 提案不占用有效行动名额，也不计拒绝次数。可选窗口中模型直接结束即跳过，不因未确认而触发必选重试。关闭、取消、过期会封窗；编号不能带到下一回合。自动回退即使返回自爆候选也被过滤，不能替模型确认。
- 警示与两次工具回执进入同一玩家的私有录制。终端与 Web 共用确认分类，详细输出关闭时仍标明“需要二次确认（尚未选定）”和“已二次确认（尚未生效）”。它们不是公开游戏事件，不给其他玩家追加知识。终端普通工具摘要不追加行动参数或发言正文；已识别的执行回执可显示本人可见的技能结果摘要；完整参数保留在私有录制和 Web 详情中。
- 这一握手属于 Agent 提交协议。模拟策略、测试中的可信领域驱动仍可直接提供 `ToolCall`，由原领域网关与自爆机制校验；不把确认编号写进领域动作、库存或死亡结算。

示例，第一次提交：

```json
{
  "turn_id": "p7",
  "action": "self_destruct",
  "arguments": { "reason": "决定中断白天", "confirm": true }
}
```

收到警示后确实决定继续，第二次提交：

```json
{
  "turn_id": "p7",
  "action": "self_destruct",
  "arguments": { "reason": "决定中断白天", "confirm": true },
  "confirmation_id": "原样复制第一份回执的编号"
}
```

若决定不自爆，直接结束模型回合，不调用占位行动。旧的单次自爆脚本需显式接入这一握手；测试驱动消费真实回执追加确认，历史冻结 fixture 不修改。

## 超时后的行动和遗言

模型思考超时后先撤销工具窗口、等待原会话资源回收，再按既有政策决定回退。回退没有额外预算；原绝对期限已经耗尽时不调用策略，也不打印一个看似已生效的回退候选。Pi、LLM、ACP 共用的期限等待在同步与异步返回时都复核时间。

普通遗言期满由机制关闭，不发表迟到文本，后续对局继续；严格授词及其它真实撤权仍失败。终端和私有档案保留超时原因，严格复现以固定的交付期满事实重现关闭路径，详见[请求契约](action-requests.md#期限耗尽与普通遗言收口)。
