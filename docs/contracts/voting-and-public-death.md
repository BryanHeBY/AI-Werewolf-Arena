# 投票、公开死亡与遗言的有限政策

## 票轮与实际目标

警长／放逐候选、参与者、票权、weight与PK单位分别维护。公开参与资格不揭示秘密免疫。已接受票表不是任意时点的当前actor列表；guard前双快照、末guard／权重复验、停止／安装原先后保。

具名AWA警长政策可仅未上警者投首轮、最多一次PK，再平或全弃不发徽。放逐也按其具名一次PK政策执行。不要从某个example推导其它板子同规则；定序／诡术的重投与目标映射保原各自覆盖条件。

## 警徽与死亡动作

死亡持徽选择继任或撕徽由真实窗口／库存owner提交；转移目标原生命、token与原badge当前性仍需复验。若接completion，必须在全部语义写成功后、事实前完成，不能provider返回即true或只首写成功即true。

死亡动作由真实DR许可，枪／来源／policy与目标映射保原顺序。公开事件不负责重构许可，body字段相同不能借旧请求开新行动。

## 死亡披露与遗言

支持的具名公开deathRevealPolicy与lastWords policy从配置／规则卡选择；默认AWA隐藏信息／初始波政策与网易2017局部明牌／白天及首夜遗言政策分开。不是整个平台流程的镜像。

翻牌只披露实际死亡者的当前身份牌，不据此公开技能、库存或实际Camp。遗言按原逐人死亡时刻、来源phase与波次策略授权，不能把所有“在夜里结算”都当第一夜。

LastWords真实窗口保创建factory时day与收集时第二day的读取；动态lease若两者失配明确拒，不缓存成一次读冒机械等价。只有遗言事实push成功返回后才true；原permit.close仍finally并保原错误优先。畸形／null候选继续或退出按原规则，不能用空串是否显示倒推付款。

具体版本、source、有限板与未支持变体以[规则卡](../rules/README.md)及实际配置schema为准；这份维护契约不重写PK、徽章或遗言玩法。
