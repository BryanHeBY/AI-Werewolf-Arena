# 状态、许可与生命周期

## 不把不同事实混成一个布尔值

- 选择：provider返回的候选；可接受：当时preflight／gateway通过；领域提交：实际写权完成；付款：一次性资源支出；生效：效果被消费；已知：事实已向受众发布。
- PhaseRevision、实际Night、ExileUnit与DeathWave分别有身份；originPhase不等于正在执行的phase。PK是新票轮，不是任意增加day；跳日也不能被调试phase替代。
- 存活、原生命版本、Role引用、实际Camp、来源与库存各按该族的原政策比较。正常value-only同值替换与严格组件引用撤权是不同政策，不统一加强。

## 写权与失败前缀

World／组件仍是实际存储。机制的state slot持原对象／JSON字段的唯一写权；没有第二WeakMap镜像或按Role筛掉扩展字段的伪codec。纯DTO投影、运行资源、公共reader与严格档案格式分别有owner。

Camp是实际阵营的唯一现场来源，Role不再保camp镜像。初始化显式传可写initialCamp和晚currentCamp；Catalog元数据只供默认初值。Victory成员关系、历史知识、查验标签和显示阵营仍是各自语义。

核心身份安装失败通过同一Role对象的运行退休终态关闭未付执行，字段恢复或同对象跨World不重开；纯数据、目标查询、历史知识与已付效果不因此统一失效。不是全仓所有角色动作已经完成相同检查的声明。

不把部分付款包装成事务：先写后抛的状态仍保前缀与原Error；原finally也抛时保原JS错误优先。新关闭通知不得盖过已有的body／原cleanup错误；具体窗口完成其既定处理后才通知 true；完成不统一等同于库存付款，晚 facts／通知错误不能触发第二结算。

## 效果、死亡与终局

阶段handler提交有来源的intent／claim或已付效果；死亡解析器按原保护、反射、关系闭包、标死和延期顺序消费。proposal不是已死；history不是World当前状态；eligibleDead不是允许任何旧请求。

原生／赠枪消费前核执行资格，已消费pending继续原体／来源／版本的纯当前性。摄梦等已付效果可能允许原actor第一次死亡后的版本变化，仍需真实原体与该族规则，不等于无条件永久生效。

PM保nightSettled首写、DR callee／实参／await及finally；普通黎明准备、特殊伤害、关系、知识公告等完整算法分别在实际ruleset／feature。胜负候选在必要死亡链后到指定checkpoint，最后唯一封盘；不能在候选出现时提前跳过原必要链或封盘后继续新动作。
