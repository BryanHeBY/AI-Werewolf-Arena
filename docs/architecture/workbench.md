# 本地工作台

工作台把文件配置、真实对局进程、终端日志和已有复盘串成一个本地工作流。视频制作保持独立入口。

## 所有权

- `apps/workbench` 拥有本地 HTTP 服务、配置编辑用例、进程启动和浏览器界面。
- `packages/game-runtime` 的配置解析器继续裁定实际运行支持；浏览器编辑原始 JSON，不保存已经解析的认证。
- `apps/game` 拥有 CLI；runner 拥有每局资源、取消和失败汇总；公共 CLI 与工作台运行同一入口。
- 录制器拥有最终产物发布；工作台不根据终端文字推断胜负或写补终档。
- `packages/game-media` 拥有唯一复盘组件、帧渲染、主题与素材；`apps/replay` 和工作台按需加载，不复制投影或规则。
- 工作台外观通过共享媒体包的公开 appearance 入口消费原主题、字体及素材，统一控制器贯穿配置、终端与回放，不另维护一套调色板。

## 配置工作流

配置入口默认展示本地已保存的板子与游戏配置，查看、编辑和新建分别进入明确的页面状态。新建游戏时选择通过运行校验的板子，阅读角色及规则选项，选择已有 Agent，设置全局／角色／座位覆盖，保存后再启动。平台向导创建既有 backends 和 agents JSON；高级用户可编辑原生字段。表单与源码使用同一文档，未展示字段保持原值。中文与英文提供相同操作。

原始文件、结构／引用诊断、已解析运行 setup 分开。编辑 API 以文件内容摘要检测外部修改，服务内按文件串行保存，临时文件完整写入后替换；不宣称能锁住不遵守协议的外部编辑器。认证只在显式读取配置时供本机编辑，不进入列表、运行摘要或日志；保留环境占位符。

### WB-UX-01：已有配置与创建流程分开

**修复前问题**：新建、查看与修改共用同一编辑区域，页面会自动选中配置或生成草稿。用户难以判断当前对象是否已保存、正在修改哪个文件，以及操作会创建还是覆盖配置。

目标行为：

- 进入“板子”或“游戏配置”首先显示已有配置列表。已有配置指 `configs/boards/`、`configs/games/` 中实际保存的文件；仓库示例模板在创建流程中单独选择，并标明来源。本地同 ID 板子不遮蔽原始示例库，初始化或修改本地文件后仍可从原示例创建。
- 列表提供明确的“新建板子”“新建游戏”按钮。点击后进入独立创建流程；没有配置时显示空状态和创建入口。
- 选择已有项先进入查看页面，展示配置 ID、板子／角色与规则、Agent 选择等摘要。点击“编辑”后才进入可修改状态，表单与 JSON 源码在此状态下操作同一份草稿。
- 新建、查看、编辑都有明确标题、当前配置标识和返回入口。“复制为新配置”与“保存已有配置”区分动作和目标 ID。
- 创建流程中明确填写 ID、检查和保存；保存成功后进入该配置的详情。取消创建不生成文件，再次点击新建应得到独立的新草稿。
- 草稿的取消、保存和离开保护只作用于当前对象；异步目录刷新不能重置草稿，保存返回不能覆盖期间新增的输入。

验收：默认进入两个列表均不自动打开编辑器、不创建板子或游戏文件（缺失的运行空骨架按首次配置规则补齐）；新建连续两份配置、查看后编辑、取消修改和返回列表都能清楚识别当前对象，磁盘变化与界面动作一致。

### WB-UX-02：快速启动从已保存的游戏配置开始

**修复前问题**：首页主要把用户导向创建和配置编辑；游戏 JSON 尚未创建或保存时就进入混杂的配置界面，修改对象与启动对象不清晰。

目标行为：

- 工作台首页首先提供已保存游戏配置的选择与快速启动区域；正在运行和历史对局保留独立、清晰的展示区域。
- 游戏配置是可反复启动的 `games/<id>.json`；对局记录是每次执行生成的 session。页面用语和操作分别表达这两类对象。
- 每个可选游戏展示 ID／名称、板子与人数、默认及覆盖 Agent 等必要摘要，提供“查看配置”“编辑”“启动”动作。空列表明确引导“新建游戏”。
- 快速启动使用明确选中的已保存配置。创建中的草稿先完成保存；编辑已有配置时明确展示未保存状态及保存动作。
- 启动前检查实际文件、配置引用及必填项。被外部修改、删除或检查失败时显示原因并引导修正，不能悄悄换成默认游戏或另一份草稿。
- 启动成功后进入对应 session 的终端与运行状态页，能识别本局使用的游戏配置 ID、板子及玩家 Agent 选择。

验收：从首页选择已有配置可以直接启动；从新建入口完成“选择板子 → 设置 Agent → 保存游戏 JSON → 启动”闭环。查看、编辑其他对象不改变当前选择的启动对象；未保存与已保存状态始终可辨。

### WB-UX-03：游戏配置、板子与对局记录均提供删除

**修复前问题**：三类列表与详情缺少删除入口，用户只能自行处理文件，配置管理和对局管理没有完整闭环。

| 对象     | 删除入口及范围                                                            | 必须处理的关联                                                                                                            |
| -------- | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| 游戏配置 | 已有游戏列表／详情提供删除，针对本地选定的 `games/<id>.json`              | 保留共用板子、Agent 和已录制对局                                                                                          |
| 板子     | 已有本地板子列表／详情提供删除；示例模板保持独立来源                      | 删除前列出引用它的游戏配置；首版阻止删除仍被引用的板子，引导用户先调整引用                                                |
| 对局记录 | 对局列表／详情提供删除，范围含该 session 的录制、日志及对应工作台运行登记 | 活动进程先通过既有停止并保存流程结束；实例存活无法确认时不能仅凭过期心跳认定可删除。已有 `output/` 视频与其他局的内容保留 |

共同要求：

- 删除前明确展示对象和影响范围并二次确认，取消不产生文件变化。
- 服务端按明确根目录与对象 ID 验证目标，沿用路径、符号链接、来源校验及配置冲突处理，不能接受任意客户端路径或越界级联删除。
- 删除成功后更新列表、详情和当前选择；刷新页面仍保持已删除状态。示例模板不能混入已有配置列表而造成“删除后又出现”的错觉。
- 失败时显示原因并保留准确状态；引用冲突、活动对局、外部修改及重复删除都有明确反馈。

验收：逐类验证删除成功、取消、失败和刷新；验证被引用板子及活动 session 的限制；检查共用配置、其他 session、`output/` 和示例源文件均保持原内容。

### 持续交付验收

- 先落实列表、详情、创建、编辑及快速启动的信息结构，再接删除用例与按钮，避免把新增动作继续塞入原混合编辑页。
- 中文和英文提供相同入口、对象区分和状态反馈，继续使用视频前端共用主题与字体。
- 浏览器测试覆盖首次进入、已有配置快速启动、完整新建、连续新建第二份、查看／编辑／取消，以及三类删除的成功和阻止路径。
- 文件集成测试核对保存与删除的真实目标、关联检查、外部修改及本地数据保留。按功能提交，记录定向验证与远端 CI 的实际结果，不把尚未结束的矩阵描述为通过。

## WB-PATH-01：统一路径解析

已由 `packages/project-paths` 集中维护默认数据根与输入／声明文件语义。公共 CLI 位于 `apps/game`，复盘与视频工具分别在 `apps/replay`、`apps/video`；共享实现归 runtime／media 包。复盘输入先定位为绝对路径，Vite 在显式应用 root 运行。录制默认根不再依据 cwd 名称推算；配置检查作为 runtime 用例公开，不反向导入 CLI。

按路径来源确定基准，不把所有路径一律解释为仓库相对路径：

| 路径来源                       | 解析基准                 | 示例与要求                                                                                                  |
| ------------------------------ | ------------------------ | ----------------------------------------------------------------------------------------------------------- |
| CLI 显式路径参数、路径环境变量 | 公共入口启动时的调用目录 | `--input ./record/session/replay.json`、`--configs-dir ./configs`；绝对路径保持绝对语义                     |
| 缺省数据目录                   | 明确的项目根目录         | `configs/`、`record/`、`output/`、`.workbench/`；在应用目录或仓库外启动不能意外生成另一份数据根             |
| 配置／项目文件中的相对文件引用 | 声明该字段的文件所在目录 | 复盘输入、视觉项目、配乐、适配器文件路径等；配置 ID、模型名、URL 与通过 PATH 查找的命令名分别按自身语义处理 |
| 应用代码资源与工具配置         | 拥有资源的应用／包目录   | Vite root/config、构建入口、dist、静态素材、CLI 可执行入口；不能借用用户的数据目录定位代码                  |

实现要求：

- 在公共入口捕获调用目录，完成参数优先级合并后将文件系统路径一次性解析为绝对路径；内部包装脚本切换目录或使用 `--cwd` 时不得重新解释用户输入。
- 项目数据根与应用资源根分别显式传递，默认根的定位集中维护。调用方不再各自拼接源码层级，不以目录名称猜测根目录，也不依次尝试多个目录静默选中另一份文件。
- 项目根缺省为本项目仓库根；现有显式配置／记录／状态目录参数继续覆盖各自默认值。未来允许独立项目根时，在入口声明覆盖关系，不新增隐藏搜索规则。
- 子进程可在应用目录运行工具，但接收已经解析的绝对数据路径与明确的配置入口。复盘从哪里读取、Vite 在哪里运行分别负责。
- 配置 schema 与字段说明标明文件路径、配置引用、命令名和 URL 的区别。浏览器资源使用 URL 的 base／origin 规则，不套用服务端文件系统 cwd。
- 启动信息及路径错误给出实际采用的数据目录或目标路径，便于定位；不打印认证内容。文档与根脚本示例同步更新，迁移不移动、重建或清理已有本地数据。

验收：从仓库根、应用目录和仓库外启动公共入口，缺省数据仍指向同一项目；显式相对参数始终相对该入口的调用目录。测试覆盖内部切换 cwd、带空格目录、绝对路径、配置文件内相对引用、配置位于仓库外以及缺失文件的明确错误。核对 Vite 配置／资源位置正确，并确认 `configs/`、`record/`、`output/` 的既有内容保留。

## 首次配置与平台向导

首次读取配置目录或运行文档时，以独占创建补齐缺失的 `runtime/backends.json` 与 `runtime/agents.json` 空目录骨架（`schemaVersion: 2`、`items: {}`），已有文件字节保持不变。校验请求保持只读，连接测试和认证导入也不会借初始化补配置。首页和 Agent 页引导 GUI 创建 Agent，不批量导入占位连接、认证或游戏；规则模板仅在用户选择“新建板子”时进入独立草稿。编辑目录允许连接先于 Agent 保存，首个 Agent 默认成为全局默认值；实际开局仍要求非空且引用完整的运行配置。游戏未配置 Agent 时提示配置入口并阻止保存与启动。

Agent 向导分别组织 API Key 与订阅 OAuth。Pi 内置平台自带地址／API／模型目录，灰色地址不自动写入 `models.providers`；只有用户实际覆盖地址时才保存 override。新建连接与 Agent 分属不同文件，后一步失败保留准确状态，并能复用或重试。新建 Codex 连接在导入失败后继续完成认证步骤；已有认证连接复用时不改写它的令牌。角色／座位 Agent 选择复用保存的 ID。

连接测试属于 runtime 公开配置用例，由工作台显式 POST 触发，只读取已保存 Agent；同一服务同时只执行一次探测。用例复用 LLM／Pi／ACP 适配器，拥有本次取消期限与资源关闭，不打开游戏行动窗口、不挂载游戏工具、不生成录制；输出仅含脱敏阶段结果。GUI 未保存草稿时禁用测试，首次配置进度与真实网络测试分开表达。

## 配置显示与有效值

配置界面区分显式值、真实运行缺省与新建推荐值。`game-contract/game-config-defaults` 提供共同的缺省常量；新建推荐预算显式写入草稿，旧文件省略字段的运行含义不因界面升级而变化。配置摘要同时展示有效预算、语言、日志开关及玩家自定义项。

`POST /api/board-rules` 接收板子草稿，使用唯一板子解析器核验候选编辑，返回当前玩法的允许范围、固定项及实际生效投影。浏览器只负责展示及字段联动，不复制有限角色组合裁决。自爆时机、警长禁用与 PK 平票的 JSON 联动由纯数据编辑函数集中处理；只读查询不补写草稿，异步结果必须绑定原文版本。

`POST /api/preview-game` 仅在用户显式请求时组合已保存 Agent 与游戏草稿的附加指令。座位与角色是假设输入，不执行发牌。输出只含 Agent 名称和来源、所选语言、最终指令及受限诊断；包含认证的运行 profile 不直接序列化。此接口不写文件、不创建会话、不调用模型。

Pi 保存检查复用内存模型目录校验提供商及模型引用，不读取宿主认证、不执行模型请求。新建与编辑共用思考等级控件，逐模型设置的优先级在界面中可见；连接级并发、初始化时限与模型请求档位明确标注共享作用范围。配置错误保留结构化代码／路径，界面负责自然语言说明和折叠技术详情。

## 运行与恢复

身份端口分别提供 Linux `/proc`、Windows 固定 PowerShell 和 macOS `ps`／`sysctl` 查询，核对进程启动与系统启动身份。Linux 和 Windows 有定向验证，macOS 尚无同级 CI 证据；查不到实例身份时保持未知，不凭复用 PID、过期心跳或服务本地缓存授予停止／删除权限。跨平台工作台不使 Linux 专属的 ACP `bwrap` 沙箱成为 Windows 隔离方案。

运行状态与录制发布见[运行生命周期](../contracts/run-lifecycle.md)。工作台扫描指定 record 根，能发现外部 CLI 的新对局；服务重启不取消已启动的对局。运行快照不是游戏状态，不能恢复 World 或行动权限。

HTTP 服务默认监听本机地址，可用 `--host` 显式改变。请求 Host 限定为绑定主机、loopback 别名及通配绑定时的本机网卡地址，变更请求继续验证同源；绑定通配地址不等于接受任意域名。路径限定在显式配置及记录根内并拒绝符号链接越界。浏览器不能指定任意 shell 命令，启动只接受已经校验的具名游戏。

本地 output、configs、record 不在目录迁移或安装中删除。工作台构建产物单独放在应用 dist，测试使用独立临时根。
