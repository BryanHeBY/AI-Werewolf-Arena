# V3 初始 Prompt 配置渲染规范

开发驱动（已归档）：`docs/drivers/archive/completed_todos/backend/prompt_config_rendering_driver.md`

## 背景
当前初始 prompt 已包含角色、队友、板子角色构成等信息，但仍缺少“规则配置层”的显式渲染，导致玩家智能体对当局规则边界认知不足（例如胜利条件、是否启用上警、是否允许自爆/自救等）。

## 目标
将“对局配置项”统一渲染到初始 prompt，使玩家在首轮即可明确本局规则，减少规则幻觉与错误策略。

---

## 本次需求（用户确认）
1. 胜利条件写入初始 prompt，并渲染具体规则说明。
2. 其他可配置项也写入初始 prompt（至少覆盖关键玩法开关）。
3. 明确“是否有上警机制”，以及“上警机制简介”。

---

## 渲染范围（第一批）
以下项进入初始 prompt 的“本局规则配置”段落：

1. 胜利条件（`winConditions[]`）
- 渲染为有序列表，按实际评估顺序展示。
- 每项附简短中文解释。
- 首批支持：
  - `slaughter_side`（屠边）
  - `slaughter_city`（屠城）
  - `wolf_reach_half`（狼人达半）

2. 警长机制（`enableSheriff`）
- 明确显示：启用/未启用。
- 启用时补充简介：
  - 存在上警流程（上警、竞选发言、退水、警下投票）
  - 警长可决定白天发言方向
  - 警长票权（如 1.5 票）需显示

3. 自爆机制（`selfDestruct.enabledWindows`）
- 明确是否启用。
- 启用时列出允许窗口（如 `on_pre_vote`）。

4. 女巫自救配置（建议配置项）
- 若已配置：显示是否允许女巫自救（特别是首夜自救）。
- 若未配置：显示“当前采用默认规则：不可自救（待配置化）”。

5. 平票处理机制（建议配置项）
- 若已配置：显示对应策略（放逐/狼刀/警长投票）。
- 若未配置：显示当前默认行为（如“平票取最小编号/最小座位”）。

---

## Prompt 结构建议
在系统 prompt 的“当前板子信息”后增加一个固定段：

`本局规则配置：`
- `胜利条件：...`
- `警长机制：...`
- `自爆机制：...`
- `女巫自救：...`
- `平票处理：...`

要求：
- 使用自然语言，不使用 JSON。
- 压缩信息密度，尽量 4~8 行内完成。
- 明确“是否启用”与“默认值/回退值”。

---

## 实现建议
1. 新增“配置渲染注册器”
- 建议位置：`backend/src/game/mechanisms/prompt/config_render_registry.ts`
- 职责：将 `BoardConfig + 机制默认值` 转换为 prompt 文本块。
- 要求：与具体角色逻辑解耦，便于新增配置项时扩展。

2. 在 `buildSystemPrompt` 输入中新增 `configPrompt`
- 由 `LlmActionProvider` 组装并注入模板。
- 避免在模板函数内部做业务判断。

3. 保持兼容
- `winCondition`（旧单值）存在时自动转成单项 `winConditions` 渲染。
- 未配置项显示“默认规则”而非留空。

## 验收标准
1. 任意一局玩家首轮 `system prompt` 可读到本局胜利条件与机制开关。
2. `enableSheriff=false` 时，prompt 不应暗示存在上警流程。
3. `winConditions=["slaughter_side","wolf_reach_half"]` 时，prompt 必须按该顺序展示。
4. 回放文件中首轮系统提示可见上述规则配置文本。
5. 相关单元测试与构建通过。
