# 🐺 智能体狼人杀引擎 (Agentic Game Engine) V3 技术白皮书

## 1. 当前代码详细文档

本白皮书面向 V3 重构目标，定义后端技术路线与机制规范。引擎专为现代大语言模型（如 DeepSeek、Qwen、Claude）设计，采用 **“OOP 中心化状态机 + ECS 玩家实体动态渲染”** 混合架构。

核心目标：

1. 摒弃传统文本正则解析。
2. 全面拥抱 `Function Calling`。
3. 提供绝对严谨、可无限拓展的多智能体博弈（LLM Arena）测试框架。

---

### 壹、核心架构与认知引擎 (Core Architecture)

#### 1. 知行解耦与记忆压缩 (LLM-Native Logic)

1. **私密思考区 (`content`)**：
   - 大模型的思维链（CoT）严格截留在内部日志。
   - 与公共信息物理隔离，防止“自爆”。

2. **意图提取 (`tool_calls`)**：
   - 发言（`speak`）、技能、自爆等行为统一抽象为工具调用。

3. **私密笔记本 (`Private Notebook`)**：
   - 允许模型主动调用工具更新战术笔记（身份推测、行动计划等）。
   - 笔记优先级极高，不受上下文清理影响。

4. **滑动窗口记忆压缩**：
   - 基于 Token 阈值触发。
   - 引擎强制模型压缩远古对话为《记忆摘要》。
   - 目标：解决中后期失忆与幻觉问题。

#### 2. 插件化注册机制 (Registry Pattern)

1. 引擎不硬编码任何板子逻辑。
2. 角色组件、阶段顺序、胜负条件、状态印记（Buffs）全部通过配置字典注册入核心状态机。
3. 体系支持热插拔。

### 贰、游戏生命周期与时序控制 (Phase & Timing)

引擎采用 **严格回合制与离散时间线**，保证 AI 并发调用稳定性与数据一致性。

#### 1. 黑夜阶段与狼刀交流机制 (Night Phase)

夜间技能提交采用 **分组并行、内部串行** 的结算机制：

1. **神职并发**：
   - 具备夜间技能的神职并行思考并提交 `tool_calls`。

2. **【新增】狼队战术交流环 (Wolf Discussion Loop)**：
   - 为模拟面杀中的手势交流与战术布置，狼队采用两段式时序：
   1. **随机顺序发言**：
      - 系统在夜间随机打乱存活狼人顺序。
      - 依次调用私密 `speak_to_wolves` 工具发言（如“我去悍跳，大家集中刀3号”）。
   2. **同序投票落刀**：
      - 发言后按同一顺序依次调用 `kill_vote` 提交袭击目标。
   3. **票多者死**：
      - 汇总狼队内部选票，最高票者成为当夜狼刀最终目标。

3. **统一结算**：
   - 阶段末按固定优先级统一下发 ECS 印记并结算生死：
   - 【守卫 > 狼人 > 女巫 > 预言家 > 附加功能狼/神】

#### 2. 白天阶段与自爆中断钩子 (Day Phase & Interrupts)

白天采用绝对 **顺序串行发言制**，并引入可配置生命周期钩子（Hooks）：

1. **警长决定顺序**【新增】：
   - 若存在警长，在常规发言前发起极简请求。
   - 警长调用工具决定本轮发言顺序：
     - 顺时针（警左）
     - 逆时针（警右）

2. **自爆响应窗口 (Explosion Window)**：
   - 房主可开启以下节点中断询问，允许特权角色截断流程：
   - `天亮钩子`：法官宣布死讯后、发言前（可吞警徽竞选）。
   - `警上钩子`：警上发言结束、警长投票前（可吞警徽投票）。
   - `放逐前钩子`：常规发言结束、放逐投票前（极限拍刀点）。
   - `每轮发言间隙钩子`（高压配置）：
     - 每位玩家发言结束后立即触发。
     - 还原“被查杀当场自爆截断后位发言”。
     - 但 Token 消耗极高。

### 叁、核心特殊系统与结算判定 (Core Systems)

#### 1. 警长与上警系统

1. **竞选与退水**：
   - 首日白天触发。
   - 支持警上玩家在投票前声明退水。

2. **警徽特权**：
   - 放逐投票权重 1.5 票。
   - 拥有白天发言顺序（顺/逆时针）决定权。

3. **移交与销毁**：
   - 警长出局时必须移交警徽给存活玩家，或撕毁警徽。

#### 2. 遗言系统

仅以下两种情况拥有遗言阶段：

1. 第一晚死亡的玩家（含多死）。
2. 白天被放逐投票出局的玩家。

无遗言情形：

1. 被狼人自爆带走。
2. 被猎人开枪带走。

#### 3. ECS 技能冲突判定 (Skill Resolution)

1. **同守同救**：
   - `[守护印记]` 与 `[解药印记]` 同时存在于同一实体时互相抵消。
   - 若目标此时存在 `[狼刀印记]`，则死亡。

2. **伤害免疫法则**：
   - 守卫护盾仅防狼刀。
   - **无法防御** 女巫毒药、猎魔人狩猎反伤等系统级神圣伤害。

#### 4. 胜负判定 (Victory Conditions)

默认采用 **屠边局**：

1. 狼人杀死所有神职，或杀死所有平民即获胜。
2. 好人需驱逐所有狼人。

### 伍、高级扩展模块 (Advanced Expansions)

依托 ECS 组件化架构，V3 支持高自由环境异变：

1. **黑死病玩法 (The Black Death)**：
   - 无需狼人底牌即可游玩。
   - 注入 `EnvironmentComponent` 模拟随机夜间死亡。
   - 纯考验模型在“无内鬼”环境下的自发猜忌与逻辑构建。

2. **动态阵营重写 (Dynamic Alignment Shift)**：
   - 针对觉醒石像鬼、机械狼等角色。
   - 运行时可剥离原有 `CampComponent`，赋予狼人视野组件。
   - 在不中断对话上下文的前提下平滑过渡游戏目标。
